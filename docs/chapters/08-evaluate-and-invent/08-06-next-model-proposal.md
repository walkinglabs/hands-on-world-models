# 8.6　动手：实现自己的世界模型

Z0做完了，你已经找到了一两个模型稳定失败的场景。别只写提案——这一节我们来真的：改代码、实现你的改进、跑对照实验，拿出属于你自己的下一台世界模型。

PA2不是写论文，也不是画大饼。它要你完成的是一次**完整、可反驳、可验证**的小型研究循环：找到问题→提出假设→最小改动→写代码实现→公平对照→诚实结论。不要求你做出SOTA，只要求你把这个循环扎扎实实走一遍。

这个过程练熟了，你以后读论文、改模型、做研究，用的都是同一套思路。

## 第一步：挑一个稳定失败，把它写具体

从Z0的结果里挑一个**最稳定、最明确**的失败。别挑"有时候效果不好"这种模糊的问题，要写得足够具体，让任何人拿到你的代码都能复现。

❌ 错误写法："模型长视频预测效果不好"
✅ 正确写法："当物体被连续遮挡超过3步、同时场景里有3个以上移动物体时，位置预测MSE从0.02上升到0.3以上，固定seed=42/43/44三次实验都出现这个问题，失败样例见fig/long_occlusion_failure.png"

你要写清楚：
- 复现这个失败需要什么命令、什么数据、什么checkpoint、什么seed
- 量化的失败条件（遮挡几步、速度多少、物体几个、误差多大）
- 至少3次重复或者在一组样本上稳定出现的证据
- 几个可视化的失败样例

如果失败不能稳定复现，先回去补评测，别着急改模型。

## 第二步：提出至少两种竞争解释

面对这个失败，至少写出两种**互相竞争、会产生不同实验预测**的解释。

还是用"遮挡三步以上丢位置"举例：

```text
解释A（记忆不足）：模型的历史窗口只有5步，遮挡前的位置信息三步以后就被挤出记忆了。
→ 预测：加长历史窗口到20步，应该主要改善长遮挡情况，短遮挡提升不大。

解释B（物体混淆）：状态里没有显式物体表示，多个物体被压成同一个特征，一遮挡就分不清谁是谁。
→ 预测：即使加长历史，只要同时有3个以上物体还是会失败；加入物体跟踪应该能改善多物体场景。
```

两个解释都要写，而且要写清楚：如果解释A对，我们会看到什么实验结果？如果解释B对，我们又会看到什么结果？

如果你实在想不出第二种解释，找个同学讨论一下——两个人很容易想到不同方向。一个人闷头想，很容易钻牛角尖。

## 第三步：选一个最小改动，真的写代码实现

选其中一个解释，设计一个**最小的改动**。记住PA2的铁则：一次只改一个东西，其他一切保持不变。

什么叫最小改动？
- ❌ 不要同时换Encoder、加数据、改loss、换Planner——你不知道是谁起作用
- ✅ 要只改最关键的一个地方：要么把GRU换成带更长记忆的版本，要么加入物体slot，要么补一类数据，要么改预测目标

写清楚你的改动：
- 输入变了吗？（加了新传感器？加了更长历史？）
- 状态表示变了吗？（加了object slot？从像素换成BEV？）
- 预测目标变了吗？（从重建像素改成预测特征？加了碰撞预测？）
- 损失函数变了吗？（加了不确定性惩罚？加了OOD正则？）
- 训练数据变了吗？（补了哪类难例？）
- 推理接口变了吗？（Planner加了安全约束？）

**现在打开编辑器，真的改代码。** 别只停留在想法阶段，把它实现出来，能跑前向、能算梯度、能训练。

除了这一个改动，其他所有东西——数据划分、模型其他部分、训练步数、optimizer、学习率、评测代码——**必须和原来完全一样**。

## 第四步：提前写好"什么结果证明我错了"

这是最关键的一步，也是大多数人会跳过的一步。在你开始跑实验之前，先写下来：

- 如果新模型比旧模型在**所有场景**都提升，包括那些本来就很好的场景——这说明什么？（可能是参数变多了，不是你的改动切中了问题）
- 如果新模型在**目标场景**提升了，但在其他场景下降了——这是成功还是失败？
- 如果新模型和旧模型**没有显著差异**——说明什么？
- 如果新模型**反而更差**——你接受这个结果吗？

还是拿遮挡例子：
> 如果把历史窗口加长到20步，结果是：
> - 长遮挡误差从0.3降到0.1，短遮挡误差不变 → 支持解释A
> - 长遮挡只降到0.25，多物体场景还是0.28 → 反对解释A，更支持解释B
> - 所有场景误差都降了0.02 → 可能是训练更久了，不是记忆的问题
> - 长遮挡误差反而变成0.4 → 加长记忆没用，我的解释错了

把这些判断标准提前写死，不能等跑完了再挑好看的说。科学的标志是它可以被证伪——如果你的假设怎么都不会错，那它不是科学，是信仰。

## 第五步：先排除更简单的替代方案

在你大动干戈改模型之前，先问自己：有没有更简单的办法就能解决这个问题？

比如：
- 是不是只要多加点这类失败场景的数据，简单finetune一下就行？
- 是不是只要调个学习率、多训几轮就能解决？
- 是不是只要把Planner的horizon缩短、或者加个动作限幅就能规避？
- 是不是数据预处理有bug，把时间对齐搞错了？

**先试这些简单的办法。** 如果简单办法就解决了，那你原来的复杂改动就是多余的——别为了用新方法而用新方法。

报告里要写清楚你试过哪些简单替代，它们为什么不够。

## 第六步：跑公平对照，别作弊

现在开始跑实验。记住几个公平对照的原则：

1. **同样的seed集合**：新旧模型用完全相同的3-5个随机种子，报平均结果和标准差。一次seed的提升不算数。

2. **同样的计算预算**：如果旧模型训了100k步，新模型也只能训100k步，不能因为是"你的方法"就给它训更久。如果参数量不一样，要报告参数量和训练时间。

3. **同样的评测代码**：用同一个评测脚本评新旧模型，别给新模型写"专属评测指标"。

4. **失败样例也要看**：别只看平均指标。看几个新模型的失败样例，它是在原来失败的地方成功了，还是把失败转移到了新的地方？

5. **负结果也要诚实报**：如果新模型没提升甚至更差，老老实实写下来。负结果不是失败——它帮你排除了一个错误方向。

## 第七步：写短报告，回答六个问题

实验跑完了，写一份3-5页的短报告。不需要华丽的辞藻，把这六个问题回答清楚就行：

1. **它解决了哪个稳定失败？** 复述你第一步找到的失败，用数据说明原来有多差。

2. **新设计是什么？** 写清楚输入、状态、预测目标、损失、接口和原来相比，最小的变化是什么。给一张新旧模型的接口对比图。

3. **为什么更简单的方法不够？** 你试过哪些简单办法（加数据、调参、规则补丁），它们为什么不行？

4. **结果支持了什么？** 你的实验在哪些场景下看到了提升？这个提升和你最初的预测一致吗？

5. **结果没有支持什么？** 哪些地方没提升？哪些场景反而变差了？你的解释有哪些地方被证据否定了？

6. **下一步最值得做什么？** 如果继续做，下一个最小改动是什么？最值得收集什么新数据？

最后附上：
- 你改了的代码（diff最好）
- 完整的Run Manifest（git、环境、显存、时间、checkpoint）
- 主要对比曲线（horizon曲线、反事实结果、主指标对比）
- 3-5个失败样例对比（旧模型失败→新模型成功/还是失败）
- 3-5篇直接相关的论文（别堆参考文献，列真正看过、和你的改动直接相关的）

## 负结果也能拿满分

最后说清楚：PA2不是比谁的模型分数高。**只要你问题找得准、代码真改了、对照做得公平、结论写得诚实，哪怕新方法完全没用，你也能拿满分。**

反过来，如果你只报提升不报下降、只挑成功样例、对照不公平、说不清楚为什么有效——哪怕分数涨了，也不算合格。

因为这门课要教你的不是"怎么把模型调得准确率高一点"，而是**怎么做研究**：
- 从失败里提出问题
- 提出可检验的假设
- 真的写代码实现
- 做干净的对照实验
- 诚实地报告结果，不管是正还是负

这套方法，比任何一个具体的模型架构都重要。

## 学完这一章你带走了什么

恭喜你，到这里整门课的核心内容就走完了。你带走的不只是五个路线的模型代码，更是一套可以迁移到任何新问题上的思维方式：

```text
先看系统在哪个具体条件下失败
→ 判断它缺少信息、状态、预测、评价还是行动接口
→ 提出竞争假设，设计能推翻自己的实验
→ 写代码做最小组件改动
→ 跑公平对照
→ 诚实地报告支持什么、不支持什么
→ 从下一次失败继续往前走
```

今天我们把这套系统叫作世界模型。将来可能会有新的名字、新的架构、新的热点，但这套从失败中学习、用证据说话、自己动手改的方法不会变。

> 👉 去写代码、跑实验吧。不用追求完美，把这个研究循环完整走一遍，你就已经超过90%只会调参的人了。
