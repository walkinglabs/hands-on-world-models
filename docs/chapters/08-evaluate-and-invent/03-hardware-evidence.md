# 8.3　运行证据与复现

你的配置文件里写着"预计显存21GB"，超参看起来也没问题，smoke测试在小batch上跑通了——然后你就拍胸脯说"这个模型24GB能跑"。

别着急。预算和证据是两回事。**配置上写"21GB"只是计划，只有真正完整跑完一次训练，留下显存记录、时间、曲线和checkpoint，那才叫"24GB已验证"。**

这一节我们不讲算法，讲怎么做一个靠谱的实验记录者——让别人（包括三个月后的你自己）能拿着你的记录重跑出同样的结果。

## 三种配方：别拿smoke当成品

每个训练实验都要分清三种配置，这三种状态绝对不能混用：

1. **smoke测试**：几分钟内能跑完的超小配置，用来验证数据管线对不对、shape对不对、前向反向能走通、保存路径没错。smoke跑通了，只说明你的代码没有明显bug，不代表你的目标配置能跑。

2. **24GB目标配置**：这是你计划在单张24GB显卡上完整跑完的正式配置。batch size、序列长度、模型大小都按实际验收标准来。

3. **research配置**：用到更大显存、更多卡、更长训练时间的研究版配置，可选做。

最常见的耍流氓行为：smoke跑通了就说"模型能跑"，或者用research配置的结果吹水，却不说那是8张A100训了一周才出来的。

在课程里，这三种状态必须分别标注：
- ❌ 不能跑
- 🧪 smoke通过
- ✅ 24GB已实测
- 🚀 research配置

没有完整证据时，一律写"目标配方"或"尚未验证"，别用"能跑"这种模糊词糊弄人。

## Run Manifest：一次完整运行要交什么

想让别人能复现你的结果，一次完整运行至少要记录下面这些字段。少了任何一项，别人复现的时候就得猜，猜不对就跑不出来：

```text
代码版本：git commit hash
硬件环境：GPU型号、CUDA版本、driver版本
依赖环境：Python版本、关键包版本（PyTorch、torchvision等）
数据版本：数据artifact名称、版本号、checksum校验和
随机种子：完整的seed列表（至少3个seed取平均）
超参数：所有训练超参（别漏了learning rate、batch size、optimizer这些）
显存记录：peak allocated、peak reserved（两个都要）
时间记录：总训练wall time、每步耗时
结果记录：主指标、训练曲线、验证曲线、失败样例
产物记录：checkpoint hash（最好给下载链接）
```

### 显存的两个口径，别只报好看的那个

显存有两个常用测量值，很多人只报小的那个藏猫腻：
- `peak allocated`：PyTorch实际申请到的张量内存，这个数通常比较小
- `peak reserved`：PyTorch向CUDA设备预留的显存总量，这个数更接近你的进程真正吃掉的显存，也是OOM的真正原因

课程验收标准是单张24GB显卡，`peak reserved`不超过22GB——留2GB给系统和波动，别卡着24GB边缘，容易因为版本不同OOM。

只报`allocated`不报`reserved`，属于学术不端行为。

## 失败运行也要留，别只晒成功

OOM了、NaN了、训练发散了、数据读一半断了——这些失败的运行记录，**一个都不能删**。

为什么？失败记录能帮你（和后来人）区分三种完全不同的问题：
1. **配方太大**：batch size开太大、序列太长，一上来就OOM——这是配置问题
2. **数值不稳**：训练到一半loss突然变成NaN，或者后期突然发散——这是训练稳定性问题
3. **代码写错了**：smoke都跑不通，或者结果明显不对——这是bug

如果你把失败日志全删了，只留那一次偶然成功的运行，后来的人根本不知道踩过什么坑。更糟的是，你自己可能都忘了那次成功是不是运气——比如seed选得好、数据shuffle刚好凑了个好结果。

科学实验不是买彩票，偶然中一次不算数。稳定可复现的结果，才是真结果。

## 数据状态也要分清楚

别一句"数据已准备"就完事了，数据也有不同阶段：

| 状态 | 含义 |
|------|------|
| schema only | 只定义了数据格式和字段，还没有真正的数据 |
| source identified | 找到了数据来源，还没写loader |
| loader available | 能把数据读进来，还没验证正确性 |
| artifact available | 数据已经打包、校验、可以直接用 |

哪怕是你自己生成的合成数据，也要记录生成器版本、seed和checksum——不然改了生成代码，旧结果就再也复现不出来了。

## 结果要写"没证明什么"，别只吹"证明了什么"

写实验报告时，别只写"我的模型比基线高X个点"。一定要诚实地写清楚：
- 这个结果是在哪个数据集上跑的？换个数据集还成立吗？
- 这个提升是在哪个horizon下的？短预测涨了长预测跌了吗？
- 超参调了多久？是不是针对测试集调的？
- 失败样例是什么样的？模型在哪些情况下不行？
- 算力开销差多少？是不是用更多参数换的？

能诚实地说出"我的结果没有证明什么"，比瞎吹"我提出了一个全新SOTA"要靠谱得多。

## 课程项目的交付标准

对于这门课的PA1和PA2，运行证据是硬要求：
1. 必须提供可以一键重跑的Notebook，不能是"我电脑上能跑"的半成品
2. 必须提供数据卡，写清楚数据来源、切分方法、预处理
3. 必须画horizon曲线，不能只报一个数字
4. 必须有反事实测试和OOD测试结果
5. 必须贴失败样例，不能只挑成功的展示
6. 必须记录显存、时间、硬件环境
7. 必须写清楚"这个结果没有证明什么"

缺一样，就不算完成。

## 小结

- [ ] 分清smoke、24GB目标、research三种配置，别拿smoke当成品
- [ ] Run Manifest要写全git、环境、数据、seed、显存、时间、checkpoint
- [ ] 显存两个口径都要报，别只报好看的allocated藏reserved
- [ ] 失败运行日志别删，它们能帮你区分配方问题、数值问题和bug
- [ ] 数据状态也要分阶段标清楚，别一句"数据已准备"糊弄
- [ ] 写结果时别只吹"证明了什么"，诚实地写"没证明什么"更重要
