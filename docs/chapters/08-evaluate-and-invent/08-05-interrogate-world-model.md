# 8.5　动手：审问世界模型

前面四节讲了一堆道理，这一节我们真刀真枪地干——载入你训练好的PA1模型，像审犯人一样把它从头到脚问一遍。

Z0实验不训练新模型，它只做一件事：给你的模型做一次全面体检。我们用一个简单的toy环境先把评测流程跑通，然后你把同一套检查原封不动地搬到你自己的PA1模型上。

Notebook路径：
```text
notebooks/08_evaluation/Z0-test-a-world-model.ipynb
```

这个实验用CPU就能跑，不需要GPU。先把toy例子跑明白，再去评你的大模型。

## 第一步：先立基线，再说话

打开Notebook，第一件事不是跑你的模型，而是先把几个傻基线跑出来：
1. **复制上一状态/上一帧**：不管输入什么，直接输出 $s_{t+1}=s_t$
2. **匀速线性外推**：假设速度不变，$\hat s_{t+1}=s_t + v\Delta t$
3. **无模型Policy**：如果是控制任务，先训一个不使用世界模型的PPO/SAC

把这三个基线的结果记下来。如果你的模型连复制上一帧都打不过，别往下做了，回去检查代码bug。

## 第二步：画Horizon曲线，看它从第几步开始崩

从测试集里挑100个不同的起点，分别做：
- 一步预测：从真实状态出发，只预测下一步
- 多步rollout：从起点开始，用模型自己的输出滚1、5、10、30、100步

计算每个horizon的误差，画成曲线。你要回答：
- [ ] 模型从第几步开始误差明显上升？
- [ ] 和复制基线比，在哪个horizon范围内它是真的更好？
- [ ] 超过哪个horizon之后，还不如直接复制上一帧？

挑3个典型的rollout结果可视化出来：一个成功的、一个开始漂移的、一个彻底崩了的。别只挑成功的展示。

## 第三步：反事实测试——它真的听动作指挥吗？

挑20个固定的初始状态，锁死随机种子，然后只换动作：
- 给全0动作（不操作）
- 给正向最大动作
- 给反向最大动作
- （可选）给几个训练分布边缘的动作

把预测的轨迹画在同一张图上。你要检查：
- [ ] 换动作之后，未来轨迹真的分开了吗？
- [ ] 轨迹方向和动作方向一致吗？
- [ ] 还是说不管给什么动作，它都在按自己的惯性跑？

如果换动作轨迹完全没变化，说明你的动作条件根本没学到——视频看起来再清楚也是白搭。

对有随机性的环境，同一个动作跑5次，比较不同动作的结果分布，别要求像素逐点相同。

## 第四步：OOD压力测试——故意给它没见过的东西

提前定义好你的OOD维度，每个维度测20个样本：
| 路线 | 建议OOD维度 |
|------|-------------|
| 通用 | 动作幅度超过训练范围、初始状态偏移 |
| 视觉 | 颜色打乱、亮度±50%、加高斯噪声 |
| 物理 | 摩擦系数±0.5、物体速度翻倍 |
| 机器人 | 物体位置偏移10cm、没见过的物体组合 |
| 空间 | 视角偏移15度、点云降采样 |

你要记录：
- [ ] OOD样本上的误差比分布内高多少？
- [ ] 如果模型输出不确定性，不确定性会上升吗？
- [ ] 它是"知道自己不知道"，还是在瞎编一个看起来合理的结果？

挑3个最离谱的OOD失败样例可视化出来。

## 第五步：不确定性校准（如果你的模型有的话）

如果模型输出方差、ensemble有多个预测、或者Diffusion能采样多个结果，做一次校准检查：
1. 把置信度分成0-10%、10-20%...90-100%这10个区间
2. 每个区间里算平均置信度和真实错误率
3. 画 reliability diagram

你要回答：
- [ ] 高置信度样本真的更准确吗？
- [ ] 低置信度样本错误率真的更高吗？
- [ ] 校准误差有多大？

没有不确定性输出的模型可以跳过这一步，但要在报告里写清楚："我的模型不提供不确定性估计，无法判断什么时候它不可靠"。

## 第六步：让Planner去找漏洞

如果你的模型是给Planner用的，做这个测试：
1. 给一个固定起点，让CEM/MPC/你的规划器去选最优动作
2. 跑10次，看Planner选出来的动作幅值有多大
3. 记录Planner"找出来"的高回报动作，是不是落在训练分布外面？
4. 在模拟器里执行这些动作，它们真的高回报吗？还是模型在瞎编？

你大概率会看到Planner钻出来一些训练里从没见过的奇葩动作，在模型里预测回报高得离谱，真实执行直接崩盘——这就是模型漏洞，把这些样例记下来。

## 第七步：写Run Manifest，留下运行证据

最后，把这次评测的运行证据写全：
- [ ] 你用的代码commit hash
- [ ] GPU/CPU型号、PyTorch版本
- [ ] PA1模型的checkpoint hash
- [ ] 评测用了多少样本、哪些随机种子
- [ ] 评测跑完用了多长时间
- [ ] 峰值内存/显存是多少
- [ ] 所有曲线、失败样例图都存好

## 第八步：写清楚"它什么行，什么不行"

最后写一页评测总结，别写空话，要具体：
✅ 它做到了什么：比如"horizon 5以内预测准确，反事实测试动作能改变轨迹方向"
❌ 它没做到什么：比如"horizon超过10步漂移严重，OOD颜色变化误差翻倍，Planner会选a>2的无效动作"
⚠️ 它的边界在哪：比如"只在训练分布内、摩擦系数0.3-0.7、速度<5时可靠"

别吹"我的模型效果很好"，要写清楚它在什么条件下好、什么条件下不好。
