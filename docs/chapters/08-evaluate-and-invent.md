# 第 8 章　怎样证明模型有用，并设计下一台模型

现在我们已经可以训练五种很不一样的小模型：latent dynamics、互动视频、JEPA、机器人动作系统和空间世界。

它们的训练 loss 不能互相比较。视频像素低不代表会规划，动作 MSE 低不代表机器人成功，feature loss 低甚至可能来自表示坍缩。

本章不再增加模型名字。我们学习一套更难也更重要的能力：怎样找出模型真正可靠的范围，怎样从一个稳定失败中提出下一种设计。

## 8.1 第一个原则：先给简单基线

很多动态数据具有惯性。复制上一帧就可能得到不错的像素误差；匀速外推也可能在短 horizon 击败复杂网络。

每条路线至少有一个便宜基线：

| 路线   | 最小基线                                   |
| ------ | ------------------------------------------ |
| 决策   | 随机策略、无模型 Policy、规则动力学        |
| 视频   | 复制上一帧、无动作模型                     |
| JEPA   | 常量表示、未训练 Encoder、无动作 Predictor |
| 机器人 | state-only BC、直接 VLA                    |
| 空间   | 复制最后 Occupancy、匀速外推、已知几何     |

若复杂模型没有稳定超过简单基线，先不要增加参数。检查数据、目标与评价是否回答了同一个问题。

## 8.2 一步误差为什么不够

训练通常采样短片段，让模型预测下一步。使用时，模型可能连续推演几十步。

第二步开始，输入已经含有第一步误差。于是我们分别报告 horizon 1、5、15、30 或更长位置的指标。

```text
horizon → error / IoU / action consistency / task success
```

这条曲线告诉我们“可靠想象还能走多远”。Planner 的 horizon 不应远超模型可靠范围。

## 8.3 反事实不只是生成两段视频

反事实测试必须固定其他条件：

```text
相同历史 + action A → future A
相同历史 + action B → future B
```

随机种子、初始状态、目标与渲染条件都应相同。然后分层检查：内部 logits/feature 是否改变，解码结果是否改变，物体或状态是否按正确方向改变，真实任务是否因此改善。

“输出有差异”是必要条件，不是充分条件。随机噪声也能制造差异。

## 8.4 OOD：模型总会交出答案

神经网络在训练范围以外通常仍会输出一个数。它不会自动贴上“我没见过”。

我们主动改变：

- 更快的速度或更大的动作；
- 新颜色、纹理或背景；
- 新视角与相机标定误差；
- 新摩擦、物体质量与接触方式；
- 新语言组合或任务模板。

一次只改一个主要因素，才能判断失败来自哪里。若同时把画面、动作和目标全换掉，结果只能说明“整体不同”。

## 8.5 不确定性要接受校准

模型可能输出标准差、离散分布或碰撞概率。数值大不等于可信。

把许多预测按置信度分箱：模型说 70% 的事件中，真实发生比例是否接近 70%？

校准好的不确定性可以帮助系统：

- 缩短 rollout；
- 降低 OOD 候选动作得分；
- 请求真实观察或人工接管；
- 选择一次最能区分几种解释的安全行动。

最后一项叫信息价值。动作不只改变外部任务，也可以帮助模型弄清自己不知道什么。

## 8.6 Planner 为什么会专找模型漏洞

普通测试数据来自环境或人类。Planner 会搜索大量候选，主动找到模型预测特别乐观的区域。

如果世界模型错误地认为超大动作能瞬间到达目标，Planner 就会不断选择这种动作。模型平均误差可能不大，控制却完全失败。

检查方法包括：

1. 保存 Planner 选择动作与训练数据动作分布；
2. 在真实环境复核高分候选；
3. 给不确定或 OOD rollout 惩罚；
4. 缩短 horizon，每步重新观察；
5. 加入 Planner 找到的失败，再训练模型；
6. 与不使用世界模型的 Policy 比较。

这形成一个有意义的循环：Planner 暴露模型弱点，真实数据修正模型，而不是让模型永远在固定测试集上自我证明。

## 8.7 不同路线用不同主指标

### 决策与规划

主指标是真实环境 return、成功率与样本效率。多步 latent 指标用于解释，不替代任务结果。

### 可交互视频

主指标是动作一致性、长时漂移和每帧延迟。视觉质量很重要，但不能单独证明控制正确。

### JEPA

先检查坍缩和 probe，再检查动作敏感性与下游成功。被动数据不能报告控制结果。

### VLA 与机器人

主指标是任务成功、碰撞、OOD 与控制延迟。动作 MSE 只作辅助。

### 空间世界

静态重建看 novel-view、几何误差和速度；动态空间看时间一致性；驾驶 open-loop 看未来 IoU/ADE/FDE。闭环指标必须有可交互环境。

统一评价不是把它们压成一个总分，而是统一证据标准。

## 8.8 什么才算一次 24GB 验证

配方里写 `peak < 22GB` 只是目标。真正“24GB 已验证”至少要留下：

- 完整命令与 git commit；
- 数据版本、split 与校验和；
- seed、模型和训练配置；
- GPU、driver、CUDA 与 PyTorch 版本；
- peak allocated 与 peak reserved；
- wall time、训练曲线和最终指标；
- checkpoint SHA256；
- 失败或中断说明。

Smoke、截断训练和估算都不能改成“已验证”。本仓库当前神经模型完整 24GB 记录仍为 0。

## 8.9 现在重新问：世界模型到底是什么

课程开始时，我们把世界模型理解为“给定过去和候选动作，推测未来”。经过五条路线以后，这个说法仍有用，却还不完整。

在有限计算下，模型不可能复制整个世界。它必须压缩：保留哪些状态、关系、变化和不确定性，丢掉哪些细节。

[A Definition and Roadmap for World Models](https://arxiv.org/abs/2607.06401) 将世界模型讨论为对物理世界状态转移过程的有限资源压缩，并强调数据上限、局部观察、多模态异步信息和 agent–environment loop。它也把功能上的 renderer、simulator、planner 与表示上的像素、latent、结构化空间放在两条互补轴上。

这解释了为什么本书的五条路线可以重新组合：一种表示可以交给多个功能，一种功能也可以建立在不同表示上。

## 8.10 下一台模型不从模型名字开始

PA2 从 PA1 的一条稳定失败开始。先把失败写成可以重复的条件：

```text
当速度超出训练范围时，15 步 latent rollout 的位置误差翻三倍，
并使 CEM 选择超大动作，真实 return 下降。
```

然后至少提出两种解释：

- 数据没有覆盖快速度；
- 状态没有保存速度；
- dynamics 的随机性表达不够；
- Planner horizon 太长；
- reward model 让错误未来显得过于乐观。

每种解释都对应不同实验。研究不是先决定“我要加一个 Transformer”，再寻找它能解决什么。

## 8.11 三个可以继续追问的根问题

### 世界应该压成什么样

像素保留细节，却计算昂贵；latent 紧凑，却可能丢掉新任务需要的信息；3D 结构便于空间推理，却可能难以表示接触和材质。

真正问题不是选哪个流行架构，而是在有限计算下，哪些信息对未来干预仍然足够。

### 数据怎样跨过“广而无动作”与“有动作但很少”的鸿沟

互联网视频覆盖广，却缺少机器人动作；机器人数据有控制语义，却昂贵且窄。

可以先从广泛视频学习物体和物理先验，再用少量动作数据对齐控制；也可以从仿真生成失败与反事实，再用真实数据校准。关键是明确每层数据增加了什么证据。

### 模型怎样知道下一件最值得弄明白的事

模型不确定时，可以选择一个安全、又能区分几种可能解释的动作，再读取真实结果。

这使世界模型不再只是离线预测器，而成为：

```text
估计现在 → 想象几种未来 → 发现关键不确定性
→ 选择任务动作或信息动作 → 观察现实 → 更新理解
```

课程在第 0 章从“行动前先想一想”出发，到这里又多了一步：想过以后，还要知道什么时候应该回到现实中问一个好问题。

## 8.12 Z0 与 PA2

Z0 使用一个可计算 toy，练习 horizon、反事实、OOD、校准、Planner 漏洞与 run manifest。它不训练新网络。

PA2 把同一套方法用于学生的 PA1：

```text
稳定失败
→ 两种竞争解释
→ 最小改动
→ 能推翻自己的实验
→ 公平对照
→ 支持范围与未支持结论
```

最终交付不是一张新结构图，而是一段可以复现的研究证据。
