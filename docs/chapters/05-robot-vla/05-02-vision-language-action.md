# 5.2　图像、语言和机器人状态怎样合在一起

桌面上同时放着红杯和蓝杯。只看图片，机器人知道物体在哪里，却不知道本次任务要抓哪一个；只看“拿起蓝杯”，又不知道杯子位于哪里。

VLA 模型把视觉、语言和机器人状态共同映射到动作。

## 三类输入

```text
image → CNN/ViT → visual tokens
instruction → text tokenizer/encoder → language tokens
proprio → MLP → state token
```

Transformer 可以让这些 token 互相注意，再由 action head 输出动作。

## 同一画面换指令

最小反事实是固定图片和机器人状态，把“拿红杯”换成“拿蓝杯”。动作方向应该随目标改变。

如果训练数据中红杯总在左边、蓝杯总在右边，模型可能只记位置捷径。测试集需要交换颜色与位置，才能检查语言是否真的被使用。

## 预训练视觉语言模型提供什么

VLM 可以提供物体与语言的通用表示，减少从零学习语义的需要。但它通常不输出符合机器人坐标、频率和安全约束的关节动作。

VLA 还需要动作示范、机器人自身状态和控制接口。会看会说，不等于已经会动。

## 冻结还是微调

小数据下可以冻结视觉或语言 Encoder，只训练融合层与 action head，节省显存并减少过拟合。若相机视角和预训练图像差异很大，再逐步解冻后层。

公平对照应比较 state-only、image+state、image+language+state，而不是一次加入所有模态后只报告最好结果。

## 小结

- [ ] VLA 将图像、语言、proprioception 映射为机器人动作。
- [ ] 同一画面换指令，是检查语言条件是否生效的最小反事实。
- [ ] VLM 表示不能替代动作数据与控制接口。
