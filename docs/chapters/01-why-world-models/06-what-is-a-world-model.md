# 1.6　世界模型的定义

“世界模型”这个词被用得越来越宽，宽到几乎失去了区分力：有人用它指视频生成器，有人用它指物理引擎，有人用它指一整套机器人系统。本节要做的事情很具体——给出一个能逐项打勾的判据，然后拿它去审四个具体系统。判据的价值不在于把谁排除在外，而在于当有人说“我们做了一个世界模型”时，你知道该问哪三个问题。

---

## 桌上的四个系统

先摆出四个真实存在的系统，它们都与“预测世界”有关：

1. **MuJoCo 物理引擎**：给定当前状态和力矩，精确算出下一时刻的刚体位姿。
2. **文本到视频生成模型**：给一句话，生成一段看起来真实的视频。
3. **DQN 策略网络**：给一帧画面，直接输出该按哪个键。
4. **DreamerV3**：把画面压成潜在状态，在潜在空间里推演未来并训练策略。

凭直觉，第 4 个显然是世界模型，第 3 个显然不是。第 1 和第 2 个则众说纷纭。要把这件事说清，需要先把判据写下来。

---

## 三条必要条件

我们采用如下工作定义。一个系统是世界模型，当且仅当它同时满足三条：

**条件一：它预测未来，而不是标注当前。**

形式上，它给出的是一个关于未来的分布或点估计：

$$\hat{P}(s_{t+1}, r_t \mid s_t, a_t) \quad \text{或} \quad (\hat{s}_{t+1}, \hat{r}_t) = f_\theta(s_t, a_t).$$

图像分类器 $P(y \mid x)$ 不满足这一条：它描述当前输入的属性，时间轴上没有前进。

**条件二：动作出现在条件一侧，且预测对动作敏感。**

这是 1.5 节反事实分歧的正式化。要求存在状态 $s$ 与动作对 $a \neq a'$，使得

$$\hat{P}(\cdot \mid s, a) \neq \hat{P}(\cdot \mid s, a').$$

被动视频生成器不满足这一条——不是因为它效果差，而是因为它的输入端没有动作这个接口。

**条件三：规律从数据里学出来，而不是人写下来。**

$$\theta^* = \arg\max_\theta \; \mathbb{E}_{(s,a,s') \sim \mathcal{D}}\left[\log \hat{P}_\theta(s' \mid s, a)\right].$$

物理引擎不满足这一条。它的转移规则是工程师用微分方程和碰撞算法写死的，参数需要手工标定，遇到未建模的现象（布料、液体、复杂摩擦）它不会从数据里自行改正。

三条之外还有一条**软要求**：模型的输出应当能被某个使用者消费——规划器、策略、碰撞检查器或人类操作员。一个谁都用不上的预测器在工程意义上不构成世界模型，但这一条不写进硬判据，因为它取决于系统边界怎么划。

---

## 拿判据审四个系统

| 系统            | 预测未来 | 动作条件 | 从数据学 | 判定                   |
| --------------- | -------- | -------- | -------- | ---------------------- |
| MuJoCo 物理引擎 | 是       | 是       | 否       | 不是，是**手写模拟器** |
| 文本到视频模型  | 是       | 否       | 是       | 不是，是**被动生成器** |
| DQN 策略        | 否       | —        | 是       | 不是，是**无模型策略** |
| DreamerV3       | 是       | 是       | 是       | 是                     |

这张表有两处值得停下来想。

**物理引擎的落选不是贬低。** 在参数标定准确、现象已被建模的场合，物理引擎比任何学出来的模型都精确得多，第 7 章的 Sim-to-Real 全部建立在它之上。它被排除只是因为它不学习——这既是它的优点（不需要数据、不会幻觉），也是它的局限（未建模现象无法补救）。两者结合的做法叫残差学习：让网络只学模拟器算不准的那部分，这是 8.6 节的主题。

**DQN 的落选也不是贬低。** 它把“预测后果”这一步隐式地压进了 $Q(s,a)$ 里，跳过了对未来的显式推演。省掉推演换来了推理速度，代价是无法回答“如果我改做另一件事会怎样”这类问题。

---

## 三件常被误认为必要的事

判据里没有出现的东西同样重要，因为它们经常被误当成门槛。

**不要求重建像素。** MuZero 完全不还原画面，它只学搜索需要的三样东西：

$$s_t = h_\theta(o_{\le t}), \qquad (\hat{r}_t, s_{t+1}) = g_\theta(s_t, a_t), \qquad (\hat{v}_t, \hat{\pi}_t) = f_\theta(s_t).$$

三条必要条件全部满足，所以它是世界模型，而且是最纯粹的一种——潜在状态里只留下了对决策有用的信息。第 6 章的 JEPA 同理，它预测特征而非像素。

**不要求状态严格马尔可夫。** 1.1 节讲过，内部状态只需是对预测“充分好”的统计量。RSSM 用固定维度的 $(h_t, z_t)$ 近似信念状态，这个近似不完美，但足以支撑规划。

**不要求可解释。** 潜在维度对不上任何物理量，不影响它是不是世界模型。可解释性是研究者的便利，不是定义的一部分。

反过来说，判据里也没有为“规模”留位置。一个 $3 \times 3$ 网格上的计数转移表，只要三条都满足，就是一台合格的世界模型——这正是 1.8 节要亲手做的东西。

## 把条件二变成一次测量

三条里只有条件二是需要动手验证的（另外两条看设计就知道）。把它写成一个可计算的标量：固定一批状态，对每个状态取两个不同动作，测量两个预测分布的总变差距离并取平均：

$$D_{\text{cf}} = \frac{1}{|\mathcal{S}|}\sum_{s \in \mathcal{S}} \; \frac{1}{2}\sum_{s'} \left| \hat{P}(s' \mid s, a) - \hat{P}(s' \mid s, a') \right|.$$

$D_{\text{cf}} = 0$ 意味着模型完全无视动作；$D_{\text{cf}} = 1$ 意味着两个动作导致完全不重叠的未来。

```python
import numpy as np

def counterfactual_divergence(model, states, a1, a2):
    """对每个状态比较两个动作的预测分布，返回平均总变差距离。"""
    gaps = []
    for s in states:
        p1 = model(s, a1)          # 形状 [n_next_states] 的概率向量
        p2 = model(s, a2)
        gaps.append(0.5 * np.abs(p1 - p2).sum())
    return float(np.mean(gaps))

# 三个模型：无视动作的、听动作的、把动作反过来用的
n = 4
def deaf_model(s, a):                       # 条件二不满足
    p = np.zeros(n); p[(s + 1) % n] = 1.0; return p

def good_model(s, a):                       # 条件二满足
    p = np.zeros(n); p[(s + (1 if a == 0 else -1)) % n] = 1.0; return p

states = list(range(n))
print(f"无视动作的模型 D_cf = {counterfactual_divergence(deaf_model, states, 0, 1):.2f}")
print(f"听从动作的模型 D_cf = {counterfactual_divergence(good_model, states, 0, 1):.2f}")
```

运行输出：

```text
无视动作的模型 D_cf = 0.00
听从动作的模型 D_cf = 1.00
```

注意 $D_{\text{cf}}$ 大只说明模型对动作有反应，**不说明反应的方向是对的**。一个把左右接反的模型同样能拿到 $D_{\text{cf}} = 1$。所以这项测量必须与真实转移对照使用，单独看它会被骗。

## 自测与常见陷阱

### 自测题

1. **判断题**：一个能够根据方向盘输入生成对应驾驶视频的模型，如果它的转移规则完全由人工编写的车辆动力学方程给出，它是世界模型吗？
   - _解析_：不是。它满足条件一与条件二，但违反条件三，属于手写模拟器加渲染器。若在其输出上再学一个残差网络来修正误差，则整个系统成为“模拟器 + 学习式世界模型”的混合体。
2. **思考题**：为什么把“能重建高清画面”写进定义会是一个坏主意？
   - _解析_：会把 MuZero 与 JEPA 这两类最重要的工作排除在外。重建像素只是获取训练信号的一种手段，而且是最昂贵的一种——它迫使模型为与任务无关的视觉细节买单（第 6 章的核心论点）。定义应当围绕“预测动作后果”这一功能，而非围绕输出的模态。
3. **计算题**：某模型在 $100$ 个状态上测得 $D_{\text{cf}} = 0.02$，而真实环境的两个动作导致完全不同的后继状态（真实 $D_{\text{cf}} = 1.0$）。这说明什么？
   - _解析_：说明动作接口几乎失效——模型把动作当成了可忽略的输入。常见原因有三：动作与帧的时间对齐错位、动作嵌入维度过小被淹没，或者训练数据里动作分布过于集中（1.5 节的采集偏置）。这属于必须在训练早期拦住的失效。

### 常见误区与工程陷阱

- **误区 1：以模态论定义**。“输出视频的才是世界模型”“输出潜在向量的不算”都站不住。判据关心的是条件与预测的结构，不是输出长什么样。
- **误区 2：把演示视频当作证据**。一段流畅的演示只能证明感知质量，无法证明条件二。必须固定起点、只换动作、给出分歧数值，这是第 9 章评测体系的起点。
- **误区 3：混淆“系统里有世界模型”与“系统是世界模型”**。现代机器人栈往往同时含有策略、世界模型、模拟器和检查器。讨论时要指明说的是哪个部件，否则关于“它算不算”的争论毫无意义。

---

## 小结与下节预告

- 世界模型的三条必要条件是：**预测未来、动作在条件一侧且预测对动作敏感、规律从数据学出**。
- 物理引擎因不学习而落选，被动视频生成器因缺少动作接口而落选，无模型策略因不显式预测未来而落选——落选都不等于无用。
- 定义**不要求**重建像素、不要求状态严格马尔可夫、不要求可解释，也不要求规模；条件二是唯一需要动手测量的一条，且必须与真实转移对照。
