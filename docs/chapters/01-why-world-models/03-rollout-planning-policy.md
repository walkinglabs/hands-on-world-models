# 1.3　多步推演与规划

只看眼前一步的动作后果，很容易掉入“局部最优但全局灾难”的陷阱。在稍微复杂的环境中，一步向前的收益可能紧跟着万丈深渊，而看似迂回的绕行才是通往目标的唯一生路。世界模型的真正力量，在于它能够将单步转移函数反复作用于自身，在智能体的脑海中展开多步推演（Rollout），让规划器提前比较长远未来的得失；同时通过模型预测控制（MPC）实现“深谋远虑，笃行一步”的动态闭环修正。

---

## 贪心算法为什么会在两步内失败？

我们把物理世界抽象为一个经典的 $3 \times 3$ 离散网格环境：智能体从左上角起点 $(0,0)$ 出发，任务目标是到达右下角 $(2,2)$，中间 $(1,1)$ 设有一处致命陷阱，四周为不可逾越的边界墙。

```text
(0,0) S ── [ (0,1) 空地 ] ── [ (0,2) 空地 ]
   │
[ (1,0) 空地 ] ── [ (1,1) 陷阱 × ] ── [ (1,2) 空地 ]
   │
[ (2,0) 空地 ] ── [ (2,1) 空地 ] ── (2,2) 目标 G
```

环境奖励函数 $R(s, a, s')$ 与曼哈顿距离代价定义如下：

- 到达目标 $G(2,2)$：即时奖励 $r = +10.0$；
- 掉入陷阱 $\times(1,1)$：即时惩罚 $r = -10.0$ 并终止；
- 每移动一步：消耗时间惩罚 $r = -1.0$；
- 到达目标的曼哈顿距离启发式代价：$h(x, y) = |x - 2| + |y - 2|$。

现在智能体位于起点 $(0,0)$，其曼哈顿距离为 $h(0,0) = 4$。智能体面临两个合法动作：

1. **选择动作 $\text{Right}$（向右走）**：
   - 到达状态 $(0,1)$，距离目标 $h(0,1) = |0-2| + |1-2| = 3$；
   - 距离缩短了 $1$，看似更接近目标！
2. **选择动作 $\text{Down}$（向下走）**：
   - 到达状态 $(1,0)$，距离目标 $h(1,0) = |1-2| + |0-2| = 3$；
   - 距离同样缩短为 $3$。

若智能体采用无长远推演的 1 步近视贪心策略（短视视野 $H=1$），在 $(0,1)$ 时它会再次计算下一步候选动作：

- 在 $(0,1)$ 执行 $\text{Down}$ 进入 $(1,1)$：距离变为 $|1-2| + |1-2| = 2$（更近了！），于是贪心策略毫不犹豫地踏入 $(1,1)$ 陷阱，任务直接宣告失败。

```text
短视贪心决策 (H=1):
(0,0) [h=4] ──Right──> (0,1) [h=3] ──Down──> (1,1) 掉入陷阱死亡！[r = -10]

长程前瞻推演 (H=4):
(0,0) ──Right──> (0,1) ──Right──> (0,2) ──Down──> (1,2) ──Down──> (2,2) 成功通关！[G = +6]
(0,0) ──Down───> (1,0) ──Down───> (2,0) ──Right──> (2,1) ──Right──> (2,2) 成功通关！[G = +6]
```

**结论非常明确**：一步推理看到的收益往往是假象，只有将时间轴向未来延伸，才能看清陷阱与通途。

## 多步推演（Rollout）与时域展开

为了看清更远的未来，智能体需要调用单步动力学模型 $f_\theta(s_t, a_t)$ 进行链式自回归迭代：

$$s_{t+1} = f_\theta(s_t, a_t),$$
$$s_{t+2} = f_\theta(s_{t+1}, a_{t+1}) = f_\theta\left(f_\theta(s_t, a_t), a_{t+1}\right),$$
$$\vdots$$
$$s_{t+H} = f_\theta(s_{t+H-1}, a_{t+H-1}).$$

这种在智能体内部展开的自回归预测序列称为 **Rollout（推演展开）**，$H$ 称为 **Planning Horizon（规划时域 / 前瞻深度）**。

一条长度为 $H$ 的推演轨迹可以紧凑地表示为状态与动作的交替链条：

$$\tau_{t:t+H} = \left( s_t, a_t, s_{t+1}, a_{t+1}, s_{t+2}, \dots, a_{t+H-1}, s_{t+H} \right).$$

### 预测时域 $H$ 的计算代价爆炸

随着预测时域 $H$ 的增加，穷举搜索的动作序列空间呈指数级膨胀。设离散动作空间大小为 $|\mathcal{A}|$，则深度为 $H$ 的完整搜索树包含的叶节点数为：

$$N_{\text{nodes}} = |\mathcal{A}|^H.$$

| 规划时域 $H$ | 动作空间 $|\mathcal{A}| = 4$ 时的候选序列总数 | 规划视野评估 |
| :--- | :--- | :--- |
| $H = 1$ | $4^1 = 4$ | 极其短视，极易陷入即时陷阱 |
| $H = 3$ | $4^3 = 64$ | 可避开浅层障碍，但看不见深层目标 |
| $H = 6$ | $4^6 = 4,096$ | 能够规划完整绕行路径，但开销增大千倍 |
| $H = 12$ | $4^{12} = 16,777,216$ | 穷举无法实时运行，必须引入采样或启发式剪枝 |

因此，工业界与学术界的世界模型规划器（如 PlaNet 的 CEM 交叉熵方法、MuZero 的 MCTS 蒙特卡洛树搜索）的核心研究主题之一，就是**如何在不穷举全部 $|\mathcal{A}|^H$ 空间的前提下，高效找到近似最优的动作序列**。

## 世界模型、规划器与策略的严格分工

在现代强化学习与具身智能文献中，初学者经常混淆世界模型、规划器和策略。它们在系统架构中承担着截然不同、边界清晰的职责：

```text
┌───────────────────────────────────────────────────────────────┐
│                          智能体内部决策脑                      │
│                                                               │
│   ┌───────────────────┐               ┌───────────────────┐   │
│   │  世界模型 f_θ(s,a) │ <──推演交互── │   规划器 Planner   │   │
│   │  (物理世界模拟器)   │ ──预测未来──> │ (在线搜索评估未来) │   │
│   └───────────────────┘               └─────────┬─────────┘   │
│                                                 │ 生成动作      │
│                                                 ▼             │
│   ┌───────────────────┐ 快速本能映射 a = π(s)     │             │
│   │   策略网络 π_ϕ(s)  │ ───────────────────────┼─────────────┼─┐
│   └───────────────────┘                         │             │ │
└─────────────────────────────────────────────────┼─────────────┼─┘
                                                  │ 施加控制     │ │
                                                  ▼             ▼ ▼
                                     ┌────────────────────────────┐
                                     │   真实物理环境 Environment  │
                                     └────────────────────────────┘
```

1. **世界模型（World Model, $f_\theta$）**：
   - 职责：回答“物理规律是什么”。输入当前状态 $s_t$ 与动作 $a_t$，输出下一状态 $s_{t+1}$ 及预期奖励 $\hat{r}_t$。
   - 接口定义：$s_{t+1}, \hat{r}_t = f_\theta(s_t, a_t)$。
2. **规划器（Planner）**：
   - 职责：回答“怎样选才能最大化长期收益”。它不直接与真实世界接触，而是反复调用世界模型 $f_\theta$ 展开多条候选轨迹，通过评价函数打分，挑出第一步最优动作。
   - 接口定义：$a_t^* = \operatorname{Planner}(s_t, f_\theta, \text{Task Objective})$。
3. **策略（Policy / Actor, $\pi_\phi$）**：
   - 职责：回答“面对当前局面直接做什么”。它是一个固化的参数化映射网络，无需在线推演搜索，耗时极短（如 $1\text{ ms}$）。
   - 接口定义：$a_t \sim \pi_\phi(a_t \mid s_t)$。

### 规划器与策略的权衡对比

| 维度               | 在线规划器（Planner，如 MPC / CEM / MCTS）     | 离线策略网络（Policy / Actor）                |
| :----------------- | :--------------------------------------------- | :-------------------------------------------- |
| **计算延迟**       | 高（每次决策需在模型内部展开数十至数千次推演） | 极低（单次前向传播，适合毫秒级高频控制）      |
| **目标适应性**     | 极强（更换目标坐标仅需修改代价函数 $c(s, g)$） | 弱（目标改变需重新收集数据或重训练网络）      |
| **模型误差敏感度** | 依赖在线重采样与真机反馈修正                   | 在想象中训练时容易被模型的漏洞欺骗（过拟合）  |
| **典型代表系统**   | PlaNet (Hafner 2019)、TD-MPC2 (Hansen 2024)    | Dreamer 系列 (Hafner 2020-2023)、ACT、OpenVLA |

## 模型预测控制（MPC）：想深几步，只走一步

如果世界模型在推演到第 $5$ 步时累积了 $20\%$ 的误差，我们是否应该直接执行这 $5$ 步生成的全部动作？

**绝对不能。** 工业界控制领域经过数十年工程血泪总结出的黄金法则是：**模型预测控制（Model Predictive Control, MPC）——深谋远虑，只行一步；即时观察，动态重置。**

MPC 的数学优化问题可以严格形式化为如下有限时域最优控制方程：

$$\mathbf{a}_{t:t+H-1}^* = \arg\max_{a_{t:t+H-1}} \sum_{k=0}^{H-1} \gamma^k \hat{r}\left(\hat{s}_{t+k}, a_{t+k}\right) + \gamma^H V_\psi\left(\hat{s}_{t+H}\right),$$

$$\text{s.t.} \quad \hat{s}_t = s_t, \quad \hat{s}_{t+k+1} = f_\theta\left(\hat{s}_{t+k}, a_{t+k}\right).$$

MPC 的标准闭环控制工作流如下：

$$ \boxed{\begin{aligned}
&\text{1. 读取环境当前真实观察，确定状态 } s_t \\
&\text{2. 在世界模型内部展开 } H \text{ 步推演，求解最优动作序列 } (a_t^*, a_{t+1}^*, \dots, a_{t+H-1}^*) \\
&\text{3. \textbf{仅将第一个动作} } a_t^* \text{ 发送给物理执行器执行} \\
&\text{4. 放弃后续规划序列，在 } t+1 \text{ 时刻读取新观察 } o_{t+1} \text{，重置状态并开启新一轮规划}
\end{aligned}}$$

```text
时刻 t   : [规划 H=3 步] : (a_t*, a_{t+1}, a_{t+2}) ──> 只执行 a_t* ──> 环境反馈真机状态 s_{t+1}
时刻 t+1 : [丢弃旧推演] : (从真实 s_{t+1} 重新规划 H=3 步) ──> 只执行 a_{t+1}* ──> 环境反馈 s_{t+2}
```

通过每一步都回到真实物理世界锚定起点，MPC 彻底斩断了多步推演误差在物理时间线上的长期积累。

## 从零实现：网格世界中的 Rollout 与 MPC 规划器

下面是用纯 Python 实现的网格世界、一步贪心策略、多步 Rollout 搜索与闭环 MPC 控制器：

```python
import itertools
import numpy as np

class GridWorldModel:
    """3x3 网格确定性动力学模型"""
    ACTIONS = {'up': (0, -1), 'down': (0, 1), 'left': (-1, 0), 'right': (1, 0)}

    def __init__(self, trap=(1, 1), goal=(2, 2)):
        self.trap = trap
        self.goal = goal

    def step(self, state: tuple, action: str) -> tuple:
        """模型单步转移: (x, y) + action -> (next_state, reward, done)"""
        if state == self.trap:
            return state, -10.0, True
        if state == self.goal:
            return state, 0.0, True

        dx, dy = self.ACTIONS[action]
        nx = int(np.clip(state[0] + dx, 0, 2))
        ny = int(np.clip(state[1] + dy, 0, 2))
        next_state = (nx, ny)

        if next_state == self.trap:
            reward = -10.0
            done = True
        elif next_state == self.goal:
            reward = 10.0
            done = True
        else:
            reward = -1.0
            done = False
        return next_state, reward, done

    def rollout(self, start_state: tuple, action_seq: list) -> float:
        """在内部展开推演一条动作序列，计算累计回报"""
        curr = start_state
        total_return = 0.0
        for act in action_seq:
            curr, r, done = self.step(curr, act)
            total_return += r
            if done:
                break
        return total_return

class MPCPlanner:
    def __init__(self, model: GridWorldModel, horizon: int = 4):
        self.model = model
        self.horizon = horizon
        self.actions = list(GridWorldModel.ACTIONS.keys())

    def plan(self, current_state: tuple) -> str:
        """枚举 horizon 长度的全部动作序列，返回第一步最优动作"""
        best_return = -float('inf')
        best_first_action = None

        for seq in itertools.product(self.actions, repeat=self.horizon):
            ret = self.model.rollout(current_state, seq)
            if ret > best_return:
                best_return = ret
                best_first_action = seq[0]
        return best_first_action

# 运行对照实验
wm = GridWorldModel()
planner = MPCPlanner(wm, horizon=4)

# 模拟真实世界中的 MPC 闭环轨迹
state = (0, 0)
trajectory = [state]
print("===== 启动 MPC 闭环控制 (Horizon = 4) =====")
for t in range(10):
    if state == wm.goal or state == wm.trap:
        break
    act = planner.plan(state)
    next_state, r, done = wm.step(state, act)
    print(f"步骤 {t}: 当前位置 {state} ──规划决策执行 [{act:5s}]──> 进入 {next_state} (奖励: {r:+.1f})")
    state = next_state
    trajectory.append(state)

assert trajectory[-1] == (2, 2), "MPC 未能成功到达目标！"
print(f"成功抵达终点！完整闭环轨迹: {trajectory}")
```

运行输出：

```text
===== 启动 MPC 闭环控制 (Horizon = 4) =====
步骤 0: 当前位置 (0, 0) ──规划决策执行 [down ]──> 进入 (0, 1) (奖励: -1.0)
步骤 1: 当前位置 (0, 1) ──规划决策执行 [down ]──> 进入 (0, 2) (奖励: -1.0)
步骤 2: 当前位置 (0, 2) ──规划决策执行 [right]──> 进入 (1, 2) (奖励: -1.0)
步骤 3: 当前位置 (1, 2) ──规划决策执行 [right]──> 进入 (2, 2) (奖励: +10.0)
成功抵达终点！完整闭环轨迹: [(0, 0), (0, 1), (0, 2), (1, 2), (2, 2)]
```

实验证明：通过 $H=4$ 的前瞻推演与 MPC 逐帧重新规划，智能体完美绕过了 $(1,1)$ 的陷阱，走出了一条全局最优避障轨迹。

## 自测与常见陷阱

### 自测题

1. **判断题**：在无噪声的完美确定性环境中，计算出长度为 $H=10$ 的最优动作序列后，直接一口气在真实世界执行这 10 个动作，与每步都重新做 MPC 的效果完全等价吗？
   - *解析*：在模型与环境 100% 绝对一致且无随机扰动的极端理论假设下等价；但在实际工程中，外界微小扰动或环境微小漂移都会导致开环执行迅速偏航，因此工业界即使在标称确定系统上也必须运行闭环 MPC。
2. **计算题**：机械臂关节动作空间为离散 $7$ 维（7 个自由度），每个自由度有 3 种控制离散量（$-1, 0, +1$），动作空间大小为 $|\mathcal{A}| = 3^7 = 2187$。若规划时域 $H=5$，穷举推演需要评估多少个候选轨迹？
   - *计算*：
     $$N = |\mathcal{A}|^H = 2187^5 \approx 4.97 \times 10^{16} \text{ 条轨迹}.$$
     这在算力上不可承受，必须使用连续优化或交叉熵采样（CEM）。
3. **思考题**：为什么 Dreamer 不采用像 PlaNet 那样每步用 MPC 现场推演，而是要训练一个 Actor 策略网络？
   - *解析*：因为现场推演（Online Planning）计算延迟极高（需在 GPU 上并行展开数千条长轨迹），无法满足无人机或四足机器人 $50\text{ Hz}\sim 500\text{ Hz}$ 的实时控制需求；Dreamer 将推演成果预先蒸馏进 Actor 网络，实现微秒级快速反应。

### 常见误区与工程陷阱

- **误区 1：把预测时域 $H$ 设得过大**。初学者常以为 $H$ 越大越好，但由于复合误差的存在，当 $H$ 超出模型的有效动力学时域时，深层的预测完全退化为幻觉，规划器会基于荒谬的预测做出错误的当前决策。
- **误区 2：忽视终止状态与打折衰减**。在多步推演中，如果推演轨迹已经进入死亡终止状态，必须截断后续累计奖励计算；否则若不处理 Done 信号，智能体会误以为穿过陷阱后还能继续拿到终点奖励。
- **误区 3：开环推演（Open-loop）与闭环推演（Closed-loop）混淆**。开环推演是固定给定一串动作序列 $\mathbf{a}_{1:H}$；闭环推演是在推演内部每一步都让策略网络根据推演出的新潜状态 $\hat{s}_k$ 重新生成动作 $a_k = \pi(\hat{s}_k)$。训练 Actor-Critic 必须使用闭环推演。

## 小结与下节预告

- 单步贪心容易被近视指标误导进入陷阱，**多步推演（Rollout）** 是评估长远收益的根本途径。
- **世界模型** 负责生成可能未来，**规划器** 负责推演比较未来，**策略网络** 负责快速映射执行动作。
- **MPC 滚动时域控制** 遵循“想 $H$ 步，行 1 步”的闭环原则，是抵御动力学累积误差的坚固防线。

在这一节中，网格世界的物理转移规则是由我们手工写好的。然而在真实科研与工程场景中，大自然不会提供现成的物理转移代码。在下一篇 [1.4 从经历学习动力学](/chapters/01-why-world-models/04-learned-dynamics) 中，我们将拿走手工规则表，探索如何从智能体采集的离散轨迹数据中，用统计与机器学习方法纯自主地学出一台世界模型。
$$
