## 第一步：把失败写成别人能复现的条件

调参和研究的分界线在这里。调参说「loss 不降，我改学习率」。研究说「我知道它在什么条件下稳定失败，我有两个解释，我设计实验看哪个对」。

稳定失败不是「有时候不好」。它是：固定初始条件、随机种子、超参数，跑三次失败三次，而且失败模式差不多。这次 OOM、下次 loss 飞了，那是工程 bug，先修再做 PA2。

$$
\text{失败}(s_0, \xi, \mathrm{seed})=1
\quad\text{对 } \mathrm{seed}\in\{s_1,s_2,s_3\}
\text{ 都成立}
$$

其中 \(\xi\) 是你写明的条件：遮挡步数、速度、物体个数、动作幅值。9.2 的玩具版可以写成：「尺度 0.9 的模型在 \(H=12\) 时 MSE=0.96，三个起点都落后」。路线项目必须换成你的模型。

**运行这一步，你会看到什么？** 一条命令、一个 checkpoint 哈希、三个 seed 的同一指标。别人拿走能复现，这一步才算完。复现不了，先回 9.2，别改模型。

## 第二步：两种解释必须预测不同的 \(\Delta\)

只写一种解释，你会下意识找支持它的证据。至少两种，而且它们指向不同改动。

还是用「遮挡三步以上丢位置」：

```text
解释 A（记忆不足）：历史窗口只有 5 步，遮挡前的位置三步后被挤出记忆。
  预测：窗口加到 20，主要改善长遮挡，短遮挡几乎不动。

解释 B（物体混淆）：状态里没有物体，多个东西压成一个特征。
  预测：加长历史也不够；同时有 3 个以上物体仍失败；加跟踪才会好。
```

用符号写，就是事先指定两个切片：

$$
\Delta_{\mathrm{long}}=R_{\mathrm{new,long}}-R_{\mathrm{old,long}},\qquad
\Delta_{\mathrm{short}}=R_{\mathrm{new,short}}-R_{\mathrm{old,short}}
$$

若 \(\Delta_{\mathrm{long}}\gg\Delta_{\mathrm{short}}\)，支持 A；若多物体切片仍然差，支持 B；两个都涨或都不涨，两个解释都可能错。

**关键判据**：如果两种解释预测同一个 \(\Delta\)，它们不是竞争解释。找同学聊十分钟，通常能逼出第二种。

## 第三步：最小改动，真的写代码

单变量原则：

$$
\Delta y=f(x_1',x_2,\ldots)-f(x_1,x_2,\ldots)
$$

\(x_1\) 可以是输入、状态、预测目标、损失、数据、推理接口里的**一个**。同时换 Encoder、加数据、改 loss、换 Planner，最后分数涨了，你不知道是谁起作用，甚至可能两项互相抵消。

什么叫已经实现，而不是还在想：

- 能跑前向
- 能算梯度（若你的方法需要）
- 能用和旧模型同一份评价函数出数字

```python
# 骨架：除了那一个旗标，其余全部共用
def run(seed, add_velocity):
    model = build_model(add_velocity=add_velocity)
    model.fit(train_data, seed=seed, steps=OLD_STEPS)
    return evaluate_with_z0_metrics(model, test_data)

for seed in (0, 1, 2):
    print(seed, run(seed, False), run(seed, True))
```

`OLD_STEPS` 必须和旧模型相同。新模型参数变多，要在表里另开一列，不能把「多训了一倍」说成方法赢了。

**运行这一步，你会看到什么？** 一份只动一处的 diff，两边都能出 9.2 那几项指标。还停在架构图上，这一步没做完。

## 第四步：事前写死四种结果怎么判

这是最容易跳过、也最能把「调参」和「研究」分开的一步。科学的标志是它可以被证伪。假设怎么都不会错，那就不是假设。

四个格子在跑之前填：

| 若看到                       | 事先规定的读法                 |
| ---------------------------- | ------------------------------ |
| 目标场景升、其它场景几乎不动 | 支持你选的解释                 |
| 所有场景一起升一小点         | 可能只是参数或训练更久         |
| 目标场景几乎不动             | 解释错了，换另一条             |
| 目标场景更差                 | 改动有害；负结果，循环仍算完成 |

遮挡例子可以写成更硬的数：长遮挡从 0.3 降到 0.1、短遮挡不动 → 支持 A；长遮挡只到 0.25、多物体仍是 0.28 → 反对 A；所有场景都降 0.02 → 不像记忆问题；长遮挡变成 0.4 → 解释错了。

这些句子必须出现在训练日志的**前面**，不能出现在看完曲线之后。

## 第五步：先排除更简单的替代

大动干戈之前，先问：有没有更便宜的办法？

- 多加点这类失败的数据，finetune 一下？
- 调学习率、多训几轮？
- 把 Planner 的 horizon 缩短，或加动作限幅？
- 数据预处理把时间对齐搞错了？

**先试这些。** 简单办法就解决了，复杂改动就是多余的。报告里要写试过哪些、为什么不够。写「没时间试」比假装试过更诚实，但该项会扣分。

这一步的数学含义是：你声称 \(x_1\) 是因果，必须先排除「其实是样本量」和「其实是预算」。否则 \(\Delta y\) 解释不唯一。

## 第六步：公平对照，别作弊

对照实验估计的是

$$
\widehat{\Delta}=\frac1K\sum_{k=1}^{K}\bigl(R_{\mathrm{new}}(\mathrm{seed}_k)-R_{\mathrm{old}}(\mathrm{seed}_k)\bigr)
$$

\(K\ge 3\)。一次 seed 的提升不算数。还要报标准差，以及至少几个失败样例：新模型是在原来失败的地方成功了，还是把失败挪到了别处？

五条不能破：

1. 同样的 seed 集合
2. 同样的计算预算（步数，不是「我觉得收敛了」）
3. 同样的评测代码
4. 失败样例也看
5. 负结果也报

DreamerV3 用一套超参打通 150+ 任务 [4]，工程上靠的就是这种干净对照，不是靠每次换一套故事。

## 第七步：六个问题，负结果也能成立

实验跑完，3–5 页，按六个问题写。详细格式和分数在 PA2。这里只强调第 5 和第 6 问最容易空：

- **结果没有支持什么？** 必须点名一个被否掉的解释，或一个变差的切片。
- **下一步最值得做什么？** 只写一项最小证据，不要列愿望清单。

负结果不是失败。它排除一个错误方向，和「这条路走得通」同样完成循环。反过来，只报提升、藏下降、对照不公平——主指标涨了也不算合格。

三个可以真正去做最小验证的入口，在这里变成选择：

- **补证据**：少看了触觉、第二视角、控制延迟？补一个，看原来的失败还在不在。
- **改状态**：像素、任务特征、物体、BEV，换一种表示，谁先在新任务上死。
- **接现实**：模型能不能说「我不知道」，选一个既安全又能区分解释的动作去试。

## 已知简化与坑

- **课程规模很小。** 三次 seed、一个切片、一个改动，得不出「通用世界模型」这种结论。
- **负结果容易被自己劝回去。** 「再训久一点就好了」如果事前没写进预算，就是事后改规则。
- **解释 A 和解释 B 共用同一个改动**，无法区分。改动必须只打中其中一个预测。
- **模板里的 `assert True` 会绿。** 它不证明你做了研究。
- **引用要和改动真正相关。** 堆 20 篇综述，参考文献项不算过。

## 本节小结

- **研究从稳定复现的失败开始**，不是从新模型名字开始。
- **两种解释必须预测不同的 \(\Delta\)**，否则不是竞争。
- **一次只改一个变量**，其余与旧模型共用。
- **四种结果的读法写在训练前面。**
- **先试更简单的替代**，再谈新方法。
- **公平对照看多种子和同一预算**；负结果只要干净，就成立。

```text
先看系统在哪个具体条件下失败
→ 判断它缺信息、状态、预测、评价还是行动接口
→ 提出竞争假设，设计能推翻自己的实验
→ 写代码做最小组件改动
→ 跑公平对照
→ 诚实地报告支持什么、不支持什么
```

今天我们把这套系统叫作世界模型。将来可能会有新的名字、新的架构，但这套从失败中学习、用证据说话、自己动手改的方法不会变。
