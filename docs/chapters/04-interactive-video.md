# 第 4 章　可交互视频：按键以后，画面应该怎样变化

路线 A 把未来留在 latent 里，主要用它训练策略。现在换一个目标：我们希望人能直接看见模型推演出的世界，而且可以按键改变它。

这不是普通视频生成。给定一段开头，普通视频模型只要生成一种看起来合理的后来。可交互视频模型还必须回答反事实问题：同一个起点，向左和向右会得到什么不同画面？

## 4.1 这条路线交出什么

模型读入：

```text
过去若干帧 + 当前动作
```

模型交出：

```text
下一帧像素
或下一帧的离散 token
或下一帧的连续 latent
```

它通常不替玩家选择动作。它负责让画面忠实地表现动作后果。

因此，评价不能只有“清不清楚”。我们至少检查四件事：

- **动作一致性：**换按键以后，物体是否按照对应方向改变；
- **长时稳定：**模型连续吃自己的输出以后，是否漂移、消失或卡住；
- **视觉质量：**小物体、文字与边缘是否仍可辨认；
- **交互速度：**一帧需要多久，能否在下一次按键以前交出结果。

这条路线只要求学完第 0–2 章。第 3 章的 RSSM 与 Actor-Critic 可以用来对照，但不是先修。

## 4.2 第一个困难不是模型，而是时间

假设数据按下面方式保存：

```text
frame_0, action_0, frame_1, action_1, frame_2
```

这里 `action_0` 造成 `frame_0 → frame_1`。若采集程序把按键记录在渲染之后，真实对齐可能向后错一格。

错位数据仍然可能让 loss 下降。模型会从画面惯性猜下一帧，却学不会按键的作用。于是我们在 B1 训练以前先做三项检查：

1. 显示 `frame_t、action_t、frame_{t+1}`；
2. 用规则环境验证位移方向；
3. 记录 control frequency、渲染频率和输入延迟。

数据的时间接口不可靠，后面换更大 Transformer 也不会修好因果关系。

## 4.3 为什么先压缩画面

一张 `64×64×3` 图片有 12288 个通道值。若把每个像素值当成一个离散记号，一帧就成为很长的序列。

我们先用 VQ-VAE 做一件事：把一块局部图像换成一个码本编号。

```text
图片 → Encoder → 连续特征
                ↓ 找最近码字
             离散编号 → Decoder → 重建图片
```

例如，一张 `16×16` 图片经过两次下采样，可以得到 `4×4` 的 token 网格。模型不用预测 768 个颜色值，只需预测 16 个编号。

### VQ 与普通 VAE 有什么不同

VAE 使用连续随机变量。相近图片可以落在连续空间中相近的位置。

VQ-VAE 只允许从有限码本中挑一个向量。这样，视频模型面对的是离散分类问题，也得到一种强制压缩。

离散码本会丢信息。小子弹、仪表文字或短暂闪光若没占到合适码字，Decoder 以后无法凭空找回。码本大小、token 网格分辨率与视觉细节之间始终有取舍。

## 4.4 离散选择怎样训练：STE

“选择最近码字”的 `argmin` 不能像普通加法那样求梯度。可是 Decoder 的重建误差还要告诉 Encoder 怎样改。

直通估计器采用一个有意的近似：

```text
前向：使用选中的码字
反向：假装量化步骤是恒等映射
```

代码常写成：

```python
z_st = z_e + (z_q - z_e).detach()
```

前向数值等于 `z_q`；梯度沿 `z_e` 返回。

这不是严格导数，而是一种训练办法。我们还需要 codebook loss 让码字靠近 Encoder 特征，以及 commitment loss 避免 Encoder 特征不断追逐码字。

### 码本坍缩

小数据上常见一种失败：所有位置都选择同一个码字。重建背景占了大部分像素时，这甚至可能让 MSE 看起来不错。

B1 会先用连续 Autoencoder 预热，再从真实 Encoder 特征初始化码本。随后同时报告：

- 重建误差；
- 实际使用了多少码字；
- 每个码字的使用频率；
- 小物体区域是否仍能重建。

只看总 MSE，会错过码本已经失去表达能力的事实。

## 4.5 怎样根据动作预测下一组 token

得到 token 后，最小动态模型是：

```text
当前 frame tokens + action embedding + position embedding
→ Transformer
→ 下一 frame 每个位置的 token 分布
```

位置编码说明每个 token 在画面的哪里。动作 embedding 说明这一步做了什么。

完整 IRIS 一类系统会在更长的 token 历史上进行自回归预测，并将生成的世界用于智能体学习。本书的 B1 先做“一帧到下一帧”，把动作条件和 token 预测单独检查清楚。

### 因果掩码解决什么

当输入包含很多历史 token 时，第 `t` 个预测不能偷看真实的 `t+1`。因果掩码让序列位置只能读取已经发生的部分。

但掩码不能修复数据错位，也不能自动保证模型使用动作。反事实测试仍然必要。

## 4.6 怎样证明模型读懂了动作

第一项检查是固定同一起点，复制成五份，分别输入停、左、右、上、下。

我们可以从弱到强检查：

1. logits 是否改变；
2. argmax token 是否改变；
3. 解码画面是否改变；
4. 物体位移方向是否正确；
5. 连续多步以后，位移是否仍与动作序列一致。

只通过第一项，说明动作进入了网络，却不能说明生成结果已经可控。B2 的 CPU smoke 只做到前两层附近；PA1-B 必须做到第四和第五层。

还要加入一个“去掉动作”的基线。若有动作与无动作的结果几乎相同，数据里的画面惯性可能已经足够预测大部分 token，模型没有学到我们真正关心的控制关系。

## 4.7 为什么一步好，多步仍会坏

训练时，模型每一步读到真实 token。生成时，第二步开始读到自己的预测。

```text
训练：真实帧 → 预测一步
生成：预测帧 → 再预测 → 再预测 → ……
```

一个错误 token 会成为下一步输入。于是小误差沿时间累积，可能出现：

- 角色慢慢变形；
- 背景纹理闪烁；
- 小物体消失；
- 动作几步以后不再生效；
- 模型进入训练数据中没有出现过的画面。

因此要把指标画成 horizon 曲线，而不是只报告 one-step accuracy。实际交互还可以每隔一段时间读入真实观察，重新校正内部状态。

## 4.8 为什么又会出现 Diffusion

离散 token 强制每块图像选择有限码字。它便于自回归预测，却可能损失细节。

Diffusion 选择另一条路。训练时给真实下一帧或 latent 加噪声，让网络根据当前画面、动作和噪声强度预测噪声。生成时从噪声开始，反复去噪。

```text
带噪未来 + 当前帧 + 动作 + 噪声等级
→ Denoiser
→ 预测噪声
```

它容易表达“同一动作可能出现多种视觉结果”，也能保存更多细节。代价是每帧需要多次网络调用，交互延迟更高。

B2 只实现一次噪声预测，帮助读者看清接口。完整 DIAMOND 使用的是经过设计的扩散世界模型；一次去噪 smoke 不能冒充论文复现。

## 4.9 三类数据能教会什么

### PixelWorld

项目内生成，动作和物体位置完全可知。它适合检查时间对齐、反事实与多步漂移，却不能代表复杂视觉。

### CarRacing 小数据

画面与动作更复杂，可检查道路、转向和速度变化。课程会固定环境版本、seed、wrapper、控制频率与 episode split。

### 无动作互联网视频

它可以教模型外观、物体和常见运动，但没有告诉模型“这个控制输入造成什么”。Genie 一类工作尝试从视频中发现潜在动作；这是一项额外学习问题，不等于数据原本含有真实控制标签。

本书不会用无动作视频的结果声称模型已经学会可控动态。

## 4.10 B1、B2 与 PA1-B

B1 完成：

```text
动作—帧对齐
→ Autoencoder 预热
→ VQ-VAE / STE
→ 动作条件 token 预测
```

B2 完成：

```text
反事实动作
→ 自回归多步
→ 连续去噪接口对照
```

PA1-B 再把它们接成可以用键盘控制的小世界。24GB 目标配置为 `64×64`、小码本、短上下文和单卡训练，但当前尚无完整显存实测记录。
