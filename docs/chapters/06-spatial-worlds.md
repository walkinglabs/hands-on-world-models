# 第 6 章　空间世界：相机移动了，世界并没有跟着消失

人在桌子左边看见杯子，走到右边以后，整张视网膜图像都变了。可是杯子仍在桌面同一个位置。

只预测相邻像素，不一定会得到稳定三维结构。空间世界路线先明确相机、坐标和占用，再根据目标选择 3D/4D 场景或自动驾驶未来 Occupancy。

## 6.1 这条路线为什么先有一份共同 Notebook

无论最后选择 NeRF、3DGS、BEV 还是驾驶预测，都要先回答：

- 一个像素对应空间中的哪条射线？
- 深度点处于相机坐标还是世界坐标？
- 两台相机的数据怎样落到同一坐标系？
- 空间哪里被占用，哪里可以通过？

这些问题若算错，模型仍可能让训练 loss 下降，却会把多个视角拼成扭曲世界。

因此 E1 只做几何，不训练大网络。完成后再从 E2a 与 E2b 选择一份。

## 6.2 相机内参：像素怎样变成射线

针孔相机用焦距 `fx, fy` 与主点 `cx, cy` 描述投影。

已知像素 `(u,v)` 的深度 `z`，相机坐标是：

```text
x = (u-cx) × z / fx
y = (v-cy) × z / fy
z = depth
```

一张 RGB 图本身没有直接提供深度。深度可以来自传感器、双目、点云或神经网络预测。预测深度的不确定性会继续传到三维点和 Occupancy。

## 6.3 相机外参：不同视角怎样进入同一世界

外参描述相机在世界中的旋转和平移。

```text
world_point = camera_to_world × camera_point
```

最常见错误不是网络，而是把 `camera_to_world` 与 `world_to_camera` 用反，或混淆左手、右手坐标系。

E1 会故意把相机平移写错 0.3 米，观察所有三维点整体错位。标定误差是一种系统误差，不能只靠增加数据假装不存在。

## 6.4 BEV 与 Occupancy 各回答什么

BEV 是从上往下看的表示。它可以保存道路、物体特征和语义，不一定只有 0/1。

Occupancy 更直接：每个网格或体素说明该处空闲、被占用或未知。

它们适合规划，因为碰撞与可通行性在统一世界坐标中更容易计算。代价是离散网格会损失细节，分辨率越高，内存与计算越大。

## 6.5 LSS 为什么叫 Lift、Splat、Shoot

多相机驾驶数据首先是二维图片。Lift-Splat-Shoot 的直觉是：

1. **Lift：**让每个像素特征沿可能深度升到三维；
2. **Splat：**把三维特征落到统一 BEV 网格；
3. **Shoot：**在 BEV 上完成检测、分割或规划任务。

它不要求每个像素只有一个确定深度，而可预测深度分布。E1 使用已知深度建立几何直觉；PA1-E2b 才实现 tiny LSS 与多相机输入。

## 6.6 分支 E2a：从静态神经场到 4D

NeRF 学习一个连续函数。简化地说：

```text
位置 + 观察方向 → 颜色 + 密度
```

沿相机射线在许多位置查询，再用体渲染合成像素。多视角图片共同约束同一个空间场，因此能从新视角生成画面。

E2a 先用坐标网络拟合彩色球的密度和颜色。这只是 Neural Field 的最小接口，不是完整 NeRF 渲染器。

### 3DGS 与 Mesh

3D Gaussian Splatting 使用许多带位置、尺度、旋转、颜色与透明度的高斯，经过 rasterization 快速渲染。它是显式表示，通常比逐点查询神经场更适合实时显示。

Mesh 用顶点与三角面片表示明确表面，方便编辑、碰撞与接入物理引擎。视觉上很好看的 radiance field 不一定有干净表面；能渲染不等于能可靠碰撞。

### 什么时候才叫 4D 或动作条件世界

静态 `f(x,y,z)` 只表示一个不变场景。加入时间 `f(x,y,z,t)` 才能表示动态。

即使场景会随时间变化，也不一定受智能体控制。若要回答“推这个物体会怎样”，还需要动作或接触条件：

```text
f(x,y,z,t,action/history)
```

因此静态 Lego 重建只能证明 3D 表示，不能称为完整 4D 世界模型。

## 6.7 分支 E2b：自动驾驶为什么预测未来空间

驾驶系统关心的不只是下一帧长什么样，而是未来几秒：

- 哪些区域会被车辆或行人占用；
- 自车计划改变以后，未来是否不同；
- 哪条轨迹可能碰撞或驶出道路。

教学版读取过去三帧 Occupancy 与一个候选动作，预测未来三帧 Occupancy。

```text
past BEV/occupancy + ego action
→ future occupancy logits
```

数据中若没有 ego action 或计划轨迹，模型只能学习“场景通常怎样继续”，不能回答反事实计划。

## 6.8 Occupancy 为什么不能只看 accuracy

大部分网格是空的。一个永远预测空的模型，accuracy 可能很高。

更合适的检查包括：

- occupied IoU；
- 不同未来 horizon 的 IoU；
- 稀有动态物体的召回率；
- 概率校准与未知区域；
- 替换 ego action 后预测是否合理改变。

PA 还应与复制最后一帧和匀速外推比较。

## 6.9 Open-loop 预测与闭环驾驶的区别

离线数据提供固定的未来。模型预测以后，不能改变原数据里的车辆轨迹。

闭环驾驶则是：模型或 Planner 选择动作，模拟器更新自车与其他交通参与者，下一次观察随行动改变。

因此，只有 nuScenes-mini 离线 future prediction 时，我们可以报告 IoU、ADE/FDE 或动作敏感性，不能报告闭环碰撞率。要报告安全行动，必须增加可交互模拟器与控制接口。

## 6.10 E1、E2 与 PA1-E

所有学生先完成 E1：深度反投影、坐标变换与 Occupancy。

随后二选一：

- E2a：最小神经场，随后在 PA 中做 tiny NeRF/3DGS 与动态扩展；
- E2b：动作条件未来 Occupancy，随后在 PA 中做 tiny LSS 与驾驶迁移。

这样 3D 内容创作和自动驾驶共享空间基础，却不用把两套工程全部学完。

## 6.11 读论文时问什么

- [NeRF](https://arxiv.org/abs/2003.08934) 怎样用多视角共同约束连续场？
- [3D Gaussian Splatting](https://repo-sam.inria.fr/fungraph/3d-gaussian-splatting/) 的显式表示为何更适合实时渲染？
- [Lift-Splat-Shoot](https://arxiv.org/abs/2008.05711) 怎样把任意相机阵列统一到 BEV？
- 一种空间表示是否适合渲染、编辑、碰撞和规划，还是只擅长其中一项？
- 从静态重建走向动态、动作条件和闭环，各需要增加什么数据？
