# 6.1　机器人数据与行为克隆

> **第 6 章 · 具身智能与机器人**
>
> 视觉语言模型可以描述桌上的杯子，机器人却需要输出能执行的动作。本章先实现一个能动的动作模型，再加入一个小型世界模型，在执行以前检查候选动作的后果。
>
> 直接 VLA 的输出是动作；世界模型的输出是动作后果。两者可以连接，但不能用同一个名字代替。动作 MSE 下降也不保证闭环成功，本章会一直保留这种诚实差距。
>
> 👉 本章实验：[视觉-语言-动作模型（VLA）](/chapters/06-robot-vla/05-robot-vla)（D1）、[动作后果检查（世界模型检查器）](/chapters/06-robot-vla/05-robot-vla)（D2）；课程作业 [PA1-D：Tiny VLA](/assignments/pa1-d)

图片分类里，一张图只配一个类别。机器人示范要复杂得多：每一步都要记下看到了什么、接到什么指令、关节处在什么状态，以及随后执行了什么动作。

我们先用一台桌面小臂把这件事说清楚。所谓机器人数据，就是把同一时刻的图像、语言、自身状态和动作，按照时间一一对齐。

## 一条机器人 episode 长什么样

小臂抓桌上的杯子。摄像机每秒拍下桌面图片，机械臂每一步报告自己的关节角和夹爪开合，人在旁边给一句“拿起红杯”。把这些连同每一步的动作存下来，就得到一条 **episode**。

记一个 episode 有 $T$ 步动作。那么观察有 $T+1$ 帧（多出一个终点观察），动作只有 $T$ 个。一条 episode 的基本字段是：

```text
images:       [T + 1, C, H, W]
proprio:      [T + 1, P]
instruction:  text 或 token
actions:      [T, A]
success/done: [T]
timestamps:   [T + 1] 和 [T]
```

`proprio` 是机器人自身状态，例如关节角、末端位置和夹爪开合。$A$ 维动作可能是关节增量、末端速度或目标位姿，数据卡必须写清坐标系和单位。

观察和动作之所以差一步，是因为动作 $a_t$ 发生在观察 $o_t$ 和 $o_{t+1}$ 之间。把动作整体错开一格对齐，模型仍可能靠画面惯性猜中下一帧，却永远学不会“换了动作，未来会变”。

## 先只用状态做行为克隆

**行为克隆**（behavior cloning, BC）就是把专家示范当成监督学习。最朴素的版本是：

$$
\text{状态 } s_t \xrightarrow{\;\text{policy}\;} \hat a_t,\qquad \text{目标是模仿专家动作 } a_t.
$$

我们暂时丢掉图像，只用 `proprio` 加指令做一次 state-only BC。这样做的好处是，可以先单独检查动作归一化、时间对齐和控制接口是否正确，再决定要不要加视觉。简单基线能帮我们判断后续的视觉模型是否真的增加了价值。

## BC 的损失函数

预测动作和专家动作都是连续向量，最自然的损失是均方误差。设预测动作为 $\hat a_t$，专家动作为 $a_t$，动作维度为 $A$，一个 batch 里有 $N$ 个样本，则：

$$
\mathcal{L}_{\text{BC}}=\frac{1}{N}\sum_{i=1}^{N}\lVert \hat a_t^{(i)}-a_t^{(i)}\rVert_2^2=\frac{1}{N}\sum_{i=1}^{N}\sum_{d=1}^{A}\bigl(\hat a_{t,d}^{(i)}-a_{t,d}^{(i)}\bigr)^2.
$$

所谓 MSE，就是把每个动作分量的误差平方，再平均。让 $\mathcal{L}_{\text{BC}}$ 下降，意味着模型预测越来越接近专家在那一步会做的动作。

## 为什么动作 MSE 不等于成功

杯子摆在桌中间。同一个目标，小臂可以从左侧绕过去抓，也可以从右侧绕过去抓。两条动作都正确。

可 MSE 不知道这一点。它会算出一条平均路线——正好撞穿杯子。这就是多模态动作带来的麻烦：可行的动作不止一个，把其中一个当标准答案去惩罚另一个，模型就学会了中间那条并不存在的路线。

因此动作误差只能作为辅助指标。真正的主指标是任务成功率、碰撞率和执行稳定性。$\mathcal{L}_{\text{BC}}$ 下降而成功率仍低，说明模型只拟合了单步示范，没有解决闭环问题。

## 分布偏移

训练数据来自专家附近的状态。模型一旦犯小错，就会滑到专家很少访问的区域，后续错误继续积累。这就是所谓的**分布偏移**（distribution shift）。

短 horizon、每步重新规划、加入失败轨或 DAgger 类数据收集，都能缓解它。但在动手阶段，我们先做一件更朴素的事：把失败的 episode 也存下来。看到成功率上不去时，再判断问题来自视觉、动作多模态，还是分布偏移。

## 小结

- [ ] 机器人数据同时包含图像、自身状态、指令、动作和时间，$T+1$ 个观察对 $T$ 个动作。
- [ ] state-only BC 是检查控制接口的最小基线。
- [ ] 动作 MSE 把多条可行路线平均成错误答案，不能替代真实任务成功率。
