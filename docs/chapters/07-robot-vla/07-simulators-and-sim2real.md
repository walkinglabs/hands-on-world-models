# 7.7　模拟器与 Sim-to-Real

同一份抓取策略，在训练用的模拟器里跑出 $0.94$ 的成功率，换一个物理后端评测掉到 $0.71$，搬到真机只剩 $0.38$。三个数字来自同一组权重，差别全在它们脚下的那层物理。

$0.94$ 这个数字本身没有错，错在把它当成对真机的预测。这一节把「仿真通过」到「真机成功」之间的每一道关口拆开。

## 四个栈各自擅长什么

| 栈                  | 物理后端       | 并行方式          | 原生资产   | 最适合                    |
| ------------------- | -------------- | ----------------- | ---------- | ------------------------- |
| Isaac Lab           | PhysX 5（GPU） | GPU 上数千环境    | USD        | 腿式与全身 RL，大批量采样 |
| MuJoCo + MJX        | MuJoCo（XLA）  | JAX `vmap` 批处理 | MJCF       | 接触精度、可微与可复现    |
| ManiSkill3 + SAPIEN | PhysX（GPU）   | GPU 环境 + 批渲染 | URDF/USD   | 操作任务基准，视觉观察    |
| Genesis             | 多物理统一后端 | GPU               | 多格式导入 | 软体与流体，场景批量生成  |

选栈的判据不是"哪个更快"，而是任务的瓶颈在哪。腿式控制吃采样量，需要几千个并行环境；插接吃接触保真度，MuJoCo 的求解器在软接触上通常更可控。选错的代价是训练很顺利、迁移全失败。

## 并行环境与 GPU 物理：吞吐决定可行性

腿式策略常需要 $2\times 10^{9}$ 步环境交互。算一下两种配置：

$$
\text{GPU：}\;4096\times 60=2.46\times 10^{5}\ \text{步/s}\;\Rightarrow\;2.3\ \text{小时},\qquad
\text{CPU 单环境：}\;1.5\times 10^{3}\ \text{步/s}\;\Rightarrow\;15\ \text{天}.
$$

这不是快慢之别，是可做与不可做之别。GPU 物理让腿式 RL 从"实验室级项目"变成"一晚上"。

$24\ \mathrm{GB}$ 显存下要留意观察类型。纯状态观察的环境很便宜，几千个并行没有问题；一旦每个环境都要渲染 $64\times 64$ 的 RGB，显存和带宽都被渲染吃掉，通常只能开到几百个。所以视觉策略的常见做法是先用状态观察训教师，再蒸馏出视觉学生——和 [7.6](/chapters/07-robot-vla/06-legged-and-whole-body) 的教师-学生同一个动机。

## 腿式 RL 的奖励怎么调

CS 123 的 Lab 5 把这件事做成了真机课的核心手艺：在 MJX 上跑数千个 Pupper 并行，PPO 当黑盒用，学生真正动手的是**调奖励函数**。腿式奖励至少有五项，每一项都对应一种失败：

| 项 | 奖励方向 | 调不好会怎样 |
| --- | --- | --- |
| 速度跟踪 | 鼓励跟上指令速度 | 太弱：站着不动；太强：往目标方向猛冲失控 |
| 能耗 | 惩罚用力 | 太弱：动作剧烈；太强：学会省力地原地抖 |
| 稳定性 | 惩罚躯干俯仰角 | 太弱：前仰后翻；太强：不敢加速 |
| 平滑 | 惩罚相邻动作差 | 太弱：抽搐；太强：动作迟钝 |
| 足端接触 | 惩罚非周期着地 | 太弱：乱蹬；太强：单一频率磨一个关节 |

没有一组权重是万能的。做法是固定其余项、扫一项，看步态视频和 reward 曲线。调好后还要加**域随机化**：地面摩擦、质量、电机延迟各随机 $\pm 20\%$–$50\%$，让策略见过足够多的"假机器人"，真机才像其中一种。最后用 wandb 把策略一键部署到真机 Pupper，看 sim2real 差距。

这条流水线（MJX 并行 → 调奖励 → 域随机化 → 一键部署）是腿式 RL 的事实标准。本书 7.12 的全身 sim2real 动手页走的就是它。

最后说清一个概念：**奖励对齐**（reward alignment）。奖励函数只是任务目标的代理，代理和真目标之间永远有缝——策略会找到缝里钻：速度奖励给太高，Pupper 学会原地高频抖腿也算"跟踪上了速度"。这就是 reward hacking，和 [7.4](/chapters/07-robot-vla/04-robot-world-models) 里"Checker 也会被利用"是同一类病：任何可优化的信号都会被优化到失真。对齐的办法不是把奖励调得更复杂，而是让奖励可检查——世界模型预测"这个动作序列之后世界长什么样"，用人能看懂的方式（视频、落脚点图）呈现出来，奖励有没有被骗过，一眼能看见。

## 资产格式：URDF、MJCF 与 USD 的互转损耗

三种格式描述的不是同一件事，互转一定有损失：

- **拓扑**。URDF 只能表达树状结构。四杆连杆、并联机构这类闭链要靠额外的约束声明，MJCF 用 `equality`，USD 用 physics joint，转换时最容易整段丢掉。
- **惯量**。URDF 里 `inertia` 缺失或写错很常见，导入工具会用碰撞体密度估算填上，结果可能差几倍。
- **碰撞几何**。凸分解（V-HACD 一类）的参数不同，同一个网格会得到不同数量的凸块。插接任务对孔口几何极敏感，这一步的差异足以改变成功率。
- **语义不对应**。MuJoCo 的 `armature`（电机转子惯量）在 URDF 里没有字段，丢掉之后关节会显得异常灵敏；阻尼、摩擦损耗、关节限位的刚度在各家的默认值也不同。

转换完成的第一件事不是训练，而是核对总质量、各连杆惯量主轴和自由落体时间。这几个数对不上，后面所有实验都是在另一台机器人上做的。

## 现实差距从哪里来

**现实差距**（reality gap）要拆成可分别诊断的四项，否则只会得到一句"迁移不好"：

| 来源   | 典型表现                 | 最小诊断实验                                 |
| ------ | ------------------------ | -------------------------------------------- |
| 视觉   | 换光照或背景，成功率骤降 | 用真机图像做离线动作预测，比较误差与仿真图像 |
| 动力学 | 轨迹缓慢偏离，误差累积   | 开环回放同一动作序列，比较关节轨迹           |
| 延迟   | 高频振荡、过冲、极限环   | 发阶跃指令，实测从下发到编码器响应的时间     |
| 接触   | 抓取滑落、插接卡死       | 同一动作换求解器或时间步，比较成功率差异     |

四项要分开测。若开环回放的关节轨迹在 $2$ 秒内就偏出 $5^\circ$，问题在动力学，换多少视觉增强都没用。

## 域随机化与系统辨识

**域随机化**（domain randomization, DR）把仿真参数当随机变量，优化其上的期望回报：

$$
\max_\theta\;\mathbb{E}_{\xi\sim p(\xi)}\bigl[J(\pi_\theta;\;\xi)\bigr],\qquad
\xi=(\mu,\;m,\;k_p,\;\tau_{\text{delay}},\ldots).
$$

例如摩擦 $\mu\sim U(0.4,1.2)$、连杆质量 $\pm 20\%$、电机增益 $\pm 25\%$。代价是明确的：区间越宽，策略越保守。典型形状是仿真内成功率随区间变宽单调下降，真机成功率先升后降——因为过宽的区间里包含大量真机永远不会出现的物理，策略为它们付出了保守性。

**系统辨识**（system identification）从另一头收紧：用真机的开环回放数据拟合 $\xi$，把随机化区间围在实测值附近。

$$
\hat\xi=\arg\min_{\xi}\;\sum_{t}\bigl\lVert q_t^{\text{real}}-q_t^{\text{sim}}(\xi)\bigr\rVert_2^2 .
$$

两者是互补的：辨识给中心，随机化给宽度。只做随机化会得到一个平庸而稳健的策略；只做辨识会得到一个对单台机器人过拟合的策略，换一台就失效。

## 延迟建模与动作重复

延迟要逐段实测再相加。一个典型分解是传感 $5\ \mathrm{ms}$、推理 $20\ \mathrm{ms}$、通信 $3\ \mathrm{ms}$、执行器响应 $10\ \mathrm{ms}$，合计 $38\ \mathrm{ms}$。若控制频率是 $200\ \mathrm{Hz}$（周期 $5\ \mathrm{ms}$），机器人执行的是 $7.6$ 步以前算出的动作。仿真里不建模这一项，训出的策略会依赖一个真机不存在的即时反馈。

```python
from collections import deque

class DelayedActionRepeat:
    """在仿真环境外面套一层：动作延迟 d 个控制周期，并重复执行 r 次。"""

    def __init__(self, env, delay_steps: int, action_repeat: int = 1):
        self.env, self.delay, self.repeat = env, delay_steps, action_repeat

    def reset(self):
        obs = self.env.reset()
        self.buffer = deque([self.env.zero_action()] * self.delay,
                            maxlen=self.delay + 1)
        return obs

    def step(self, action):
        self.buffer.append(action)
        applied = self.buffer[0]          # 真正被执行的是 d 步以前的动作
        total_reward, done = 0.0, False
        for _ in range(self.repeat):
            obs, reward, done, info = self.env.step(applied)
            total_reward += reward
            if done:
                break
        return obs, total_reward, done, info

# 38 ms 延迟、200 Hz 控制：delay = ceil(38 / 5) = 8
env = DelayedActionRepeat(base_env, delay_steps=8, action_repeat=1)
```

`action_repeat` 是另一件事：它降低有效决策频率，让策略更平滑，也和 [7.2](/chapters/07-robot-vla/02-imitation-and-policies) 的动作分块同源。两者都用开环片段换稳定性。延迟量本身也应当随机化，因为真机的延迟会抖动。

## 人在回路的样本效率

纯仿真 RL 便宜但不诚实；纯真机 RL 诚实但太贵。**HIL-SERL** 一类方法让人在真机上介入：策略在跑，人随时接管并留下那一段示范，再用这些数据做 off-policy 更新。它改的是**数据从哪来**，不是世界模型的接口。和 7.4 数据引擎的差别是：人给的是真机标签，生成模型给的是合成标签。两者都可以进同一 replay。课程不要求复现 HIL-SERL；若真机选题用了介入，必须在数据卡里写清介入比例和谁在何时接管。

成功判据也不一定由人给。2025 年以来的做法是让视觉语言模型当奖励模型：把 rollout 视频喂给 VLM，问"任务成了吗"，用回答当奖励信号。它省掉了人工标注，但把奖励对齐问题换成了"VLM 的判断可不可信"——所以用 VLM 奖励时，必须抽一部分由人复核，报告一致率。

## 真机评测必须报告什么

$20$ 次试验里成功 $14$ 次，$\hat p=0.70$。正态近似的 $95\%$ 区间是

$$
0.70\pm 1.96\sqrt{\frac{0.70\times 0.30}{20}}=0.70\pm 0.20 .
$$

也就是 $[0.50,\,0.90]$。在 $20$ 次试验下，$0.70$ 和 $0.55$ 根本不可区分。要把半宽压到 $0.05$，需要 $n\approx 323$ 次——真机上这通常意味着几天。这不是可以绕过的统计学，只能诚实地报告 $n$ 和区间。

一份可信的真机报告至少包含：试验次数与置信区间；初始条件的分布（物体位置、光照、干扰的采样方式）；**失败分类**（未抓住、抓住后滑落、碰撞、超时、卡死各占多少）；每类失败的视频；以及权重与随机种子。只报一个成功率均值的结果不构成证据。

## 小结

- [ ] 栈的选择要看任务瓶颈：采样量吃 GPU 并行，接触保真度吃求解器质量。
- [ ] 资产互转会丢闭链、惯量、碰撞几何和 `armature` 这类语义，转换后先核对质量、惯量与自由落体时间。
- [ ] 现实差距要拆成视觉、动力学、延迟、接触四项分别诊断；开环回放是最便宜的第一道检查。
- [ ] 系统辨识给随机化区间定中心，域随机化给宽度；过宽的区间会用保守性换稳健性。
- [ ] 真机结论必须带 $n$、置信区间、失败分类和视频，$20$ 次试验的半宽约 $\pm 0.20$。
- [ ] 人在回路（HIL-SERL）改的是真机数据从哪来；介入比例必须写进数据卡。
