# 7.6　腿式与全身控制

一台人形机器人单脚站立，脚掌 $26\ \mathrm{cm}\times 10\ \mathrm{cm}$，质心高 $0.9\ \mathrm{m}$。它想把手往前伸去拿桌上的杯子，质心前向加速度达到 $1.5\ \mathrm{m/s^2}$。这个数字足以让它前倾摔倒，而机械臂做同样的动作毫无风险。

差别在于机械臂的底座被螺栓固定在桌上，人形机器人的"底座"只是踩在地上的一只脚。腿式与全身控制的所有麻烦都从这一点长出来。

## 没有一个电机连着地面

一台双足机器人有 $23$ 个关节，广义坐标却是 $6+23=29$ 维——多出的 $6$ 维是**浮动基**（floating base）的位置与姿态。驱动器只有 $23$ 个，浮动基的 $6$ 个自由度没有任何电机直接连着。

这就是**欠驱动**（underactuation）。机器人不能任意指定自己质心的加速度，只能通过改变脚底的接触力来间接影响它，而接触力还必须落在摩擦锥和支撑区域之内。机械臂的逆动力学可以给出任意期望加速度对应的力矩，腿式机器人不能。

## 支撑多边形与零力矩点

**支撑多边形**（support polygon）是所有接触点在地面上的凸包。单脚支撑时它就是脚掌那块 $26\ \mathrm{cm}\times 10\ \mathrm{cm}$ 的矩形，前后半长 $13\ \mathrm{cm}$。

**零力矩点**（zero moment point, ZMP）是地面反力合力的作用点。在质心高度近似恒定的线性倒立摆模型下：

$$
x_{\text{zmp}}=x_c-\frac{z_c}{g+\ddot z_c}\,\ddot x_c .
$$

把开头的数字代进去，取 $x_c=0$、$z_c=0.9\ \mathrm{m}$、$\ddot z_c=0$、$\ddot x_c=1.5\ \mathrm{m/s^2}$：

$$
x_{\text{zmp}}=-\frac{0.9}{9.81}\times 1.5=-0.138\ \mathrm{m}.
$$

$13.8\ \mathrm{cm}$ 已经超出 $13\ \mathrm{cm}$ 的脚掌半长。ZMP 落到支撑多边形之外意味着地面无法提供所需的力矩，机器人会绕脚跟转起来。反解可用的加速度上界：$\ddot x_{\max}=g\,x_{\text{edge}}/z_c=9.81\times 0.13/0.9=1.42\ \mathrm{m/s^2}$。

只看当前姿态还不够。**捕获点**（capture point）回答的是另一个问题：如果现在就要停下来，脚该踩在哪里。

$$
x_{\text{cp}}=x_c+\dot x_c\sqrt{\frac{z_c}{g}} .
$$

```python
import numpy as np

G = 9.81
FOOT_HALF = 0.13  # 单脚支撑时前后半长（米）

def zmp(x_c, ddx_c, z_c=0.9, ddz_c=0.0):
    return x_c - z_c / (G + ddz_c) * ddx_c

def capture_point(x_c, dx_c, z_c=0.9):
    return x_c + dx_c * np.sqrt(z_c / G)

for ddx, dx in [(0.5, 0.0), (1.5, 0.0), (0.0, 0.4), (0.0, 0.8)]:
    p, c = zmp(0.0, ddx), capture_point(0.0, dx)
    print(
        f"ddx={ddx:4.1f}  dx={dx:4.1f}  "
        f"zmp={p:+.3f} ({'界内' if abs(p) <= FOOT_HALF else '出界'})  "
        f"cp={c:+.3f} ({'可站住' if abs(c) <= FOOT_HALF else '必须迈步'})"
    )
```

时间常数 $\sqrt{z_c/g}=0.303\ \mathrm{s}$。质心速度 $0.8\ \mathrm{m/s}$ 时捕获点在 $0.242\ \mathrm{m}$ 处，远在脚掌之外——此时"站稳"不是选项，唯一可行的动作是把脚迈到那里去。平衡是一个必须持续消费动作预算的过程。

## 周期性步态与运动先验

行走是准周期的。引入相位变量 $\phi=(t/T)\bmod 1$，步频 $1.6\ \mathrm{Hz}$ 对应周期 $T=0.625\ \mathrm{s}$。把 $\bigl(\sin 2\pi\phi,\cos 2\pi\phi\bigr)$ 喂给策略，它就不必从零学出"什么时候该抬左腿"。

更强的约束是**运动先验**（motion prior）：先从一批参考动作里学一个动作分布 $p(a_{t}\mid s_t)$ 或潜在动作空间，再让 RL 只在这个分布附近搜索。奖励里加一项 $-\log p$ 类的正则，输出就会长得像人走路而不是像抽搐。代价是先验之外的动作被压住了——需要跨越障碍时，机器人可能拒绝做出数据里没有的大跨步。

## 参考动作跟踪与动捕重定向

人体动捕给的是人的骨架轨迹。**重定向**（retargeting）要把它变成机器人的关节轨迹，中间有三层不匹配：

- 尺寸。人的髋宽 $0.32\ \mathrm{m}$，机器人 $0.22\ \mathrm{m}$，线性缩放系数约 $0.69$；缩放后步长变短，速度也跟着变。
- 自由度。人的肩部有三个转动自由度加锁骨的额外活动，机器人常只有三个，某些姿态无解。
- 限位与力矩。人的膝关节可屈到 $150^\circ$，机器人减速器限位可能只有 $120^\circ$，超出部分必须裁剪。

裁剪之后的轨迹不再保证动力学可行——脚可能穿地，质心轨迹可能违反 ZMP 约束。所以重定向的结果只能当作**参考**，跟踪奖励要和平衡奖励一起优化，而不是硬性回放。

## 上下身解耦与移动操作

**移动操作**（mobile manipulation）的常见工程做法是分工：下身策略跟随速度指令 $(v_x,v_y,\omega_z)$，上身控制器跟随末端位姿。两者的耦合被当作扰动处理。

耦合项是可以算的。上身伸出 $0.5\ \mathrm{m}$ 拿一个 $2\ \mathrm{kg}$ 的物体，对基座产生的俯仰力矩是 $2\times 9.81\times 0.5=9.8\ \mathrm{N\cdot m}$。这个力矩要靠下身重新分配脚底压力来抵消。解耦能不能成立，取决于下身策略在训练时见过多大范围的上身扰动。所以训练下身时应当主动注入随机的基座力矩和负载变化，而不是等到装上手臂再说。

更激进的做法是**边走边抓**（loco-manipulation）：不把上下身拆开，让一个策略同时管腿和手。HIMLoco 让四足在走动中用"嘴"叼起地上的物体，AGILE 让人形在站立时伸手取物。它们的共同点是训练时把基座运动和手臂运动放在同一个回报里联合优化，而不是先训走路再加手。世界模型在这里预测的是"伸出手的瞬间，脚会不会打滑"——一个跨上下身的接触后果。

## 特权教师-学生蒸馏

仿真里可以随手读到地形高度图、每个足端的摩擦系数、外部推力和精确接触状态。真机上这些量全都没有——机器人只有 IMU、关节编码器和一段历史。

直接用可部署观察做 RL 很难：地形信息要从关节历史里反推，探索和信用分配同时变难，样本量会涨一个数量级以上。**特权教师-学生蒸馏**（teacher-student distillation）把问题拆成两步：

$$
\underbrace{\pi^{T}(a\mid s_t,\;\xi_t)}_{\text{特权观察，用 RL 训}}\;\longrightarrow\;\underbrace{\pi^{S}(a\mid o_{t-H:t})}_{\text{可部署观察，用监督学习训}}
$$

其中 $\xi_t$ 是特权信息。第一步用完整状态把控制问题解干净，第二步只需要在教师访问过的状态上做回归。学生的数据必须由学生自己 rollout 再由教师标注（DAgger 式在线蒸馏），否则学生一旦偏离教师轨迹就没有监督——这正是 [7.2](/chapters/07-robot-vla/02-imitation-and-policies) 那个复合误差问题。

它成为标准做法不是因为优雅，而是因为可部署观察下的 RL 在预算内经常训不出来。代价也要写清：学生的性能上限被教师锁住，而且教师依赖的特权量若在真机上根本不成立（例如仿真的刚性接触），学生会忠实地继承这个错误。

## 世界模型提供地形与接触预测

腿式控制里的世界模型有一个很具体的位置：预测**下一次落脚的后果**。给定候选落脚点，预测该处的高度差、法向方向和滑移概率。

$$
\bigl(\hat h,\;\hat n,\;\hat p_{\text{slip}}\bigr)=f_\theta\bigl(o_{t-H:t},\;p_{\text{foot}}^{\text{cand}}\bigr).
$$

这比预测整幅未来图像有用得多：高度差算错 $3\ \mathrm{cm}$ 就是一次踏空，而图像 PSNR 高几分不改变任何落脚决策。世界模型在这里的价值来自它被下游消费的方式，不来自重建质量。

## 室内导航是另一类身体

Malik 课把 locomotion、navigation、dexterous manipulation 分成三个案例。导航的状态常常是位姿 + 占用或拓扑图，动作是速度命令，失败是撞上和迷路。世界模型预测的是未来占用或可通行性，接口更接近第 8 章而不是本节的 ZMP。若选题是室内走去杯子，先声明消费的是落脚预测还是 BEV 占用，不要混在一张成功率表里。

具身导航（embodied navigation）有自己的评测体系，和操作不是同一张表。Habitat 把机器人在三维场景里找目标点做成基准，ETPNav 处理语音指令导航（VLN：vision-language navigation，"走到厨房拿杯水"这类）。它们的成功判据是**到达率**和**导航误差**，不是抓取成功率。世界模型在导航里预测的是"沿这条走廊走三步后，前方还通不通"——一个可通行性的多步 rollout，和 7.4 的想象 rollout 同构，只是状态从机械臂变成占用网格。

本书不把导航单列一章，因为它的世界模型接口已经在第 8 章的占用预测里讲清楚了。选题碰到导航时，引用 8.2 的占用网格作为状态表示，引用本节的 ZMP 作为下身控制，两者在"速度命令"这个接口上对接。

导航还牵出一个本书其他地方没有的问题：**主动感知**（active perception）。机械臂的相机是固定的，导航机器人的相机长在自己身上——看不见拐角后面，就绕过去看一眼。"下一步往哪看"本身就是一个动作选择问题，而回答它恰好需要世界模型：预测"如果我绕到左侧，占用网格里哪块不确定性会消掉"。NBS（next-best-view）类方法选的是信息量最大的下一个观察位置。主动感知把"感知"和"规划"焊在一起，这是它和 7.5 那个固定相机抓取的根本区别。

## 小结

- [ ] 浮动基的 $6$ 个自由度没有电机，欠驱动让期望质心加速度不能被直接指定。
- [ ] ZMP 出界意味着地面无法提供所需力矩；捕获点告诉你现在能不能站住，$0.8\ \mathrm{m/s}$ 时唯一可行动作是迈步。
- [ ] 动捕重定向要跨尺寸、自由度和限位三层不匹配，结果只能当参考轨迹，不能硬性回放。
- [ ] 教师-学生蒸馏成为标准做法，是因为可部署观察下的 RL 在预算内难以收敛；代价是学生继承教师的上限与错误假设。
- [ ] 室内导航消费的是占用与可通行性，和落脚预测不是同一张表。
