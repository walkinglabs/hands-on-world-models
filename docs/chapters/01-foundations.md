# 第 1 章　怎样表示世界，并从经历中学出模型

第 0 章的九格世界只有九个状态。我们可以直接用 `(行, 列)` 表示位置，再用一张表写出每个动作的结果。

现在把格子换成一张 `64×64` 的彩色图片。一张图包含 12288 个数。若再加入最近 30 帧、相机位置、机器人动作和奖励，直接建表就不再可行。

这一章把共同基础放在一起。我们先研究一段真实数据从传感器进入以后，要经过哪些地方，才能变成可以推演和选择的内部状态；然后把观察、动作和结果按时间接好，从连续经历中学出第一台小世界。

```text
图片、点云、语言和机器人状态
→ 看出画面与空间中的内容
→ 压成较短的内部状态
→ 用历史更新状态
→ 根据动作推测下一状态
→ 评价未来
→ 选择动作
```

我们先让每个组件只回答四件事：输入是什么，输出是什么，为什么需要，在哪条路线会完整实现。接着再把这些组件放回数据与训练循环。基础阶段要建立一张可使用的地图，不是背完一部缩写词典。

## 1.1 怎样把现实放进模型里

### 先把 shape 读对

PixelWorld 中有一块红色方块。每张图片的高和宽都是 16，颜色有红、绿、蓝三个通道。

```text
一张图片：[H, W, C] = [16, 16, 3]
一段视频：[T, H, W, C] = [19, 16, 16, 3]
一批视频：[B, T, H, W, C]
```

这里的张量（Tensor），可以先理解为装着许多数字的多维盒子。shape 说明每一维的含义。

`B` 表示 batch，也就是并排计算多少份样本。`T` 表示时间。`H` 和 `W` 是图片高宽，`C` 是颜色通道。

这些字母不能只看大小。一个 shape 为 `[32, 10, 5]` 的数组，可能表示 32 段轨迹、每段 10 步、每步 5 个状态量；也可能表示别的东西。数据卡必须同时写出每一维的语义。

#### 为什么时间维最容易出错

假设一段经历有四张图片：

```text
o0 --a0--> o1 --a1--> o2 --a2--> o3
```

它有 4 个观察，却只有 3 个动作。`a0` 发生在 `o0` 与 `o1` 之间，而不是“属于”某一张图。

所以，一段 episode 的基本 shape 是：

```text
observations: [T + 1, ...]
actions:      [T, ...]
rewards:      [T]
dones:        [T]
```

若把动作整体错开一格，模型仍然可能让 loss 下降，却会学到错误的动作后果。本章后半部分会专门检查这一点。

### 图片太大：先找出有用的局部形状

红方块向右移动了一格。我们希望从图片中找到它的位置。

最直接的方法是逐像素检查红色通道。这对颜色固定的小环境有效。若光照改变，方块出现纹理，或者要识别杯把和轮子，手写规则会迅速变长。

我们需要一台可以从数据中学习局部形状的工具。

#### CNN：同一个小窗口到处检查

卷积神经网络（CNN）的核心操作，是让一个小窗口在图片上滑动。窗口每到一个位置，就计算这里是否像某种局部形状。

先看一个 `5×5` 的灰度图。左半边是 0，右半边是 1。下面的 `3×3` 小窗口会对右边给正权重、左边给负权重：

```text
-1  0  1
-1  0  1
-1  0  1
```

窗口跨过明暗边界时，结果会很大。它由此成为一个竖直边缘探测器。

CNN 不只使用这一个窗口。训练会学出许多 kernel，浅层寻找边缘和纹理，深层再把局部结果组合成较大的形状。

```text
输入：[B, C, H, W]
输出：[B, C', H', W']
```

在 Dreamer 中，CNN 常把图片压成视觉特征。在机器人路线中，它也可以成为观察编码器。

CNN 的长处是局部结构明确、参数复用、在小图片上计算便宜。它暂时没有直接回答远处两个区域怎样关联，也没有保存过去。

#### ViT：把图片变成一串 patch

另一种办法是把图片切成许多小块。每块展平成一个向量，就得到一串视觉 token。

一张 `16×16×3` 图片使用 `4×4` patch 时，会得到：

```text
4 × 4 = 16 个 patch
每个 patch 有 4 × 4 × 3 = 48 个数
tokens.shape = [16, 48]
```

视觉 Transformer（ViT）让这些 patch 互相交换信息。左上角的方块可以直接关注右下角的目标，不必只靠一层层局部卷积传递。

但是，切成一串以后，模型并不知道第一个 token 在左上，还是在右下。于是还要加入位置编码，把空间位置写进 token。

```text
patch 内容 + patch 位置 → 带空间信息的 token
```

JEPA 会遮住一部分 patch，让模型预测被遮区域的特征。VLA 会把视觉 token 与语言 token 放在一起。因此，ViT 会在这两条路线中再次深入。

CNN 与 ViT 不是必须二选一的阵营。小图片、局部模式明显时，CNN 往往更省算力；需要遮挡预测、长距离关系或语言融合时，token 接口更方便。

### 一张图不够：把过去带到现在

现在让两个红方块都出现在画面中央。第一段视频中，它从左边来到中央；第二段视频中，它从右边来到中央。

最后一帧完全相同，下一步方向却不同。只编码当前帧无法区分它们。

一个最小记忆可以直接保存最近两个位置：

```text
当前位置 - 上一位置 = 速度线索
```

实际环境还可能有遮挡、延迟和更长依赖。于是需要可以不断更新的内部状态。

#### RNN 与 GRU：每一步更新一份记忆

循环神经网络（RNN）的接口很简单：

```text
h_t = update(h_{t-1}, x_t)
```

`x_t` 是当前观察特征，`h_{t-1}` 是上一时刻记忆，`h_t` 是更新后的记忆。

普通 RNN 在很长序列中容易忘掉早期信息。GRU 加入门控，让模型学习哪些旧信息保留、哪些新信息写入。

GRU 仍然没有自动成为世界模型。若它只读观察，它只是记忆器。要预测动作后果，还要把动作放进状态转移。

#### 因果 Transformer：过去可以互相查看，未来不能偷看

Transformer 可以一次处理整段 token。训练下一步预测时，要加入因果遮罩：第 `t` 步只能查看 `0...t`，不能偷看 `t+1` 的答案。

```text
第 0 步：看 0
第 1 步：看 0, 1
第 2 步：看 0, 1, 2
```

互动视频路线会把历史图像 token 和动作 token 排成序列，再逐步生成未来。推理时，KV Cache 保存已经算过的历史，避免每生成一步都从头计算。

#### RSSM：长期记忆旁边，再留一份随机状态

假设两辆外观相同的小车进入隧道。摄像头暂时看不见它们。历史记忆可以估计大致位置，但真实位置仍有多种可能。

只保存一个确定向量，容易把多种可能压成平均结果。RSSM 把状态分成两部分：

```text
确定状态 h_t：由 GRU 更新，保存长期线索
随机状态 z_t：描述当前仍不确定的部分
```

训练时，模型用当前观察推断 `z_t`；想象未来时，只根据过去状态和动作预测 `z_t` 的分布。

RSSM 是 Dreamer 的核心组件。共同基础只需要看懂这两个接口，第 2 章再完整实现 prior、posterior、KL、重建与 reward heads。

### 世界太大：压缩什么，丢掉什么

一张 `64×64×3` 图片有 12288 个数。直接连续预测像素，计算量大，模型也容易把精力花在不重要的纹理上。

最简单的压缩方法，是把每个 `4×4` 区域取平均。一张 `16×16×3` 图片会变成 `4×4×3`，数字量缩小 16 倍。

解码时，把每个平均值重复扩回 `4×4`。方块仍大致存在，清楚边缘却消失了。

这已经暴露所有表示学习都会面对的取舍：压得越短，计算越便宜；丢掉的信息也可能越多。

#### AE 与 VAE：连续 latent

自动编码器（AE）由 Encoder 与 Decoder 组成：

```text
图片 → Encoder → latent → Decoder → 重建图片
```

若只要求重建，模型可能把每张图映到凌乱的 latent。变分自动编码器（VAE）让 latent 靠近一个简单概率分布，从而更容易采样和插值。

VAE 的随机性也可以表达不确定性，但“用于压缩图片的随机 latent”和“用于动态不确定性的随机状态”需要根据接口区分，不能只看名字。

#### VQ-VAE：把画面变成离散编号

VQ-VAE 准备一张有限码本。Encoder 输出连续向量后，选择最接近的码本项，用一个整数编号代替它。

```text
局部图像 → 连续向量 → 最近码本项 → token id
```

这样，一帧图片变成一串离散 token，容易交给 Transformer 自回归预测。

“选择最近编号”本来没有平滑梯度。直通估计器（STE）在前向使用离散结果，在反向把梯度近似传回 Encoder。它解决的是训练接口问题，不是新的生成模型。

#### Diffusion：同一历史可以生成多种未来

湿滑路面上急刹，车辆可能稳定减速，也可能打滑。若模型只回归一个像素平均值，画面会变模糊，也没有表达两种完整结果。

扩散模型从噪声开始，经过几步去噪得到一个具体样本。改变随机噪声，就可以从同一条件采样多个未来。

它通常比一次前向生成更慢，却更善于保留丰富细节和多模态结果。互动视频路线会在同一 PixelWorld 数据上，把离散 token 自回归与 tiny diffusion 做小对照。

#### JEPA：也许根本不需要还原所有像素

如果任务只关心方块位置和运动，重建背景纹理可能是额外负担。JEPA 直接预测目标 Encoder 的 feature，而不是每个像素。

这种做法计算目标变了：它主动放弃一部分可见细节，希望保留更稳定的信息。

问题随之转移到“哪些 feature 才有用”。第 4 章会用 linear probe、动作敏感性和下游规划检查，而不是只看 feature loss。

## 1.2 怎样让内部状态服务于空间与行动

### 二维图片不等于三维空间

摄像头向右移动时，图片中的所有物体都会向左移动。若只看像素变化，模型可能误以为整个房间都动了。

我们需要知道光线从哪台相机、哪个像素出发，以及它在三维空间中遇到了什么。

#### 相机内参与外参

内参描述相机怎样把三维点投到图片上，例如焦距和成像中心。

外参描述相机在世界中的位置和朝向。

若深度图告诉我们一个像素离相机 2 米，就可以用针孔相机公式把它反投影成三维点：

```text
x = (u - cx) * z / fx
y = (v - cy) * z / fy
```

同一个杯子从两台相机看起来位置不同，变换到世界坐标以后应该落到相近位置。这是跨视角一致性的第一项检查。

#### Point Cloud、BEV 与 Occupancy

许多反投影点组成点云（Point Cloud）。点云保留了测到的表面，却不直接说明没有点的地方是空的、未知的，还是被遮挡了。

鸟瞰图（BEV）从上往下整理道路和物体，适合驾驶规划。占用网格（Occupancy）把空间切成小格，记录哪里被占用、哪里可通行、哪里未知。

它们更关心结构和碰撞，不一定能生成漂亮新视角。

#### NeRF、3DGS 与 Mesh

NeRF 用神经函数表示空间位置和观看方向对应的颜色与密度，适合高质量新视角合成。

3D Gaussian Splatting（3DGS）用许多显式高斯粒子表示场景，渲染通常更快。

Mesh 用三角面片保存表面，容易编辑，也容易接入碰撞和物理引擎。

这些表示保留的信息不同。能渲染新视角，不自动等于知道哪里可以抓、哪里会碰撞。第 6 章会根据使用者选择表示，不把所有 3D 方法塞进同一个排行榜。

### 能预测以后，怎样评价和选择

世界模型产生未来。若任务没有目标，它无法替我们判断哪种未来更好。

奖励（reward）描述一步结果。回报（return）描述整条未来的累计结果。价值（value）估计从某个状态继续行动，未来大约还能得到多少。

#### Policy、Actor 与 Critic

Policy 从当前信息直接输出动作。连续动作任务中，Policy 常输出一个概率分布，再从中采样。

Actor 是负责行动的 Policy。Critic 估计 Actor 当前选择的未来价值。两者一起训练，就得到 Actor-Critic。

Actor-Critic 可以完全不使用世界模型。Dreamer 的不同之处，是它在世界模型生成的想象轨迹中训练 Actor 和 Critic。

#### MPC：想几步，只走一步

模型预测控制（MPC）从当前状态预测多步，选择一条动作序列，只执行第一步，再读取真实观察重新规划。

它适合模型不完全准确的情况，因为每一步都有机会修正状态。

#### CEM：不再枚举所有连续动作

连续动作无法像九格世界那样全部列出。交叉熵方法（CEM）先随机采样许多动作序列，保留其中较好的部分，再围绕这些序列重新采样。

```text
宽泛采样 → 保留前若干名 → 缩小分布 → 再采样
```

PlaNet 使用 CEM 在 latent dynamics 中现场规划。CEM 的结果不会自动变成一个快速策略。

#### MCTS：把有希望的分支展开得更深

蒙特卡洛树搜索（MCTS）把动作看成树的边。它不平均搜索所有分支，而是反复在探索新分支与利用高价值分支之间选择。

MuZero 学习 reward、policy 和 value，再让 MCTS 在隐空间搜索。它不要求重建观察。第 2 章把它作为 Dreamer 的选修对照，而不是另一条必修主线。

### 代码能跑，模型为什么仍会学坏

世界模型同时训练表示、动态、重建、奖励和策略，数值范围也可能差很多。几个工程工具会在后续路线反复出现。

Replay Buffer 保存历史 episode，让模型重复采样连续序列。它不能跨 episode 拼接，否则终止后的下一帧会来自另一个世界。

EMA 让目标网络缓慢跟随在线网络，避免学习目标每一步同时剧烈移动。JEPA 会用它稳定 target encoder。

Free Bits 给 KL 留出一小段免费区间，防止 VAE/RSSM 为了降低 KL，完全不使用随机 latent。

Symlog 把很大的正负数压到较小范围：

```text
symlog(x) = sign(x) * log(|x| + 1)
```

DreamerV3 用它处理从很小到很大的奖励与价值。`symexp` 可以把结果映回原尺度。

Gradient Clipping 在梯度过大时按比例缩小它，防止一次异常更新破坏训练。它能控制数值，却不能修复错误数据或错误目标。

Twohot、Unimix、KV Cache 等工具也会在真正需要的路线出现。基础阶段不逐项开实验，避免工程名词遮住主要问题。

### F1 与 F2 怎样安排

这一章只有两份 Notebook。

#### F1：`see-remember-compress.ipynb`

我们用同一段 PixelWorld 方块视频完成：

```text
读 shape
→ 从零卷积找边缘
→ patchify 变成 ViT token
→ 比较相同末帧的两段历史
→ 用位置差留下速度
→ 压缩图片并观察细节损失
```

F1 的目标是看清视觉、记忆和压缩的接口。它不训练大型 CNN、ViT 或 VAE。

#### F2：`space-plan-train.ipynb`

我们从一张小深度图开始：

```text
像素 + 深度
→ 三维点
→ 俯视 Occupancy
→ 在一维世界用 CEM 搜索动作
→ 用 Symlog 和梯度裁剪观察训练数值
```

F2 把空间、规划和稳定训练放在一起，是因为它们都回答“内部状态怎样被后续系统使用”。真正的 NeRF、LSS、Actor-Critic 和 Dreamer 稳定技巧留到路线章节。

### 选择组件时先问接口

面对一个新模型，先不要问“它用了哪种最先进的 Backbone”。先画出四个量：

```text
模型读入什么？
模型输出什么？
谁会使用输出？
哪些信息有意不保留？
```

若输出是可观看的下一帧，像素细节很重要。若输出只供 Planner 比较动作，保留奖励、碰撞与可控变化可能更重要。若输出是机器人动作，动作可执行性和延迟比重建画面更直接。

同一个组件在不同系统里也可能承担不同职责。Transformer 可以做视频 token dynamics，可以融合 VLA 的图像与语言，也可以成为 JEPA Predictor。名字相同，不代表学习目标相同。

### 到这里，我们已经有了哪些工具

- [ ] Tensor 的 shape 必须同时写清每一维的语义。
- [ ] CNN 在图片上复用局部窗口，ViT 把图片切成带位置的 patch token。
- [ ] RNN/GRU 保存历史，因果 Transformer 处理过去 token，RSSM 再表达动态不确定性。
- [ ] AE/VAE 使用连续 latent，VQ-VAE 使用离散码本，Diffusion 用多步去噪采样多种未来。
- [ ] Point Cloud、BEV、Occupancy、NeRF、3DGS 与 Mesh 保留不同空间信息。
- [ ] Policy 直接行动，Planner 比较候选未来，MPC、CEM 与 MCTS 是不同规划办法。
- [ ] 稳定训练工具只能修复对应的数值或优化问题，不能代替正确数据和任务设计。

接下来不再逐个看零件。我们把观察、动作、奖励和下一观察按时间接好，从连续经历中学出第一台小世界。

## 1.3 从连续经历中学出第一台小世界

第 0 章的 `next_state` 由我们编写。前两节又认识了图片、记忆、压缩、空间和规划组件。

现在拿走移动规则。机器只得到自己曾经经历过的记录。它要从这些记录中发现：在某种情况下做出某个动作，接下来通常会发生什么。

这一节完成课程第一次“数据—模型—规划—现实检查”闭环。

### 一张图片不构成经历

我们先准备三张红方块图片。若把它们打乱后放进一个文件夹，模型能学会方块长什么样，却不知道方块为何从左边来到右边。

世界模型需要连续顺序和动作：

```text
o0 --a0--> o1 --a1--> o2
```

一条 transition 保存一次变化：

```text
observation o_t
action a_t
reward r_t
next_observation o_{t+1}
done d_t
```

`done` 表示这一步以后任务是否结束。任务结束后的下一张图，不应继续接到另一个 episode 的起点。

许多连续 transition 组成一段 episode。许多 episode 才组成世界模型的训练数据。

#### 动作到底放在哪两帧之间

PixelWorld 中，方块起始位置为 `(2, 2)`。动作 `right` 执行以后，位置变成 `(2, 3)`。

正确记录是：

```text
frame[0] + action[0]=right → frame[1]
```

若把动作整体向后错一格，训练样本会变成：

```text
frame[0] + action[1] → frame[1]
```

模型看到的动作不再是造成这次变化的动作。若数据中大多数时候都继续向同一方向，错误对齐仍可能得到不差的一步 loss。一旦我们做反事实测试，换动作却不换历史，问题才会暴露。

因此，每个动作数据集都要记录：

- action 的时间戳；
- 控制频率；
- 观察频率；
- 控制命令到物体真正响应的延迟；
- wrapper 是否重复动作或跳帧。

动作条件世界模型首先是一项数据问题，然后才是网络问题。

### Episode、Replay Buffer 与数据切分

课程的 `Episode` 容器使用下面四组数组：

```python
Episode(
    observations=[T + 1, H, W, C],
    actions=[T],
    rewards=[T],
    dones=[T],
)
```

`validate()` 会检查：

1. `T+1` 个观察是否对应 `T` 个动作；
2. reward 和 done 是否与动作同长；
3. episode 是否在中间已经结束，却仍继续保存后续步骤。

这些检查看起来简单，却比训练结束后再猜“为什么换动作没反应”便宜得多。

#### 不同长度怎样组成 batch

真实 episode 长度不同。常见做法有两种。

第一，从每段 episode 内采样固定长度片段。例如，从 100 步中随机取连续 16 步。Dreamer 的 Replay Buffer 常使用这种方式。

第二，把短序列补到同样长度，并用 mask 标出哪些位置是真实数据。计算 loss 时只使用 mask 为 1 的位置。

本课程优先使用固定长度片段。它更容易检查，也不会让初学者同时处理 padding 与 dynamics。

#### Replay Buffer 为什么不能跨 episode

假设 episode A 在终点结束，episode B 从另一个随机位置开始。若直接把两个数组拼在一起，再按索引截取，可能得到：

```text
A 的最后观察 --不存在的动作--> B 的第一观察
```

模型会把一次环境重置当成正常动态。

课程的 Replay Buffer 先选择一段足够长的 episode，再从这一段内部选择起点。每个样本还保留 `episode_id` 和 `start`，方便追查来源。

```text
先选 episode
→ 再选连续起点
→ 截取 T+1 个观察与 T 个动作
```

这条规则同样适用于视频、机器人和驾驶数据。若任务有 scene、司机、地图或数据库模板，还要让相同 group 保持在同一 split 中。

#### 为什么不能随机拆帧

一段视频中的相邻帧几乎相同。若把每张帧随机分到 train 与 test，测试集中常会出现训练帧的近邻。

模型只需记住背景和物体位置，就能得到很好的一步结果。这样的测试没有说明模型能进入新 episode、新场景或新动作区域。

正确做法是按 episode 切分：

```text
train：一组完整 episode
val：另一组完整 episode
test：从未进入训练的完整 episode
```

更复杂数据还要按 scene、object、task template 或 environment seed 分组。切分边界必须在数据卡中说明。

### 从计数开始学习转移

神经网络不是学习世界模型的必要起点。我们先回到 LineWorld：机器人在一条直线上，可以向左或向右。

环境带有 20% 打滑。我们观察到：

```text
位置 2 + right → 位置 3，共 8 次
位置 2 + right → 位置 2，共 2 次
```

最简单的 learned dynamics 是计数表：

```text
P(3 | 2, right) = 0.8
P(2 | 2, right) = 0.2
```

这台模型没有梯度，也没有 GPU。它已经满足三个重要要求：从数据学习、结果依赖动作、未来可以有多种可能。

#### 未见状态不能伪装成确定答案

若数据从未出现“位置 4 + right”，计数表会返回空分布。

空分布不能直接用于行动，却诚实说明这里没有证据。神经网络通常会对任何输入输出一个结果，因此后续需要距离、ensemble、校准或其他 OOD 方法，判断模型是否离开训练分布。

基础阶段先保留一个简单规则：未知状态—动作不允许被当作高把握捷径。

### 一步准确为什么仍不够

假设模型预测每一步有 95% 概率正确。连续 20 步都正确的概率是：

```text
0.95 ^ 20 ≈ 0.36
```

这不是说每个世界模型都能用独立概率这样计算，而是说明小的一步错误在长序列中会迅速积累。

所以数据与模型至少要报告两组结果：

- one-step：每次都从真实状态预测下一步；
- open-loop rollout：只在起点使用真实状态，之后把模型输出继续送回模型。

第一项检查局部动态，第二项检查模型能否承受自己的预测。

若只报告一步指标，我们不知道模型从第几步开始进入假世界。

#### 反事实测试要固定同一个世界

我们想知道模型是否理解动作。不能从数据集中随便找两段“看起来相似”的视频，一段向左、一段向右，然后比较它们。

两段视频的物体、速度、摩擦和随机事件可能都不同。

更严格的反事实测试是：

```text
固定同一初始状态
固定物体、地图、摩擦和随机种子
只把 action=left 换成 action=right
比较未来是否按规则改变
```

若环境本身随机，可以为每个动作运行多次，比较结果分布，而不是要求两条轨迹逐像素相同。

PixelWorld 可以完全控制这些变量，所以它是后续路线共同使用的第一层数据。

### 把学到的模型交给 MPC

计数模型可以给出每个动作最可能的下一状态，也可以保留完整分布。

我们先使用最可能结果做短期 rollout。规划器枚举几步动作，选择预测回报较高的路线，只在真实环境执行第一步。

```text
真实状态 s_t
→ learned dynamics 中展开候选动作
→ 选择第一动作 a_t
→ 真实环境执行
→ 得到 s_{t+1}
→ 再规划
```

每次执行后，我们把新的 transition 放回 Replay Buffer，更新计数表。模型由此接触到规划器真正访问的区域。

这条循环就是 PA0 的核心。第 2 章会把表格替换成 RSSM，把枚举替换成 CEM 或 Actor，但数据与闭环接口保持相似。

### 模型错误来自哪里

规划失败时，不要立即换更大网络。先把问题分成四类。

#### 数据错误

动作错位、跨 episode、训练测试泄漏、控制延迟未记录。此时更大模型只会更好地拟合错误关系。

#### 任务不可判定

两段历史完全相同，未来却由未记录的摩擦或隐藏对象决定。此时模型需要新观察、历史或概率输出，而不是单一确定答案。

#### 模型能力不足

数据包含规律，简单计数或当前帧模型却无法表示。此时才考虑记忆、latent、Transformer 或 3D 结构。

#### 规划使用不当

模型只在短 horizon 可靠，规划器却向前搜索很久；或者规划器反复进入训练数据之外。此时需要缩短 horizon、加入不确定性惩罚、收集新数据或使用独立安全约束。

诊断顺序很重要。世界模型系统中的失败，不一定来自 world model 网络本身。

### F3：学习表格小世界

`F3-learn-a-table-world.ipynb` 完成下面一条连续路径：

1. 生成带打滑的 LineWorld episode；
2. 检查 observation、action、reward、done 的时间对齐；
3. 按 episode 切分数据；
4. 从 Replay Buffer 采样连续片段；
5. 用计数学习概率 dynamics；
6. 检查未见状态与多步误差；
7. 固定起点，只替换动作做反事实；
8. 用 MPC 在真实环境走一步、修正一次。

它仍只使用 CPU。这样，PA0 的困难集中在系统接口，而不是调 GPU。

### PA0：重新发明一台可学习世界模型

PA0 提供一个新的小地图和轨迹生成接口，不提供完整模型结构。学生需要自己决定：

- 什么是状态，什么是观察；
- 动作如何编码；
- 一条训练样本包含哪些字段；
- 模型输出一个结果还是结果分布；
- Planner 怎样调用模型；
- 哪个测试能够证明模型真的使用动作。

必交产物只有一份 Notebook，但包含七项证据：

1. 输入输出接口图；
2. 数据卡与 episode 切分；
3. 复制上一状态或规则等简单基线；
4. one-step 与 multi-step 曲线；
5. 同一起点替换动作的反事实表；
6. 使用模型前后的任务成功率；
7. 一组稳定失败与下一步需求说明。

PA0 不要求神经网络。若表格方法已经解决任务，继续堆网络不会加分。

#### 怎样从 PA0 选择路线

PA0 结束以后，先从失败记录中选择最想解决的一项。

若真实试错太贵，希望在 latent 中练策略，进入第 2 章。

若最希望直接看见动作后的画面，进入第 3 章。

若像素重建耗费太多，只想保留任务信息，进入第 4 章。

若要把图像和文字变成机器人动作，并检查动作后果，进入第 5 章。

若主要问题来自视角、遮挡和三维空间，进入第 6 章。

选择前写下四句话：

```text
我希望模型输出什么？
谁会使用这个结果？
哪些信息必须保留？
哪些信息可以暂时不预测？
```

如果这四句话还说不清，先不要按论文名选方向。
