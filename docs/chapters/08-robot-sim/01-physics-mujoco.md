# 8.1　物理引擎与接触力模拟（MuJoCo）

同一份抓取策略，在训练用的模拟器里跑出 $0.94$ 的成功率，换一个物理后端评测掉到 $0.71$，搬到真机只剩 $0.38$。三个数字来自同一组权重，差别全在它们脚下的那层物理。

$0.94$ 这个数字本身没有错，错在把它当成对真机的预测。这一节先拆解第一道关口：我们依赖的物理引擎和仿真器到底在算什么。

## 四个栈各自擅长什么

| 栈                  | 物理后端       | 并行方式          | 原生资产   | 最适合                    |
| ------------------- | -------------- | ----------------- | ---------- | ------------------------- |
| Isaac Lab           | PhysX 5（GPU） | GPU 上数千环境    | USD        | 腿式与全身 RL，大批量采样 |
| MuJoCo + MJX        | MuJoCo（XLA）  | JAX `vmap` 批处理 | MJCF       | 接触精度、可微与可复现    |
| ManiSkill3 + SAPIEN | PhysX（GPU）   | GPU 环境 + 批渲染 | URDF/USD   | 操作任务基准，视觉观察    |
| Genesis             | 多物理统一后端 | GPU               | 多格式导入 | 软体与流体，场景批量生成  |

选栈的判据不是"哪个更快"，而是任务的瓶颈在哪。腿式控制吃采样量，需要几千个并行环境；插接吃接触保真度，MuJoCo 的求解器在软接触上通常更可控。选错的代价是训练很顺利、迁移全失败。

## 并行环境与 GPU 物理：吞吐决定可行性

腿式策略常需要 $2\times 10^{9}$ 步环境交互。算一下两种配置：

$$
\text{GPU：}\;4096\times 60=2.46\times 10^{5}\ \text{步/s}\;\Rightarrow\;2.3\ \text{小时},\qquad
\text{CPU 单环境：}\;1.5\times 10^{3}\ \text{步/s}\;\Rightarrow\;15\ \text{天}.
$$

这不是快慢之别，是可做与不可做之别。GPU 物理让腿式 RL 从"实验室级项目"变成"一晚上"。

$24\ \mathrm{GB}$ 显存下要留意观察类型。纯状态观察的环境很便宜，几千个并行没有问题；一旦每个环境都要渲染 $64\times 64$ 的 RGB，显存和带宽都被渲染吃掉，通常只能开到几百个。所以视觉策略的常见做法是先用状态观察训教师，再蒸馏出视觉学生——和 [7.4](/chapters/07-robot-policy/02-dexterous-manipulation) 的教师-学生同一个动机。

## 腿式 RL 的奖励怎么调

CS 123 的 Lab 5 把这件事做成了真机课的核心手艺：在 MJX 上跑数千个 Pupper 并行，PPO 当黑盒用，学生真正动手的是**调奖励函数**。腿式奖励至少有五项，每一项都对应一种失败：

| 项       | 奖励方向         | 调不好会怎样                             |
| -------- | ---------------- | ---------------------------------------- |
| 速度跟踪 | 鼓励跟上指令速度 | 太弱：站着不动；太强：往目标方向猛冲失控 |
| 能耗     | 惩罚用力         | 太弱：动作剧烈；太强：学会省力地原地抖   |
| 稳定性   | 惩罚躯干俯仰角   | 太弱：前仰后翻；太强：不敢加速           |
| 平滑     | 惩罚相邻动作差   | 太弱：抽搐；太强：动作迟钝               |
| 足端接触 | 惩罚非周期着地   | 太弱：乱蹬；太强：单一频率磨一个关节     |

没有一组权重是万能的。做法是固定其余项、扫一项，看步态视频和 reward 曲线。调好后还要加**域随机化**：地面摩擦、质量、电机延迟各随机 $\pm 20\%$–$50\%$，让策略见过足够多的"假机器人"，真机才像其中一种。最后用 wandb 把策略一键部署到真机 Pupper，看 sim2real 差距。

这条流水线（MJX 并行 → 调奖励 → 域随机化 → 一键部署）是腿式 RL 的事实标准。本书 [7.7](/chapters/08-robot-sim/03-domain-randomization) 的全身 sim2real 轨道走的就是它。

最后说清一个概念：**奖励对齐**（reward alignment）。奖励函数只是任务目标的代理，代理和真目标之间永远有缝——策略会找到缝里钻：速度奖励给太高，Pupper 学会原地高频抖腿也算"跟踪上了速度"。这就是 reward hacking，和 [7.3](/chapters/07-robot-policy/07-vla-rtx) 里「Checker 也会被利用」是同一类病：任何可优化的信号都会被优化到失真。对齐的办法不是把奖励调得更复杂，而是让奖励可检查——世界模型预测「这个动作序列之后世界长什么样」，用人能看懂的方式（视频、落脚点图）呈现出来，奖励有没有被骗过，一眼能看见。

## 资产格式：URDF、MJCF 与 USD 的互转损耗

三种格式描述的不是同一件事，互转一定有损失：

- **拓扑**。URDF 只能表达树状结构。四杆连杆、并联机构这类闭链要靠额外的约束声明，MJCF 用 `equality`，USD 用 physics joint，转换时最容易整段丢掉。
- **惯量**。URDF 里 `inertia` 缺失或写错很常见，导入工具会用碰撞体密度估算填上，结果可能差几倍。
- **碰撞几何**。凸分解（V-HACD 一类）的参数不同，同一个网格会得到不同数量的凸块。插接任务对孔口几何极敏感，这一步的差异足以改变成功率。
- **语义不对应**。MuJoCo 的 `armature`（电机转子惯量）在 URDF 里没有字段，丢掉之后关节会显得异常灵敏；阻尼、摩擦损耗、关节限位的刚度在各家的默认值也不同。

转换完成的第一件事不是训练，而是核对总质量、各连杆惯量主轴和自由落体时间。这几个数对不上，后面所有实验都是在另一台机器人上做的。

## 小结

- [ ] 栈的选择要看任务瓶颈：采样量吃 GPU 并行，接触保真度吃求解器质量。
- [ ] 资产互转会丢闭链、惯量、碰撞几何和 `armature` 这类语义，转换后先核对质量、惯量与自由落体时间。
- [ ] 腿式 RL 的核心手艺在于调奖励，而任何可优化的信号都会被过度优化到失真。
