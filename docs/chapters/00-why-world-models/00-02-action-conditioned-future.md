# 0.2　没有执行的动作，结果从哪里来

我们已经保留了最近几帧，并估计出汽车正在接近弯道。现在需要在三个动作中选择一个：保持速度、轻踩刹车或急刹车。

真实世界只会执行其中一个动作。其他两个动作会发生什么，摄像机没有拍到。

## 普通续写回答的是“通常后来怎样”

给一段道路视频，视频模型可以继续生成一种常见未来。例如，大多数训练片段中的司机都轻踩刹车，模型就可能继续生成减速转弯。

但规划需要三个分别受动作约束的未来：

```text
当前状态 + 保持速度 → 未来 A
当前状态 + 轻踩刹车 → 未来 B
当前状态 + 急刹车   → 未来 C
```

若模型忽略动作，只生成训练数据中最常见的后来，我们无法比较三个选择。

## 动作要进入转移

设当前内部状态为 `s_t`，候选动作为 `a_t`。最小预测接口写成：

```text
next_state(s_t, a_t) → s_{t+1}
```

动作不是结果出来以后附加的标签，而是导致变化的条件。训练数据也必须保存“在什么状态下做了什么，随后发生什么”。

```text
(s_t, a_t, s_{t+1})
```

若动作与帧错开一步，模型仍可能拟合运动趋势，却无法回答更换动作后的未来。第 1 章会具体检查时间对齐。

## 不同动作并不保证唯一结果

湿滑路面上急刹车，汽车可能稳定减速，也可能打滑。预测接口因此可以输出一个分布：

```text
P(s_{t+1} | s_t, a_t)
```

这里的 `P` 表示多种结果及其可能性。一个只输出平均位置的模型，可能把“向左打滑”和“向右打滑”平均成一条现实中不会出现的直线。

## 什么算动作条件模型

我们固定同一个起点、历史、路面和随机源，只替换动作。如果预测随动作按照合理方向改变，模型才显示出动作敏感性。

从数据集中任取两段不同视频进行比较不够严格，因为物体、速度和路面也可能同时变化。

## 小结

- [ ] 普通视频续写学习常见后来，动作条件预测回答指定动作的后果。
- [ ] 动作必须进入状态转移，也必须在数据中与相邻观察正确对齐。
- [ ] 同一动作可能有多种结果，模型需要在适当任务中保留不确定性。
