# 2.3　PlaNet：用 CEM 现场选择动作

RSSM 已经可以从当前状态展开未来。现在给它 1000 组候选动作序列，怎样在连续动作空间里找到较好的一组？

枚举不再可行。PlaNet 使用交叉熵方法（CEM）在 latent dynamics 中反复采样。

## 一轮 CEM

先为未来 `H` 步动作建立一个较宽的高斯分布，从中采样 `N` 组序列。

```text
采样动作序列
→ 在 RSSM 中 rollout
→ 累加预测 reward 与末端 value
→ 保留前 K 组
→ 用它们更新动作分布
```

重复几轮以后，分布集中在较好的动作附近。规划器只在真实环境执行第一步，然后重新读取观察。

## 为什么末端需要 Value

horizon 有限时，最后一个预测状态之后仍有未来。若只累加 `H` 步 reward，规划器可能偏好短期收益。

末端 value 估计剩余回报：

```text
score = r_t + γr_{t+1} + ... + γ^H V(s_{t+H})
```

value 自身也可能错误，因此要与不使用末端 value 的短 horizon 基线比较。

## CEM 的优点与代价

CEM 不需要提前训练 Actor，目标改变后可以直接换 reward 再规划。代价是每个真实动作前都要运行大量模型 rollout。

模型有漏洞时，CEM 会主动寻找并放大漏洞。限制动作范围、不确定性惩罚和真实反馈都很重要。

## PlaNet 与 MPC

PlaNet 并不是“预测一次就照着走到底”。它采用 MPC：每次使用最新观察更新 posterior，只执行当前规划的第一步。

## 先用可解释状态验收

直接在 RSSM latent 中规划时，失败可能来自 Encoder、状态、动态或 Planner，很难一次分清。A2 先做一个较简单的对照：从 PixelWorld 图片中量出红色方块位置，学习 `位置 + 动作 → 下一位置`，再用 learned dynamics 规划。

这个模型仍然从观察得到状态，也仍然从数据学习转移，只是状态只有两个数。若它能让真实控制优于随机动作，我们便确认“学习动态—模型内搜索—现实执行”这条链成立。之后换成 latent，新增困难才主要来自表示与长时间预测。

## 小结

- [ ] CEM 用采样、筛选和重拟合搜索连续动作序列。
- [ ] PlaNet 在 RSSM 中规划，并通过 MPC 每步重新计算。
- [ ] 在线搜索适应目标变化，但计算慢，也会寻找模型漏洞。
