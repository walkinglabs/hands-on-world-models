# 1.2　图像编码器：CNN 与 ViT

一张 $64\times64\times3$ 的图片包含 $64\times64\times3=12288$ 个数。若为每一种可能的图片单独建一张转移表，状态数量瞬间就爆炸。

我们需要的，是把图片压缩成较短的特征，同时尽量保留物体位置、形状和运动这些后续预测要用的信息。这一节介绍两种最常用的**编码器**（encoder）：CNN 与 ViT。

## CNN：同一个小窗口到处检查

先看一张左半边为 $0$、右半边为 $1$ 的灰度图。我们拿一个 $3\times3$ 的小窗口去扫它，窗口对右边一列给正权重、对左边一列给负权重：

$$
K=\begin{bmatrix}-1 & 0 & 1\\ -1 & 0 & 1\\ -1 & 0 & 1\end{bmatrix}.
$$

当窗口跨过明暗边界时，九格相乘再求和的结果最大；落在纯色区域时，结果接近零。把窗口扫过整张图，输出的就是一张“边缘响应图”。设窗口在位置 $(i,j)$ 覆盖的图像块为 $P_{i,j}$，一次卷积可以写成：

$$
Y_{i,j}=\sum_{u,v} K_{u,v}\,P_{i,j}[u,v].
$$

**卷积神经网络**（CNN）做的事情，就是从数据中自动学习成百上千个这样的 kernel $K$。浅层寻找边缘和纹理，后续层把局部结果再组合成更大的形状。

在 shape 上，CNN 把一张图片映射成一组特征图：

$$
[B,C,H,W]\;\longrightarrow\;[B,C',H',W'],
$$

输入通道 $C$、输出通道 $C'$ 通常各不相同，分辨率也会随下采样变小。CNN 在小图像上计算便宜、局部结构明确。Dreamer 常用 CNN 编码画面，机器人模型也常用它提取视觉特征。

## ViT：把图片切成 patch

另一种办法是把图片切成许多小块。一张 $16\times16\times3$ 的图片，用 $4\times4$ 的 patch 来切，会得到多少块？沿每条边 $16/4=4$ 块，总共 $4\times4=16$ 个 patch，每个 patch 含 $4\times4\times3=48$ 个数：

$$
[16,16,3]\;\longrightarrow\;16\text{ 个 }[4,4,3]\text{ patch}\;\longrightarrow\;16\text{ 个 token}.
$$

**视觉 Transformer**（ViT）把这些 token 放进同一序列，让它们两两交换信息。与 CNN 的局部窗口不同，远处两个 token 在一次注意力里就能直接建立联系。这也方便我们把视觉 token 与语言 token、动作 token 拼在同一条序列中一起处理。

## 为什么还需要位置编码

图片切成序列之后，模型看到的只是一组向量，它并不会自动知道哪个 patch 在左上角、哪个在右下角。位置编码就是把空间坐标注入 token 的过程。一个常见做法是给第 $k$ 个 token 加一段与位置相关的向量 $e_k$：

$$
\tilde{x}_k = x_k + e_k.
$$

加了位置编码，交换两个 patch 后模型才能察觉内容“搬家”了。视频还要再补一维时间位置：JEPA 的 tubelet、互动视频的 token 预测、VLA 的图文融合都依赖这一点。

## CNN 与 ViT 怎样选择

小图片、局部模式明显、计算预算较紧时，CNN 通常更简单直接。需要遮挡预测、长距离依赖或与语言融合时，token 接口更顺手。

二者也可以组合。例如先用 CNN 降低分辨率，再把特征图切成 token 喂给 Transformer。选择依据是数据、任务和接口，不是模型阵营。

## 编码器保留了什么

分类模型只要保留物体类别就够了。世界模型却要预测位置、速度和动作后果，因此编码器不能随意丢掉这些信息。

最小检查包括三件事：用一个线性头能否从 latent 读出物体的位置与速度；替换动作之后，预测的 latent 未来是否随之改变；多步 rollout 之后，画面里的小物体还在不在。这三项比“重建误差低”更贴近世界模型的真实需求。

## 小结

- [ ] CNN 复用局部 kernel，用 $\sum K\cdot P$ 提取边缘与纹理等局部结构。
- [ ] ViT 把图片切成 patch、加位置编码，再让 token 互相通信。
- [ ] 编码器是否合格，要由后续预测和任务来检查，而非只看分类或重建。
