# 1.7　Replay Buffer 与第一台可学习模型

组件已经有了，接下来把连续经历整理成模型真正能学的数据。世界模型不能只拿一堆互不相关的图片训练，它需要知道动作位于哪两帧之间。

## Episode 怎样保存

课程使用下面的最小容器：

```python
Episode(
    observations=[T + 1, ...],
    actions=[T, ...],
    rewards=[T],
    dones=[T],
)
```

验证函数检查长度、终止位置和时间戳。对机器人数据，还要保存语言指令、关节状态、控制频率和延迟。

## Replay Buffer 不能跨 episode

episode A 结束以后，episode B 会从新的随机状态开始。若先把数组拼在一起再截取序列，模型可能学到：A 的终点经过一个不存在的动作，突然来到 B 的起点。

正确顺序是先选择一段足够长的 episode，再从其中截取连续片段。

## 数据切分不能随机拆帧

相邻视频帧几乎相同。随机拆帧会让训练帧的近邻进入测试集，得到虚高结果。

课程按 episode、scene、seed 或 task template 分组切分。动作条件任务还要检查测试集中是否包含训练从未覆盖的动作区域。

## 从计数学习 LineWorld

在一维世界中，机器人可以向左或向右，环境带有 20% 打滑。我们统计每个 `(state, action)` 后出现的下一状态，得到概率转移表。

这台模型不使用梯度，却可以：

1. 保留多个结果；
2. 标出未见状态—动作；
3. 进行多步 rollout；
4. 被 MPC 调用选择动作。

## 反事实与闭环检查

固定同一起点和随机种子，只替换动作。预测应按动作合理改变。

随后把规划器选择的第一步放回真实 LineWorld，保存新的 transition，更新计数表，再次规划。这就是课程第一次“数据—模型—行动—现实修正”循环。

## PA0 交出什么

PA0 提供新的小地图，不提供完整模型结构。提交内容包括：接口图、数据卡、简单基线、一步与多步结果、动作反事实、下游成功率和一组失败案例。

表格方法若已经解决任务，继续换神经网络不会加分。只有当图像、历史、不确定性或动作空间确实使表格失败时，才进入相应路线。

## 小结

- [ ] Replay Buffer 在同一 episode 内采样连续片段。
- [ ] train、val、test 按 episode 或场景切分。
- [ ] 计数表可以成为第一台 learned world model。
- [ ] PA0 用多步、反事实和任务结果检查模型，而不只看训练误差。
