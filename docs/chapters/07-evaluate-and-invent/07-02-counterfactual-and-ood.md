# 7.2　反事实、OOD 与模型漏洞

从数据集中找一段左转视频和一段右转视频，不能证明模型理解动作。两段视频的速度、地图、天气和随机事件可能同时不同。

## 反事实测试

固定初始状态、历史、物体、环境参数和随机源，只替换一个动作或指令。

```text
same world + action A → predicted future A
same world + action B → predicted future B
```

对随机环境，每个动作运行多次，比较结果分布，而非要求像素逐点相同。

## OOD

神经网络在训练范围之外仍会输出结果。我们改变颜色、速度、摩擦、视角、物体数量或语言组合，查看错误是否上升，以及模型是否知道自己没有把握。

OOD 条件必须在实验前定义，不能看到失败后只挑最戏剧性的样例。

## 不确定性校准

把预测置信度分箱，比较每一箱的真实错误率。可靠模型的低置信样本应更容易出错。

ensemble、概率 latent 或 diffusion 多样性都可提供不确定性线索，但样本多样不自动等于校准。

## Planner 会寻找漏洞

普通测试随机采样动作；Planner 会主动寻找高预测回报动作，常进入模型最不可靠的区域。

因此要让 Planner 对模型进行压力测试，保存“预测很好、现实很差”的固定 seed。处理办法包括补数据、限制规划域、不确定性惩罚、缩短 horizon 和独立安全约束。

## 小结

- [ ] 反事实测试固定同一世界，只更换一个条件。
- [ ] OOD 检查模型在训练分布之外的错误与置信度。
- [ ] Planner 是模型漏洞的主动搜索器，应单独进行压力测试。
