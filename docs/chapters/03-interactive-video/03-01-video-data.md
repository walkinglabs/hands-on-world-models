# 3.1　动作条件视频数据

在 ViZDoom 的走廊里，我们按下「向左」后，画面里的敌人会从右侧滑到中间；在 CRAFTER 里砍一棵树，下一帧的树会少一格血条。把这种「按键—画面变化」的对应完整记下来，就是动作条件视频数据。它和普通的监控录像不一样的地方在于：每一段画面之间，都夹着一个由人决定的动作。

所谓动作条件世界模型，就是从这样的数据里学「在给定历史的条件下，下一个动作会把画面带到哪里」。所以我们先得把数据接对。

## 一段轨迹长什么样

把一段长度为 $T$ 的游戏经历按时间排好，第 $t$ 帧记作 $x_t$，第 $t$ 个动作记作 $a_t$。关键是动作的位置：$a_t$ 是从 $x_t$ 走到 $x_{t+1}$ 之间执行的那个按键。

```text
x_0, a_0, x_1, a_1, x_2, ..., a_{T-1}, x_T
```

也就是说，一条轨迹里画面比动作多一个，因为最后那一帧后面没有「下一个动作」。一条样本因此写成：

```text
frames : x_0, x_1, ..., x_T        形状 [T+1, C, H, W]
actions: a_0, a_1, ..., a_{T-1}    形状 [T, A]
done   : 终止标志                   形状 [T]
```

动作空间 $a_t \in \mathcal{A}$ 可以是离散的（ViZDoom 的「左移 / 右移 / 开火」），也可以是连续的（CRAFTER 用方向键，CarRacing 用方向盘角度和油门）。

## 错位是怎样发生的

录数据时最常见的错误，是把 $a_t$ 配到错误的那一段变化上。比如把 $a_t$ 当成「导致 $x_t$ 的动作」，于是模型学到的其实是：

$$
x_{t+1} = f(x_t, a_{t+1})
$$

而不是正确的 $x_{t+1} = f(x_t, a_t)$。错了一格。

奇怪的是，错位模型的 loss 往往并不高。原因是赛车类游戏连续几帧都保持相近方向，即使动作整体往后挪了一格，模型依靠上一帧和惯性也能猜对大部分像素。这就是「loss 低却不等于学对了因果关系」的一个典型例子。

这种错位要到反事实实验里才暴露：固定同一份历史、只替换当前动作来比较，模型若继续沿原方向生成，就说明它根本没用上 $a_t$。

## 反事实：判断可控的最小实验

所谓反事实，就是把「其余一切相同，只改变一个因素」的情形摆在一起看。对动作条件视频，做法是固定初始帧 $x_0$、速度和随机种子，然后分别给三个动作 $a \in \{\text{left}, \text{right}, \text{noop}\}$，让模型各 rollout 一段。

```text
同一 x_0 ──┬─ a=left  ──► 物体往左
          ├─ a=right ──► 物体往右
          └─ a=noop  ──► 物体几乎不动
```

比较的不是「三段视频清不清楚」，而是未来物体的位置和朝向是否随动作分叉。这是后面 B2 notebook 反事实网格的雏形。

## 还要记录什么

光有像素和按键还不够。下面的信息看起来琐碎，却都属于「数据的定义」，缺一项就可能在别处复现不出来：

- 帧率与控制频率：每秒采样多少帧、多久发一次动作；
- 动作重复：游戏里一个按键持续几帧才记录一次（很多环境的 wrapper 会把同一动作重复 4 帧）；
- 延迟：按下到画面真的变化的间隔；
- 随机种子：环境的初始状态和随机事件来源。

如果某个 wrapper 让每个动作保持四帧，那么「一条样本」的时间跨度其实是四帧而不是一帧。这种细节写不进像素，必须单独记。

## 三层数据各能验证什么

我们用到的数据有三个层次，各自能证明的事情不同：

- **PixelWorld**：可由项目按 seed 程序生成，画面干净、因果明确，用来检查动作对齐和反事实分叉是否正确；
- **CarRacing / CRAFTER**：纹理更复杂、动作连续或半连续，提供更接近真实游戏的漂移和遮挡；
- **无动作互联网视频**：只能训练画面外观或被动表示，不能直接证明「按键可控」，因为它压根没有动作标签。

这最后一类之所以单列出来，是因为很多视频生成模型在它上面效果惊艳，但「会预测运动」和「能被动作控制」是两回事。Genie 那一类工作正是试图从无动作视频里反推出隐含动作（latent action），我们在 3.4 会再提。

## 数据切分

切训练 / 验证集时要按完整的 episode 和环境 seed 切，不能把一条轨迹的帧随机打散。同一条赛道或同一个地图的帧高度相关，打散会让验证集泄漏训练集的信息，多步漂移指标也会失真。如果某些场景反复出现，还要按场景分组。

## 小结

我们这一节把「动作条件视频」拆成了画面 $x_t$ 和动作 $a_t$ 交替的序列，强调 $a_t$ 必须落在 $x_t$ 与 $x_{t+1}$ 之间，并用固定历史替换动作的反事实来判断模型是否真的可控。数据本身还要附带帧率、控制频率、wrapper 行为和随机种子，否则复现时会踩坑。
