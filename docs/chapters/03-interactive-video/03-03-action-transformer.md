# 3.3　动作条件 Transformer：自回归视频生成

经过 3.2，每一帧 $x_t$ 已经变成一张 token 网格，比如 PixelWorld 的 $4\times4=16$ 个编号。这一节我们把这些 token 和动作排成一条长序列，让 Transformer 像语言模型预测下一个词那样，自回归地预测下一帧的 token。

所谓自回归，就是「一步一步往后生成，每一步都把已经生成的部分当作输入」。语言模型这么预测下一个词，视频模型也这么预测下一组画面 token。

## 序列怎样排列

最直接的排列是把帧的 token 和动作交替地拼起来。设第 $t$ 帧展开成 $N=h\times w$ 个 token $s_t = (s_t^{(1)},\dots,s_t^{(N)})$，整条序列就是：

$$
s_0^{(1)}, \dots, s_0^{(N)},\ a_0,\ s_1^{(1)}, \dots, s_1^{(N)},\ a_1,\ \dots
$$

模型每一步要预测的，是给定前面所有内容后，下一个 token 的分布。形式化地，下一个 token 的条件概率被分解成：

$$
p(s_{1:T} \mid s_0, a_{0:T-1}) = \prod_{t=0}^{T-1}\prod_{i=1}^{N} p\!\left(s_t^{(i)} \mid s_{<t},\ a_{<t},\ s_t^{(<i)},\ a_t\right)
$$

其中 $s_{<t}$ 是第 $t$ 帧之前的所有帧 token，$s_t^{(<i)}$ 是第 $t$ 帧里第 $i$ 个位置之前的 token。这就是把视频生成当成「token 流的下一项预测」。

要让模型分清「这是第几帧的第几个格子、是画面还是动作」，还要叠加位置编码：空间位置编码标记格子坐标、时间位置编码标记第几帧、类型编码区分视觉 token 和动作 token。

## 动作怎样进入序列

离散按键 $a_t$ 可以直接用一个 embedding 表查表，得到 $D$ 维向量当成一个 token；连续控制（方向盘角度等）可以先过一个小 MLP 投影到 $D$ 维。无论哪种，关键约束是：**动作 token 必须排在它所影响的那一帧之前**，这样因果顺序才对。

$$
a_t \text{ 的 embedding } e(a_t) \in \mathbb{R}^D
$$

也有一些模型不把动作当成序列里的 token，而是在每一层把动作特征加到画面特征上，或者用 cross-attention 把动作当作外部条件。课程为了方便做「去掉动作」的消融对照，先用最直接的 token 方式——这样删掉动作 token 就等于无条件生成，比较干净。

## 因果遮罩与训练目标

预测下一个 token 时，模型只能看历史和当前帧里已经生成的位置，绝不能偷看到未来答案。训练时用一个下三角的因果遮罩（causal mask）挡住未来位置：

$$
\text{注意力位置 } (i,j)\ \text{允许} \iff j \le i
$$

遮罩错了会发生数据泄漏：训练 loss 看着很低，部署时却根本生成不出来，因为生成阶段根本看不到未来的真值。这是自回归模型最常见的「loss 掩人耳目」陷阱。

每个位置的输出是一个在 $K$ 个码本项上的分类分布，训练目标是最大化真实 token 的对数似然，等价于交叉熵：

$$
\mathcal{L}_{\mathrm{AR}} = -\sum_{t,i} \log p\!\left(s_t^{(i)} \mid s_{<t},\ a_{<t},\ s_t^{(<i)},\ a_t\right)
$$

B1 里我们正是用 `dynamics.loss(current_tokens, actions, next_tokens)` 算这个交叉熵，并报告 token accuracy。

## Teacher forcing 与部署的落差

训练时，模型每一步看到的「上一帧」都是真实数据里的 token；这种喂真实历史、只预测下一步的训法叫 teacher forcing。它的好处是稳定、好并行，坏处是和部署时的处境不一样。

部署生成时没有真值可喂，第二步开始输入的就是模型自己刚预测的 token。一步的小错误会进入下一次的输入，下一步又在这被污染的输入上继续错，错误像滚雪球一样累积。这就是后面要反复提到的多步漂移（compounding error）。

所以光看一步的 token accuracy 远远不够。B2 从同一起点连续 rollout 8 步，并跟踪红色方块解码后的中心位置——中心停住、反向或消失，都是长程 rollout 失败的信号。

## 反事实：去掉动作或换动作

判断「画面真的听从按键」的最小实验，是固定同一份起始 token $s_0$，只替换动作 $a$，看输出的下一帧 token 是否不同。B2 把起点复制五份，分别给五种动作，并测量输出 logits 相对「不动」那组的差异：

$$
\Delta_i = \lVert \mathrm{logits}(s_0, a_0) - \mathrm{logits}(s_0, a_i) \rVert
$$

如果所有 $\Delta_i \approx 0$，说明模型其实在忽略动作、只是在「复制画面」，无论单步 loss 多好看都不可控。只有中心位置随动作分叉，才能继续谈可控。

## KV Cache 与实时性

自回归生成每一步都要重新处理整段历史，朴素做法的计算量随步数平方增长。KV Cache 把已经算过的每层 key 和 value 存下来，下一步只算新 token 那一份，把每步成本压回线性。

即便如此，端到端延迟仍要把 tokenizer 编码、Transformer 前向、Decoder 还原这三段加在一起算。互动视频要求每帧都在几十毫秒内出，所以 B2 会同时记 tokenizer、Transformer、Decoder 各自的耗时，而不只是 Transformer 的 FLOPs。

## 小结

我们把帧 token 和动作 token 交替排成序列，用因果遮罩保证只看过去，用交叉熵目标训练一个动作条件的自回归视频模型。训练用 teacher forcing、部署吃自己的输出，这一落差正是多步漂移的来源，必须用反事实和长程 rollout 来检查。接下来看另一条生成路线：扩散模型。请看 [3.4 扩散视频生成与多步漂移](./03-04-diffusion-and-evaluation.md)，动手实验在 [B2：可控视频生成](/labs/route-bc)。
