# 第 0 章　为什么机器需要先想一想

一辆小车来到弯道前。车上的相机拍到下面这幅情景：道路向右弯，外侧有护栏，路面有一片积水。

程序现在要选择一个动作。它可以继续加速，可以轻踩刹车，也可以急刹。

我们先不使用“世界模型”这个词。我们从已经熟悉的办法开始，一步一步看它们能做到哪里。

## 0.1 一张照片能告诉我们什么

先训练一个卷积神经网络。所谓卷积神经网络（CNN），可以暂时理解为一台从图片中寻找局部形状的机器。

它看到道路边缘、弯道和积水，输出下面几个结果：

```text
弯道：有
积水：有
护栏：右侧
```

如果训练数据中的车速都相近，我们可以在 CNN 后面接一条简单规则：看见弯道就减速。这套方法并不差。在道路简单、速度变化小的时候，它甚至已经够用。

现在只改变一个条件。

两辆车来到同一个弯道前。它们的相机拍到了几乎相同的照片。第一辆车每小时 20 公里，第二辆车每小时 100 公里。

照片告诉我们汽车在哪里，却没有告诉我们汽车刚才怎样运动。低速车可以平缓转弯，高速车却应该更早刹车。

问题不在 CNN 没有看清弯道。需要的速度信息，本来就不在这一张照片里。

### 先保留一小段过去

我们把最近三张照片放在一起。第一辆车在三张图中的位置变化很小，第二辆车的位置变化很大。

```text
慢车：位置 10 → 12 → 14
快车：位置 10 → 20 → 30
```

即使没有速度表，从位置怎样变化也能得到速度线索。于是，我们需要一份由历史更新而来的内部记忆。

RNN 或 GRU 可以承担这项工作。此时不必先研究它们的门控公式，只需记住它们的接口：

```text
上一份记忆 + 当前观察 → 新的记忆
```

新的记忆不一定直接对应一个可以说出名字的量。它只要保留当前任务需要的过去信息，例如速度方向、刚才是否打滑、前一时刻有没有看见行人。

到这里，我们得到第一条结论：**看清当前画面**和**根据过去估计现在的情况**不是同一件事。

## 0.2 记住过去以后，还缺什么

现在，程序已经能区分快车和慢车。我们仍然只让它选择一个动作，通常可以训练一条策略：

```text
当前观察 + 内部记忆 → 动作
```

这里的策略（Policy），就是根据当前信息直接决定做什么的程序。环境固定、目标不变、试错便宜时，直接策略往往更简单，执行也更快。

接下来把路面改成湿滑路面。我们不想马上执行动作，而想在执行以前比较三种做法：

```text
轻踩刹车以后，两秒内会到哪里？
急刹以后，车身会不会失控？
继续转向以后，会不会撞上护栏？
```

RNN 的记忆保存了“刚才发生了什么”。上面三个动作却都还没有发生。

我们需要把某个候选动作放进程序，让它从同一个现在出发，分别推测三个未来。记住过去和试演未来由此分开。

可以继续使用 RNN，也可以换成 Transformer。网络结构不是关键。新的接口才是关键：

```text
当前内部状态 + 候选动作 → 下一内部状态
```

如果把输出的下一状态再次送回模型，就可以继续推测第二步和第三步。

## 0.3 续写常见未来，不等于预测指定动作

互联网上有大量视频。我们可以训练一个 Transformer，根据前面的画面预测后面的画面。

假设训练集中的驾驶员经过这个弯道时通常会轻踩刹车。视频模型很可能学会生成一段平稳减速的视频。

现在我们指定“急刹”。如果训练数据没有记录刹车踏板踩了多深，模型看到的仍然只有过去画面。它只能猜测人们通常怎样开过这个弯，无法确认我们指定的动作究竟是什么。

两项任务看起来接近，实际输入不同：

```text
根据过去画面，续写一个常见的后来

根据过去画面和指定动作，推测这个动作的后果
```

后者需要动作与观察严格对齐。若方向盘是每秒 20 次、相机是每秒 30 帧，我们还要知道每张图之间执行了哪些控制，以及控制信号有多少延迟。

动作条件加进模型以后，还有一个问题。连续生成时，模型会把自己生成的结果当作下一步输入。第一步只偏一点，十步以后可能已经来到现实中不存在的道路。

所以，Transformer 可以成为世界模型的骨架，但“使用 Transformer”本身不保证模型可以用于行动。数据里要有动作，连续推演要检查漂移，执行后还要回到真实观察修正。

## 0.4 会讲道理，仍不等于可以反复试演

我们也可以把弯道图片交给视觉语言模型，再问语言模型：“高速进入湿滑弯道会怎样？”

它可能回答：制动距离会变长，车辆也可能打滑。这条常识是合理的。

真正控制这辆车时，还需要当前轮胎的磨损、车辆重量、路面摩擦、刹车延迟和刚才的方向盘角度。语言模型通常没有这些眼前状态，也不需要在动作执行以后，把自己的预测与传感器结果逐步对照。

一句合理说明与一台可运行的变化模型并不相同。后者要支持下面的重复试验：

```text
固定同一辆车、同一段路和同一时刻
→ 把刹车从 10% 改成 30%
→ 推测接下来每一步的速度和位置
→ 执行第一步
→ 读取新传感器
→ 修正内部状态，再计算一次
```

语言模型可以帮助理解目标、调用工具和提出高层计划，视觉语言模型可以帮助读懂画面。它们仍然可以成为系统的一部分。

这里缺少的不是另一种聊天能力，而是针对当前环境和当前身体，反复接受现实检查的动作后果模型。

## 0.5 直接策略在什么时候不够

直接策略并没有错。若任务只要求在固定赛道上尽快到达终点，而且模拟器允许安全试错几百万次，我们完全可以学习“看到这种情况就做这个动作”。

下面分别改变三个条件。

第一，终点改变。原来的目标是尽快到学校，现在变成先去医院。好动作变了，道路如何连接却没有变。

第二，试错变贵。机械臂一次错误抓取可能打碎杯子，汽车一次错误转向可能造成事故。我们希望动作执行以前，先比较几个后果。

第三，环境变陌生。模型没有见过透明杯子或结冰路面。此时系统应该知道自己的判断没有把握，而不是仍然输出一个很肯定的动作。

直接策略把“世界怎样变化”和“当前想完成什么”压进了同一个动作答案。目标改变时不容易复用；发生失败时，也很难询问另一个动作原本会怎样。

将变化规律单独学出来，可以让同一套规律服务不同目标，也可以在真正执行以前比较动作。

### 三种无法绕开的办法

一个动作还没有执行，它的结果就不在当前观察里。若仍想比较几个动作，只有三种基本办法：

1. 把每个动作都在现实中试一遍；
2. 使用工程师写好的方程或模拟器；
3. 从过去经历中学出动作与结果之间的规律。

第一种办法在小游戏里可能便宜，在驾驶、机器人和科学实验中却可能太慢、太贵或不可逆。

第二种办法本身就是一套人写的世界变化模型。第三种办法则是本书主要研究的学习型模型。

因此，只要任务同时要求“行动前比较未执行的动作”和“不能把所有动作都在现实中试一遍”，某种形式的内部模型就会出现。它可以藏在策略内部，也可以是一个单独模块；可以是方程、表格、latent dynamics 或视频生成器。

我们现在可以给它一个名字：**世界模型**负责根据过去和候选动作，推测接下来可能发生什么，并让新的真实观察不断修正这份推测。

## 0.6 先做一个人写的最小世界

真实驾驶包含图像、速度、摩擦和连续控制。为了只研究动作怎样改变状态，我们先把世界缩成九个格子。

```text
┌──────┬──────┬──────┐
│ 起点 │ 陷阱 │ 终点 │
├──────┼──────┼──────┤
│      │ 墙壁 │      │
├──────┼──────┼──────┤
│      │      │      │
└──────┴──────┴──────┘
```

机器人从左上角出发。它可以向上、向下、向左或向右，但不能穿过墙壁。

若只选择“下一格离终点最近”的动作，机器人第一步就会向右走进陷阱。它知道终点在哪里，却没有考虑动作造成的变化。

我们先在纸上写两行：

```text
左上角 + 向右 → 陷阱
左上角 + 向下 → 左中格
```

为了写出这两行，程序需要知道当前在哪个格子、可以做哪些动作，以及每个动作会怎样改变格子。

第三项称为状态转移：

```text
当前状态 s + 动作 a → 下一状态 s'
```

此时，一台最小世界模型已经出现。它不负责挑动作，只负责回答动作的后果。

### 最小代码

在 F0 中，我们会完成下面这个函数：

```python
def next_state(state, action):
    row, col = state
    dr, dc = ACTIONS[action]
    candidate = (row + dr, col + dc)

    if outside(candidate) or candidate in WALLS:
        return state
    return candidate
```

这段代码是人工写成的模型。它很小，却已经具有后面神经世界模型的主要接口：输入当前状态和动作，输出下一状态。

## 0.7 一步预测为什么不够

知道下一步以后，机器人可以避开眼前的陷阱。但一个安全的第一步，不一定通向终点。

我们把模型预测出的下一状态再次放回模型：

```python
state = start
for action in actions:
    state = next_state(state, action)
```

假设动作序列是：

```text
下 → 下 → 右 → 右 → 上 → 上
```

这些移动还没有真正发生。程序只是在内部连续调用转移模型。

这种向前推演称为 rollout。rollout 的长度也称为 horizon。horizon 为 1 时只看一步，为 6 时看六步。

更长的 horizon 能发现更远的陷阱，却需要更多计算。模型若不准确，误差也会随步数累积。我们以后会反复遇到这项取舍。

## 0.8 可以生成未来以后，怎样比较

模型现在能生成许多路线，却不知道哪一条更好。我们给九格世界加入一项任务：

```text
到达终点：+10
掉入陷阱：-10
普通移动：-1
```

一步得到的分数称为奖励（reward）。一条路线累计得到的结果称为回报（return）。在这个小例子里，可以直接把每一步奖励相加。

路线 A 掉进陷阱：

```text
-10
```

路线 B 经过六步到达终点：

```text
-1 -1 -1 -1 -1 +10 = 5
```

世界模型描述“动作之后会发生什么”。奖励或目标说明“我们现在关心什么”。两者不应混在一起。

若把终点移动到另一格，转移规律没有改变，路线的好坏却会改变。这正是把世界规律与任务目标分开的好处。

## 0.9 世界模型、规划器和策略

我们现在把三个程序并排放好。

世界模型接收当前状态和动作，给出动作的可能后果。

规划器（Planner）反复调用世界模型，展开几条路线，再比较它们的回报。

策略接收当前信息，直接输出这次要执行的动作。

```text
世界模型：现在 + 某个动作 → 可能的未来
规划器：调用世界模型比较几种未来 → 选出动作
策略：当前信息 → 直接给出动作
```

三者可以配合使用。规划器先用世界模型算出许多好动作，再把这些结果交给策略学习。以后遇到相似情况，策略便可以直接行动，不必每次从头搜索。

它们也不必总是同时出现。互动视频模型通常负责根据玩家按键生成未来画面，不替玩家选择按键；直接 VLA 负责输出机器人动作，也可能没有显式世界模型。判断一个系统时，先看输入、输出和调用关系，不看名字里有没有 `world`。

## 0.10 转移规律从哪里来

九格世界的移动规则是我们写进程序的。现实环境没有附送 `next_state` 函数。

机器需要先保存连续经历：

```text
观察 o_t
动作 a_t
奖励 r_t
下一观察 o_{t+1}
是否结束 d_t
```

假设我们记录了下面几次移动：

| 当前格 | 动作 | 下一格 |
| ------ | ---- | ------ |
| 左下   | 右   | 中下   |
| 左下   | 右   | 中下   |
| 左下   | 右   | 左下   |
| 中下   | 右   | 右下   |

前三行说明，同一个动作不一定总有相同结果。也许地面打滑，机器人有一次没有移动。

我们可以先用计数学习最简单的概率模型：从左下向右时，三次中有两次到达中下，一次停在原地。

```text
P(中下 | 左下, 右) = 2 / 3
P(左下 | 左下, 右) = 1 / 3
```

模型不应只输出两个结果的平均位置。平均位置可能落在两个格子之间，那里根本不是合法状态。更合理的做法是保留多种可能及其概率。

在复杂任务中，计数表会换成神经网络，格子会换成 latent、图像 token 或 3D Occupancy。问题并没有改变：从连续经历中学习动作与结果之间的规律，并表达还没有把握的部分。

## 0.11 模型会想错

现在假设机器人从未走过地图右下角。学习到的模型却误以为那里是一条近路。

规划器会主动寻找回报最高的路线。它可能反复调用模型，最后正好找到模型最不准确的角落，并把一个预测错误当成捷径。

这不是普通随机误差。规划器越认真搜索，越可能利用模型的漏洞。

一个实用办法是模型预测多步，但只执行第一步：

```text
观察真实状态
→ 在模型里比较未来
→ 只执行第一个动作
→ 读取新的真实状态
→ 再规划一次
```

这就是模型预测控制（Model Predictive Control，MPC）的基本节奏。它不能让错误消失，却能在每一步用现实把内部想象拉回来。

除此以外，还需要：

- 在没见过的状态—动作上报告较高不确定性；
- 限制 rollout 长度；
- 收集规划器真正会访问的数据；
- 在真实环境或高可信模拟器中做闭环评价；
- 保存失败案例，而不只展示最好的一段轨迹。

世界模型的价值不在于永远预测正确，而在于它的预测可以被检查、被修正，并帮助系统在有限代价下做出更好的动作。

## 0.12 回到经典《World Models》

现在再打开 2018 年的《World Models》。论文用三个部分完成一套可学习的赛车和 Doom 控制系统：

- `V`：视觉模型把图片压成较短的 latent；
- `M`：记忆模型根据 latent 和动作预测未来分布；
- `C`：控制器根据当前 latent 和记忆选择动作。

这些名字现在不再是需要背的字母。

图像太大，无法直接建转移表，所以需要 `V`。一张图看不出速度，未来又可能有多种结果，所以需要带记忆和随机预测的 `M`。最终任务需要执行动作，所以加入 `C`。

论文还有一个很重要的实验：控制器可以在记忆模型生成的“梦境”里训练，再回到真实游戏测试。模型若过于简单，控制器可能利用梦境漏洞，回到真实环境就失败。作者通过增加模型中的随机性，让梦境变得更难被钻空子。

这与九格世界右下角的假捷径是同一类问题。规模和网络结构不同，基本矛盾没有变。

### World Models、PlaNet 与 Dreamer 的位置

经典 World Models 展示了“在学出的内部世界中训练控制器”。PlaNet 后来使用 RSSM，并在每次行动前用 CEM 搜索动作序列。Dreamer 继续使用 RSSM，却把想象中的好动作训练成 Actor，并用 Critic 估计未来价值。

```text
PlaNet：世界模型 + 每次现场搜索
Dreamer：世界模型 + 在想象中训练策略
```

这组对照会在第 3 章完整实现。第 0 章只需要保留问题：动作是每次临时搜索，还是把搜索经验学成一条能快速行动的策略？

## 0.13 以前为什么没有成为同一条主线

“机器应该在行动前想一想”并不是近几年才出现的想法。

控制系统长期使用方程预测机器运动。棋类程序在规则写好的棋盘上向前搜索。1990 年提出的 Dyna 已经把真实试错、学习环境模型、在模型中规划和再次行动接成循环。

长期困难在于：怎样从复杂现实数据中，学出一台足够可靠、又来得及运行的内部世界。

早期有几项实际限制。

首先，很多任务不需要学习模型。工程师已经知道机械臂方程时，直接使用方程更可靠；模拟器允许无限试错时，直接策略也可能更简单。

其次，容易获得的数据通常缺少动作。网络上有大量图片和视频，却很少同时记录关节动作、接触力、相机位姿、物体质量和失败结果。

再次，真实世界无法直接建表。机器必须把高维观察压成较短状态，又不能把速度、遮挡物体、接触关系和任务信息一同丢掉。

最后，一步预测正确不代表连续使用可靠。长时误差、推理延迟和规划器利用模型漏洞，都会让漂亮的离线结果无法变成真实行动。

近几年，视觉表示、生成模型、序列模型、GPU、模拟器和交互数据同时进步。更重要的是，人工智能开始操作软件、控制机器人、生成可进入的三维空间。模型一旦参与行动，评价标准就不再只是回答通顺或图像逼真，而是动作后果能否接受现实检验。

世界模型因此成为多个领域重新汇合的接口。它不是第五种网络，而是一项越来越难以回避的系统职责。

## 0.14 本章得到的部件

我们从一张弯道照片开始，最后得到了一套完整但很小的行动过程：

```text
保存连续经历
→ 用历史估计当前状态
→ 根据状态和候选动作预测未来
→ 表示多个可能结果与不确定性
→ 用目标或价值比较未来
→ 选择并执行第一步
→ 读取真实结果，修正内部状态
```

每个后续组件都对应本章的一处缺口。

| 缺口                     | 需要的能力       | 后续常用工具                            |
| ------------------------ | ---------------- | --------------------------------------- |
| 图片太大，无法直接建表   | 学习紧凑表示     | CNN、ViT、VAE、VQ-VAE                   |
| 当前画面看不到速度和遮挡 | 用历史更新状态   | RNN、GRU、Transformer、RSSM             |
| 动作后果未知             | 学习动作条件转移 | Dynamics Model、RSSM、token Transformer |
| 同一动作可能有多种结果   | 表示不确定性     | 随机 latent、分布预测、Diffusion        |
| 一步预测看得不够远       | 在模型中连续推演 | rollout、imagination                    |
| 多个未来无法比较         | 表示任务目标     | reward、return、value、continue         |
| 候选动作太多             | 更有效地选择动作 | CEM、MCTS、Actor-Critic                 |
| 长时想象会偏离现实       | 反复接受真实检查 | MPC、重规划、闭环评价                   |

这张表不是背诵清单。第 1 章会把这些工具放回数据流中，只认识输入、输出和用途。选定路线以后，我们再详细实现真正需要的部分。

## 小结

- [ ] 一张照片可以看清当前画面，却不一定包含速度和遮挡状态。
- [ ] 记忆保存过去，动作条件模型试演尚未发生的未来，两者职责不同。
- [ ] 视频续写学习常见的后来，动作条件预测研究指定动作的后果。
- [ ] 世界模型负责预测后果，规划器比较后果，策略直接选择动作。
- [ ] 世界模型可以是方程、表格或神经网络；它不是一种固定网络结构。
- [ ] 多步想象会积累误差，因此模型需要不确定性、重规划和现实反馈。

## 练习

### 练习 1：什么时候不需要世界模型

给出一个直接策略已经足够的任务。写清环境、目标、试错代价和为什么没有必要额外学习动态模型。

### 练习 2：相同观察，不同状态

设计一个不是汽车的例子，使两次当前观察完全相同，但正确动作不同。说明哪一段历史能够区分它们。

### 练习 3：续写与干预

找一段只有画面、没有动作标注的视频。分别写出模型可以从中学习的内容，以及它无法据此证明的内容。

### 练习 4：让自己原来的设计失败

在 F0 的九格世界中修改一个格子，使深度为 3 的规划器选择错误，而深度为 6 的规划器成功。再修改一次，使更深的搜索反而利用错误模型。

### 练习 5：三个接口

为扫地机器人分别写出世界模型、规划器和策略的输入与输出。若系统没有显式规划器，说明动作怎样产生。
