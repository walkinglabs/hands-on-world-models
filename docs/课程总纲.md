# 《动手学世界模型》课程总纲

> 版本：v0.1 · 中文课程骨架

## 课程摘要

世界模型研究的是：机器怎样根据过去的观察和候选动作，推测接下来可能发生什么，再利用这种推测选择行动。

本书不先给这个定义。我们先看一辆来到弯道前的小车，再依次尝试 CNN、RNN、Transformer、视觉语言模型和直接策略。每一种方法都能解决一部分问题。可是，只要我们要求机器在行动以前比较“轻踩刹车”和“急刹车”的后果，一个新的缺口就会出现：尚未执行的动作没有真实结果，机器需要在内部先试一次。

沿着这个问题，我们会自己得到世界模型最基本的工作循环：

```text
收集连续经历
→ 根据过去估计当前状态
→ 放入候选动作
→ 推测未来
→ 评价几种未来
→ 选择并执行一个动作
→ 用真实结果修正模型
```

第 0 章带学生重新发明这条循环。第 1–2 章学习共同的表示、记忆、预测、空间、决策和训练工具，并从数据中学出第一台小世界。第 3–7 章不再排成一条越来越长的必修链，而是五条可以单独选择的设计路线。第 8 章让所有路线重新汇合：我们不再只看训练损失，而要证明模型真的帮助了预测、规划或行动，再从失败中设计下一台模型。

课程不要求从零复现工业级大模型。每条路线只设计一台以单张 24GB 显卡为上限的小模型；是否真正满足预算，要等完整运行以后再标记。规模化架构、海量数据和完整论文复现放在“论文拔高”中。

## 这本书想培养什么能力

学完以后，学生不应只会说“Dreamer 使用 RSSM”“V-JEPA 使用 EMA target encoder”。他还应该能够问：

- 当前观察为什么不够？
- 模型究竟要记住什么，哪些东西可以忘掉？
- 未来为什么必须听从动作？
- 我们真的需要重建每个像素吗？
- 单步预测很好，为什么连续推演仍然失败？
- Planner 钻了模型漏洞，应该改数据、状态、损失还是规划器？

课程用六个逐渐升高的目标检查这种能力。

| 层级        | 学生能够做什么                           | 课程怎样检查                   |
| ----------- | ---------------------------------------- | ------------------------------ |
| 1. 说清楚   | 说出模型读入什么、交出什么、解决什么问题 | 不照论文图，用自己的例子画接口 |
| 2. 写出来   | 从零实现一个最小部件                     | 小样本、shape、数值和梯度检查  |
| 3. 接起来   | 把几个部件组成能运行的小系统             | PA0、PA1 的端到端数据流        |
| 4. 找问题   | 找到模型在什么条件下失败                 | 多步、反事实、OOD 和失败图集   |
| 5. 改设计   | 根据失败改变数据、状态、目标或规划方法   | 单变量消融和公平对照           |
| 6. 提新问题 | 把几个方向重新组合，提出可检验的新想法   | PA2“下一台模型”提案            |

前五步做不扎实，第六步就容易变成换名词。我们最终希望培养能设计新模型的人，所以开头的基础必须讲清：学生不仅要会用积木，还要知道每块积木为什么出现、解决了哪种失败、又留下了什么问题。

## 为什么选择这五条路线

世界模型的论文很多。如果按公司、模型名字或应用场景分类，目录会越分越碎。这里先问两个更稳定的问题。

第一，模型把世界记成什么样？

- 像素、视频或视觉 token；
- 较短的 latent 或 feature；
- 3D、物体、BEV 或 Occupancy 等空间结构。

第二，模型的结果交给谁使用？

- 交给人看，让未来变得可见；
- 留在内部，模拟世界怎样变化；
- 交给 Planner、Policy 或机器人，帮助选择动作。

两把尺子放在一起，就得到一张简化坐标表。

| 世界怎样表示／结果怎样使用 | 呈现可见未来           | 在内部模拟变化              | 帮助选择动作                   |
| -------------------------- | ---------------------- | --------------------------- | ------------------------------ |
| 像素、视频、token          | 互动视频、Genie 类系统 | 动作条件视频模拟器          | 视频预测加候选动作比较         |
| latent、feature            | 可选 decoder 呈现      | World Models、Dreamer、JEPA | PlaNet、Dreamer、MuZero 式系统 |
| 3D、物体、BEV、Occupancy   | NeRF、3DGS、4D 场景    | 空间动态与驾驶未来占用      | 碰撞检查、机器人或驾驶规划     |

五条路线覆盖了这张表中最常见、也最适合小模型动手的入口：

1. 决策与规划：重点是模型怎样帮助选动作；
2. 可交互视频：重点是动作怎样改变可见画面；
3. JEPA：重点是哪些未来信息值得保留；
4. VLA 与机器人：重点是理解、动作与后果怎样接在一起；
5. 空间世界：重点是跨视角、三维结构和空间动态。

这些不是互不往来的五个学科。成熟系统经常重新组合它们。VLA 可以请世界模型检查动作，JEPA 可以加入动作后用于规划，互动视频可以加入三维约束，自动驾驶也同时需要空间表示和未来预测。学习时先选一条，是为了把一个问题做深；研究时重新连接，往往正是新方法出现的地方。

## Notebook 和 PA 总量

课程坚持 Notebook-first，但不把每个名词拆成一份文件。

```text
共同基础：F0、F1、F2、F3
→ PA0：第一台可学习的小世界
→ 所选路线的两份 Notebook
→ PA1：路线小整机
→ Z0：统一评价
→ PA2：下一台模型
```

一名学生完整走一条路线，大约完成 10 份 Notebook。其他路线可以阅读，不要求在同一学期全部训练。

每份教学 Notebook 内部都按同一节奏组织：

1. 看一个具体失败；
2. 打开几条真实数据；
3. 试最简单的办法；
4. 改变一个条件，让问题出现；
5. 用自己的话写出缺少的能力；
6. 从零实现最小部件；
7. 用 PyTorch 简洁实现；
8. 在小数据上训练；
9. 加入反例，检查边界；
10. 用一道设计题连接下一步。

# 第一部分　重新发明世界模型

## 第 0 章　为什么机器需要先想一想

### 本章先问什么

一个系统已经能看图、记住历史、续写视频、讲出常识，也能直接输出动作。为什么还要学习世界模型？

### 我们怎样一步步得到答案

| 先用什么    | 它已经会什么           | 改变一个条件后出现什么问题           | 因此还需要什么                 |
| ----------- | ---------------------- | ------------------------------------ | ------------------------------ |
| CNN         | 看见道路、弯道和障碍   | 同一张弯道图可能来自低速车或高速车   | 历史和内部状态                 |
| RNN         | 从过去留下速度线索     | 要比较几个尚未执行的动作             | 动作条件预测                   |
| Transformer | 从历史续写常见未来     | 普通视频没有准确动作，连续生成会漂移 | 干预数据、不确定性和现实修正   |
| LLM / VLM   | 讲出驾驶常识和高层计划 | 不知道眼前车辆、轮胎、延迟和路面参数 | 针对当前系统、能逐步检验的模型 |
| 直接 Policy | 快速给出当前动作       | 目标改变、试错昂贵或环境陌生         | 可复用的变化规律与行动前比较   |

这时才给世界模型一个暂时定义：它根据过去和候选动作，推测可能的未来，并允许新观察不断修正内部认识。

### 从九格世界重新发明基本组件

我们把赛车缩成九格世界，只用整数和字典。

1. 最近终点的动作会走进陷阱，于是需要状态转移；
2. 一步安全可能三步以后失败，于是需要 rollout；
3. 可以生成很多路线却无法比较，于是需要 reward、return 或目标；
4. 动作太多无法全部枚举，于是需要 Planner；
5. 每次搜索太慢，于是可以把好动作学成 Policy；
6. 人写的转移表被拿走，于是需要 trajectory 和 learned dynamics；
7. 同一个动作可能打滑，于是需要概率分布；
8. 长时间相信模型会走进假世界，于是需要短视野、重规划和真实反馈。

### F0：`invent-a-world-model.ipynb`

F0 把上面八步放在同一份 Notebook 中。最终可见产物是：

- 一张九格路线图；
- “规划深度—成功率—搜索开销”曲线；
- 同一起点只替换动作的反事实结果；
- 一张“遇到的问题—缺少的能力—后来常用的组件”表。

最后才阅读 2018 年《World Models》，把自己写出的视觉表示、记忆模型和控制器，与经典论文的 `V–M–C` 对照。重点不是证明我们提前猜中了论文，而是看清经典结构如何回答刚才已经遇到的问题。

### 学完以后

学生应该能用自己的例子说清世界模型、规划器和策略的分工：世界模型猜“做了以后会怎样”，规划器比较“哪种结果更合适”，策略决定“现在就做什么”。简单任务可以只用策略；需要比较未执行动作时，世界模型才显示价值。

# 第二部分　世界模型的常用组件

## 第 1 章　怎样表示、记住和推演世界

### 本章先做什么

这一章不详细复现论文，也不要求学生背缩写。我们先把一段数据从输入到动作完整走一遍，再把常用零件放回它们工作的地方。

```text
图片、声音、点云和机器人状态
→ 看懂画面与空间
→ 压成较短的状态
→ 用历史更新状态
→ 根据动作推演未来
→ 评价未来
→ 选择动作
```

每类组件只先回答四件事：它读入什么、输出什么、为什么需要、在哪条路线会重新深入。

### 1.1 共同语言：Tensor、shape 和时间

- 标量、向量、矩阵、张量；
- batch 是“并排计算很多份”；
- 图片常写成 `[B,C,H,W]`；
- 视频和轨迹常写成 `[B,T,C,H,W]`；
- observation、action、reward、done 的时间下标怎样对齐；
- mask 为什么能让不同长度的 episode 放进同一 batch。

这部分只用可视化和小数组。Python、向量、概率与梯度不再单独占一章，而是放入随用随查的小抄。

### 1.2 视觉感知：先把二维画面看成特征

| 组件     | 先怎样理解                                | 放在系统哪里             | 哪条路线再深入      |
| -------- | ----------------------------------------- | ------------------------ | ------------------- |
| CNN      | 用小窗口寻找局部形状和纹理                | 图片 Encoder             | Dreamer、VLA        |
| ViT      | 把图片切成 patch，再让 patch 互相交换信息 | 图片或视频 token Encoder | JEPA、VLA           |
| 位置编码 | 告诉模型每块内容在什么位置和时刻          | ViT、Transformer         | 互动视频、JEPA、VLA |
| 光流     | 估计像素从上一帧移到了哪里                | 运动观察与视频诊断       | 互动视频、驾驶选修  |

### 1.3 时序记忆：一张图不够时怎么办

| 组件             | 先怎样理解                                         | 放在系统哪里    | 哪条路线再深入 |
| ---------------- | -------------------------------------------------- | --------------- | -------------- |
| RNN / GRU        | 把上一时刻留下的记忆带到下一时刻                   | 轨迹状态更新    | 决策路线       |
| 因果 Transformer | 每一步只能看过去，不能偷看未来                     | token 序列预测  | 互动视频       |
| RSSM             | 用确定记忆保存长期线索，用随机状态表达当前不确定性 | latent dynamics | Dreamer        |
| KV Cache         | 保存已经算过的历史，避免每一步重复计算             | 自回归推理加速  | 互动视频、VLA  |

### 1.4 生成与压缩：世界太大时怎样装进模型

| 组件      | 它解决什么问题                                 | 主要去向               |
| --------- | ---------------------------------------------- | ---------------------- |
| AE / VAE  | 把大图片压成连续 latent，再尝试还原            | Dreamer、生成基础      |
| VQ-VAE    | 用有限码本把图像变成离散 token                 | 互动视频               |
| STE       | 离散选择本来不能直接传梯度，用近似办法继续训练 | VQ-VAE                 |
| Diffusion | 从噪声逐步生成一种可能结果，适合多种未来       | 互动视频、机器人动作头 |
| JEPA 目标 | 不还原所有像素，只预测目标特征                 | JEPA 路线              |

### 1.5 空间几何：二维图片怎样连接三维世界

| 组件        | 先怎样理解                                 | 主要去向       |
| ----------- | ------------------------------------------ | -------------- |
| 相机内外参  | 说明相机怎样成像、放在世界哪里             | 所有空间路线   |
| Point Cloud | 用三维点记录物体表面                       | 3D、驾驶       |
| BEV         | 从上往下看道路和物体                       | 自动驾驶       |
| Occupancy   | 记录空间哪里被占用、哪里可以通过           | 驾驶、机器人   |
| NeRF        | 用神经场表示位置和观看方向对应的颜色与密度 | 3D 重建        |
| 3DGS        | 用许多高斯粒子快速渲染场景                 | 实时 3D        |
| Mesh        | 用三角面片保存可编辑、可碰撞的表面         | 物理与工程应用 |

### 1.6 评价和决策：能预测以后怎样选动作

| 组件            | 先怎样理解                                 | 主要去向           |
| --------------- | ------------------------------------------ | ------------------ |
| reward / return | 说明任务关心什么，以及一条未来总体好不好   | 所有行动路线       |
| value / TD      | 估计从当前状态继续下去还能得到多少         | Dreamer、MuZero    |
| Policy / Actor  | 直接给出动作                               | Dreamer、VLA       |
| Critic          | 评价 Actor 当前选择                        | Dreamer            |
| MPC             | 预测一小段、执行一步、再重新预测           | 决策、机器人、驾驶 |
| CEM             | 从许多动作序列中反复保留较好的部分         | PlaNet             |
| MCTS            | 把候选动作展开成树，集中搜索更有希望的分支 | MuZero             |

### 1.7 训练稳定：代码能跑为什么还会学坏

- Replay Buffer 让历史经历可以反复使用；
- EMA 让目标网络缓慢变化；
- Free Bits 防止随机 latent 被完全忽略；
- Symlog 和 Twohot 处理跨度很大的回报；
- Unimix 防止离散概率过早变成绝对答案；
- Gradient Clipping 防止一次异常梯度破坏训练。

这些技巧不在本章逐项做大实验。它们会在对应路线第一次真正需要时重新出现，并用消融展示“拿掉以后会怎样”。

### F1 与 F2

- `F1-see-remember-compress.ipynb`：从 Tensor 和 shape 开始，用一段 moving-shapes 视频走过 CNN、ViT patch、GRU、AE/VAE 与 VQ 的最小接口。
- `F2-space-plan-train.ipynb`：从一个标定小场景走过相机、点云、BEV 与 Occupancy，再用表格 value、CEM 和一次稳定训练对照认识决策与工程组件。

两份 Notebook 只建立地图，不追求在这一章完成所有模型。

## 第 2 章　从连续经历中学出第一台小世界

### 本章先问什么

零件已经认识了，但世界模型不是拿一堆互不相关的图片训练。它需要知道第几步看到了什么、做了什么，以及下一步发生了什么。

### 2.1 一段经历怎样保存

基本记录是：

```text
观察 o_t
动作 a_t
奖励 r_t
下一观察 o_{t+1}
是否结束 d_t
```

连续的 transition 组成 episode，许多 episode 进入 Replay Buffer。学生会亲手检查：动作应该对应前一帧还是后一帧？终止以后还能不能跨 episode 采样？不同长度怎样 padding？图像、语言、关节和触觉怎样按时间对齐？

### 2.2 数据切分为什么不能随机拆帧

同一 episode 的相邻帧非常相似。若随机拆帧，训练集和测试集会几乎重复，结果看起来很好却没有泛化意义。课程按 episode、scene、seed 或 task template 切分，并明确禁止未来帧泄漏。

### 2.3 从人写转移表到 learned dynamics

1. 先在 LineWorld 保存轨迹；
2. 统计 `(state, action)` 后面出现过什么；
3. 用计数得到一个概率转移模型；
4. 对没见过的状态—动作组合保留不确定性；
5. 用模型 rollout 多步；
6. 执行第一步后重新观察并更新。

这一步会把第 0 章的人写规则，变成第一台从数据学出的世界模型。

### 2.4 世界模型最基本的检查

- 一步预测是否好于复制上一状态；
- 连续 5、10、30 步以后从哪里开始跑偏；
- 同一起点只换动作，未来是否随之改变；
- 没见过的状态—动作组合是否更不确定；
- 使用模型以后，规划成功率是否真的提高。

### F3 与 PA0

- `F3-learn-a-table-world.ipynb`：收集 LineWorld 轨迹，构建 Replay Buffer，学习概率转移表，再用 MPC 完成闭环行动。
- `PA0-reinvent-a-world-model.ipynb`：学生拿到一个新的小世界和不完整代码，自行确定状态、动作、数据、预测目标和评价方法。

PA0 必须提交：接口图、数据卡、简单基线、多步曲线、反事实动作测试、一组失败案例，以及“若观察变成图片，接下来需要增加什么”的设计说明。

# 第三部分　五条设计路线

五条路线都从第 0–2 章出发，并按“最小基线—一个新困难—一个新部件—小整机—失败检查”展开。下面的“已经学过”表示共同基础已经介绍过接口；路线中仍会根据真实任务重新实现，学生不需要自己回忆论文细节。

## 第 3 章　决策与规划：怎样少在现实中试错

### 这条路线解决什么

真实交互贵，但我们有连续的观察、动作、奖励和结束标记。能否把这些经历压进 latent dynamics，再在模型里练习动作？

### 已经学过

CNN、GRU、VAE 的作用；trajectory 与 Replay Buffer；reward、return、value、MPC 和 Actor-Critic 的基本接口。

### 从简单到复杂

1. 只预测下一 latent，观察一步准确不等于多步准确；
2. 用 GRU 保存历史，再加入 stochastic latent 表示不确定性；
3. 得到 RSSM，并同时学习 observation、reward 和 continue heads；
4. 从真实状态出发生成 imagination rollout；
5. 先用 CEM 临时搜索，得到 PlaNet 式控制；
6. 再把想象中的好动作学成 Actor，用 Critic 和 TD-λ 评价；
7. 把收集数据、训练世界模型、想象、训练 Actor-Critic、真实行动接成 Dreamer-lite 闭环；
8. 选修 MuZero：不重建像素，只预测搜索需要的 reward、policy 和 value，再用 MCTS 规划。

### 两份 Notebook

- `A1-learn-a-latent-world.ipynb`：PixelWorld Encoder → GRU → RSSM → 多步 latent rollout。
- `A2-act-in-imagination.ipynb`：CEM 对照 → imagination → Actor-Critic → Dreamer-lite 闭环。

### PA1-A

在 PixelWorld 完成 Dreamer-lite，再迁移到 DMC Cartpole 的小配置。主要检查真实 return、样本效率、多步漂移和模型漏洞。Mini-MuZero 四子棋作为选做，不与 Dreamer 挤在同一次必做训练里。

### 读论文时带着的问题

- World Models 为什么把视觉、记忆和控制分开？
- PlaNet 与 Dreamer 共用什么，又为什么一个搜索、一个学习 Actor？
- DreamerV3 的 Symlog、Twohot、Free Bits 和 Unimix 分别修复了哪种训练失败？
- MuZero 不重建观察，保留的信息为什么仍可能足够规划？

## 第 4 章　可交互视频：怎样让画面真正听从按键

### 这条路线解决什么

普通视频模型可以生成“看起来合理的后来”，但我们要的是：按下向左键，角色真的向左移动；换成向右键，其他条件相同的未来也随之改变。

### 已经学过

VQ-VAE、STE、因果 Transformer、位置编码和 Diffusion 的用途；第 2 章的数据时间对齐与反事实检查。

### 从简单到复杂

1. 先检查帧与按键是否对齐；
2. 用 VQ-VAE 把每帧压成离散 token；
3. 用因果 Transformer 根据历史 token 预测下一组 token；
4. 加入动作条件，让换按键真正改变未来；
5. 连续生成 10、30、100 步，观察模型吃自己的输出后怎样漂移；
6. 用同一数据做 tiny conditional diffusion 对照；
7. 比较动作一致性、清晰度、长时稳定和每帧延迟。

### 两份 Notebook

- `B1-compress-and-predict-video.ipynb`：帧—动作对齐 → VQ tokenizer → 因果 token 预测。
- `B2-make-video-controllable.ipynb`：动作条件 → 多步生成 → 反事实动作网格 → tiny diffusion 选做。

### PA1-B

先在 PixelWorld 做出 IRIS-like 键盘小世界，再尝试 CarRacing 小子集。必须固定初始状态和随机源，只改变按键，证明未来确实听从动作。主要指标是动作一致性、长时漂移和延迟，不用单张漂亮截图代替评价。

### 论文拔高

IRIS、DIAMOND、GameNGen、Oasis 和 Genie 作为不同表示、生成方法、动作来源与实时性的案例。大模型不在课程里复现，学生要学的是为什么会出现“离散 token + 自回归”“连续 latent + diffusion”和“从无动作视频发现 latent action”这些不同选择。

## 第 5 章　JEPA：怎样只预测有用的未来

### 这条路线解决什么

预测未来时，我们真的需要猜对每片树叶的纹理吗？如果任务只关心物体在哪里、怎样运动，能否把算力用在这些较稳定的信息上？

### 已经学过

ViT patch、位置编码、视频序列、EMA 和 stop-gradient 的基本用途。

### 从简单到复杂

1. 把图片 patch 扩成视频 tubelet；
2. 遮住部分时空区域，让 Predictor 猜 target feature；
3. 加入独立 target encoder、stop-gradient 和 EMA；
4. 检查所有输入是否被压成同一个表示，也就是表示坍缩；
5. 用 linear probe 检查位置和速度能否从表示中读出；
6. 加入动作条件，检查同一历史换动作后 feature 未来是否变化；
7. 用一次短期动作选择，检验表示是否真的帮助行动。

### 两份 Notebook

- `C1-learn-video-features.ipynb`：tubelet → masking → target encoder → Tiny Video-JEPA。
- `C2-test-and-control-features.ipynb`：collapse 检查 → linear probe → Action-JEPA → 短期规划。

### PA1-C

PixelWorld 同时提供被动视频和动作轨迹。UCF101-mini 只用于被动表示迁移，不能用来声称模型理解控制。主要指标包括表示方差、feature prediction、linear probe 和动作敏感性；只有动作版才报告规划结果。

### 读论文时带着的问题

- “有用特征”由谁定义？
- EMA target encoder 为什么能减轻坍缩，却不能保证表示适合行动？
- 被动观看与动作条件预测分别能证明什么？
- 如果换任务，原来被丢掉的像素信息会不会重新变得重要？

## 第 6 章　VLA 与机器人：怎样把理解变成动作

### 这条路线解决什么

视觉语言模型会“看和说”，机器人却需要一串能执行的动作。直接动作模型很快，但它不一定在执行以前检查“这个动作会不会撞到盘子”。

### 已经学过

CNN、ViT、Transformer、Policy、Replay 数据和 Diffusion 的基本接口。这里会第一次把图像、文字、机器人自身状态和动作真正对齐。

### 从简单到复杂

1. 只用机器人 state 做行为克隆；
2. 加入图片，让模型从画面判断物体位置；
3. 同一画面给不同语言目标，加入 language conditioning；
4. 一次输出一小段 action chunk，减少逐步动作抖动；
5. 用 diffusion 或 flow action head 表示多种可行做法；
6. 让 VLA 提出几个候选动作；
7. 用一步 world model 预测成功、碰撞或下一状态，再重新排序；
8. 比较直接行动与先检查后果的成功率、碰撞率和延迟。

### 两份 Notebook

- `D1-build-a-tiny-vla.ipynb`：state BC → image BC → language → action chunk。
- `D2-check-actions-before-moving.ipynb`：候选动作 → one-step world model → lookahead reranking。

### PA1-D

先用项目内 Tabletop 和 PushT 小数据训练 Tiny VLA，再选做 world-model checker。直接 VLA 是本路线的基础作品，checker 才把它与世界模型明确接上。主指标是任务成功率、碰撞率、OOD 和延迟；动作 MSE 只作为辅助。

### 需要守住的边界

VLA 的核心输出是动作，世界模型的核心输出是动作后果。它们可以做成两个模块，也可以联合训练。前者容易检查，后者可能更高效，但失败时更难分清是“想错了”还是“做错了”。本章不把二者混成一个名词。

## 第 7 章　空间世界：怎样保持三维结构与运动一致

### 这条路线解决什么

相机移动以后，整张图片都变了，但杯子仍在原来的桌面位置。二维像素连续不等于理解空间、遮挡、物体永久性和碰撞。

### 已经学过

相机内外参、点云、BEV、Occupancy、NeRF、3DGS 和 Mesh 的用途。路线中会从一个可计算的相机小场景重新实现。

### 共同 Notebook：E1

`E1-from-camera-to-space.ipynb` 按下面顺序前进：

1. 用针孔相机看一个立方体；
2. 根据深度把像素反投影成三维点；
3. 改变相机位姿，检查点是否回到同一世界位置；
4. 把点落到 voxel、BEV 和 Occupancy；
5. 用小物体检查遮挡、可通行区域和标定误差。

完成 E1 后二选一。

### 分支 E2a：3D/4D 世界

1. 用 tiny NeRF 或 3DGS 重建静态 Lego 场景；
2. 从新视角渲染，检查跨视角一致性；
3. 比较隐式场、显式高斯和 Mesh 分别适合什么；
4. 在项目内 moving-shapes 多视角数据上加入时间；
5. 再加入最小动作条件，区分“会动的场景”与“动作能控制的世界”。

Notebook：`E2a-build-a-small-4d-world.ipynb`。

### 分支 E2b：自动驾驶世界

1. 把多个标定相机用 LSS 放到同一个 BEV；
2. 预测当前 Occupancy；
3. 根据过去三帧预测未来三帧 Occupancy；
4. 若数据包含 ego plan，再替换计划做反事实预测；
5. 比较 open-loop future prediction 与真正闭环驾驶的差别。

Notebook：`E2b-predict-driving-space.ipynb`。

### PA1-E

学生完成 `E1 + E2a` 或 `E1 + E2b`。静态 Lego 只能证明 3D 表示，不能冒充 4D 动态世界；没有控制动作和模拟器时，驾驶实验只能称为 open-loop predictor，不能报告闭环避碰成功。

### 论文拔高

本章比较三种使用已知物理的方法：在 loss 中加入软约束；把规律写进硬结构；用模拟器处理已知部分，只让网络学习摩擦、延迟等残差。学生在 PA2 中选择一种做最小验证，不额外增加 Notebook。

# 第四部分　设计下一代世界模型

## 第 8 章　证明模型有用，并设计下一台模型

### 本章先问什么

训练 loss 下降、视频看起来清楚、动作 MSE 很小，都不等于模型真正学会了世界。我们需要知道：它在什么条件下可靠？结果是否帮助了行动？它最稳定的失败能否指出下一种设计？

### Z0：`test-a-world-model.ipynb`

Z0 不再训练新模型，而是载入 PA1 的结果，统一完成：

1. 与复制上一帧、线性外推、无模型 Policy 等简单基线比较；
2. 锁定数据 split、随机种子、更新数和算力；
3. 画出不同 horizon 的误差或任务表现；
4. 固定同一初始世界，只替换动作，做真正的反事实；
5. 检查模型保留了哪些信息、丢掉了哪些信息；
6. 改变颜色、速度、视角、摩擦或指令，做 OOD 测试；
7. 检查模型不确定性与错误是否匹配；
8. 让 Planner 主动寻找模型漏洞；
9. 报告下游 return、成功率、碰撞、IoU 或动作一致性；
10. 记录推理延迟、峰值显存、时间、曲线和 checkpoint 哈希。

不同路线不用同一个总分。决策路线主要看 return 和样本效率；视频路线看动作一致性、长时漂移与延迟；JEPA 看表示、动作敏感性和下游效用；机器人看任务成功和碰撞；空间路线看几何、占用和时间一致性。所有动作条件模型都必须做反事实和 OOD。

### PA2：下一台模型

PA2 是一次小型研究循环：

```text
找到一个稳定失败
→ 判断它来自数据、状态、动态、目标、规划还是系统接口
→ 提出至少两种解释
→ 选择一种最小改动
→ 设计能够推翻自己的实验
→ 运行公平对照
→ 写清结果支持什么，也写清没有支持什么
```

最终报告必须回答六个问题：

1. 现有模型在什么条件下失败？
2. 为什么这不是一次偶然坏样例？
3. 模型缺少的是哪种信息或能力？
4. 新设计的输入、输出和训练信号是什么？
5. 更简单的替代方案是什么？
6. 哪个结果会证明新设计其实没有用？

### 三个研究入口

结合《A Definition and Roadmap for World Models》，课程把宏大的未来路线缩成三种学生可以验证的改动。

#### 入口一：补证据

视频不能判断接触，就增加触觉；单视角容易误判遮挡，就增加多视角；动作时间不准，就补控制频率和延迟。实验要回答：新证据是否修复了原来稳定出现的失败，而不是“模态越多是否越好”。

#### 入口二：改状态

比较像素重建状态、任务状态和共享状态。实验要回答：每一种状态保留了什么、丢掉了什么，换任务以后谁先失败。世界模型的根问题不是“生成器用哪种网络”，而是在有限计算下，世界应该被压成什么样。

#### 入口三：接现实

模型发现自己没有把握时，不应继续编一个确定答案。它可以选择一次安全、又能区分几种解释的动作，再从真实结果更新自己。实验要回答：机器能否发现“下一件最值得弄明白的事”。

这三个入口分别对应：给模型更多可靠证据，改变内部世界的表示，让想象接受现实检验。它们不保证产生新论文，却能把“未来展望”变成可反驳的小实验。

# 数据、算力与交付标准

## 数据台阶

每条路线都按同一顺序增加难度。

| 层级    | 数据                                                                 | 用途                            |
| ------- | -------------------------------------------------------------------- | ------------------------------- |
| T0      | 手写数组、规则小世界                                                 | 检查接口、shape、公式和明显 bug |
| T1 组件 | 项目内可生成的 LineWorld、PixelWorld、Tabletop、moving-shapes        | 实现一个零件                    |
| T1 整机 | 同一生成数据上的连续 episode                                         | 把零件接成小模型                |
| T2      | DMC、CarRacing、UCF101-mini、PushT、Lego、nuScenes-mini 等真实小数据 | 检查能否迁移到更复杂分布        |
| T3      | 环境 return、任务成功、可玩控制、闭环或高可信下游                    | 证明模型是否有用                |

数据可用状态必须分开写：只有 schema、已经确定来源、loader 可用、artifact 可用，不能都叫“数据已准备”。项目内生成数据也要记录生成器版本、seed 和校验和。

## 24GB 验收

每个实验计划提供 smoke、24GB 和 research 三档配置。必做实验的目标是单张 24GB 显卡、峰值 reserved 显存不超过 22GB，并尽量在 24 小时内完成。

但“配方写成 21GB”不等于已经验证。只有提交以下证据，才能标记为“24GB 已实测”：

- 完整运行清单；
- GPU、CUDA 和依赖版本；
- peak allocated 与 peak reserved；
- 总运行时间；
- seed、数据版本和配置；
- 训练曲线、主要指标和失败案例；
- checkpoint 哈希。

本总纲发布时，神经网络实验的 24GB 真机完整记录仍为 0 个。后续每验证一个，就在仓库的运行证据中单独登记。

## 每次作业必须交什么

1. 可以重新运行的 Notebook；
2. 数据卡和切分方法；
3. 模型输入输出接口图；
4. 一个简单基线；
5. 多步或下游主指标；
6. 反事实或控制变量实验；
7. 失败图集；
8. 资源记录；
9. “结果没有证明什么”；
10. 下一步最小改动。

# 论文怎样进入课程

论文不会按年代排成九十分钟的模型名单。每条路线只保留：

- 一页问题地图；
- 一个 24GB 内的小模型；
- 一个公平对照；
- 三到五篇拔高论文。

阅读论文时，学生始终先写四个答案：论文改变了哪一段接口？保留了什么信息？丢掉了什么信息？作者用什么证据证明这种取舍值得？

经典路线包括 World Models、PlaNet、Dreamer、MuZero、IRIS、DIAMOND、GameNGen、Oasis、Genie、V-JEPA、V-JEPA 2、RT-2，以及 3D/4D 和驾驶世界模型的代表工作。课程会核对官方论文与实现，但不会把“融资公司的路线”直接当成技术证据。公司的公开方向用于观察真实需求，模型结论仍以论文、代码和可重复实验为准。

# 学完这门课以后

学生最终带走的，不应只是五个方向的地图。更重要的是一套可以迁移到新问题的方法：

```text
先看系统在哪个具体条件下失败
→ 判断它缺少信息、状态、预测、评价还是行动接口
→ 选择最小组件补上缺口
→ 让新设计接受反例和现实结果
→ 从下一次失败继续往前走
```

今天我们把这套系统叫作世界模型。将来的好问题，也许还没有名字。课程真正想做的，是让读者有能力在那个名字出现以前，先看见它为什么非出现不可。
