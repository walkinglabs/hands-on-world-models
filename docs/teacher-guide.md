# 教师指南

这门课的目标不是让学生记住世界模型论文列表，而是让他从一次失败中判断系统缺少什么，再用最小实验验证自己的判断。

## 建议学期安排

| 周    | 内容                | 课堂结果                                     |
| ----- | ------------------- | -------------------------------------------- |
| 1–2   | 第 0 章与 F0        | 亲手得到状态、动作、转移、rollout 与 planner |
| 3–5   | 第 1 章、F1–F3      | 读懂组件接口，完成数据与表格动态             |
| 6     | PA0                 | 独立重新发明一台小世界模型                   |
| 7–10  | 第 2–6 章中选择一条 | 完成两份路线 Notebook                        |
| 11–13 | PA1                 | 训练路线小整机并接受真实评价                 |
| 14    | Z0                  | 多步、反事实、OOD、不确定性与漏洞            |
| 15–16 | PA2                 | 从稳定失败完成一次小研究循环                 |

五条路线不在同一个学生身上全部必做。教师可让不同小组选择不同路线，最后用第 7 章的共同证据标准互相答辩。

教材中的 38 篇小章是阅读与课堂讨论单元，不是 38 份实验。通常用 2–4 篇小章回答一组连续问题，再用一份 Notebook 把这些内容接起来。这样既能把概念讲细，又不会让学生整学期都在赶文件数量。

## 一节课怎样展开

先让学生写下预测，再运行最小例子。只有原办法出现具体失败以后，才给新组件名称。

```text
具体情境 → 学生预测 → 最小基线 → 改一个条件
→ 观察失败 → 说清缺口 → 实现组件 → 再次检查
```

若学生直接说“这里应该用 Transformer”，继续追问：输入输出是什么？RNN 或表格为什么不够？哪个结果会证明 Transformer 没有帮助？

## Notebook 怎样批改

不要只检查最终数值。每份实验至少看：

1. 时间与 shape 是否正确；
2. 是否有简单基线；
3. 是否固定变量做反事实；
4. 是否报告多步或真实下游结果；
5. 是否保存失败样例；
6. 是否写明结果没有证明什么。

代码完整但结论越界，不应获得高分。负结果若问题明确、对照公平、证据完整，可以获得完整实验分。

## PA 建议评分

| 项目                    | 比例 |
| ----------------------- | ---: |
| 问题与接口说清楚        |  15% |
| 数据、切分与可复现性    |  15% |
| 最小实现与测试          |  20% |
| 基线、多步、反事实、OOD |  25% |
| 失败诊断与结论边界      |  15% |
| 表达、图表与运行证据    |  10% |

PA2 不以“是否超过基线”决定全部成绩。它更看重竞争解释、可证伪实验和诚实边界。

## 资源不足时怎样缩小

按下面顺序缩小，而不是删除评价：

```text
先减少数据量与 updates
→ 再降低分辨率、sequence length 与 hidden size
→ 保留 train/val/test、基线、反事实和 horizon 曲线
```

Smoke 可以在 CPU 检查接口。任何截断运行都不能改写成 24GB 完整证据。
