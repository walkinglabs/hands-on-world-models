# PA0 · 动手：重新发明一台可学习世界模型

F0 使用了人写的九格规则，F3 又用 LineWorld 演示了计数动态。PA0 不要求照抄其中任何一张结构图。

我们提供一个新的小世界接口和一批连续经历。需要自行决定什么状态值得保存、模型输出一个结果还是分布，以及 Planner 怎样使用它。

## 任务

选择下面一种变化，修改 F3 或自己构造环境：

1. 当前观察看不到完整位置，需要最近两步历史；
2. 同一个动作在两种地面上结果不同，但地面类型暂时不可见；
3. 目标会在 episode 开始时改变；
4. 地图中有一个训练数据未覆盖的区域。

一次只选择一种变化。PA0 的目的不是制造最复杂环境，而是让一种失败稳定出现。

## 必交 Notebook

文件名：

```text
PA0-reinvent-a-learned-world.ipynb
```

Notebook 必须包含以下七项证据。

### 1. 接口图

不用论文架构图。用自己的变量写清：

```text
模型输入 → 内部状态或预测 → 模型输出
Planner 怎样调用 → 环境怎样返回真实结果
```

### 2. 数据卡

至少写明：

- 数据怎样生成；
- transition 字段和 shape；
- action 对应哪两次观察；
- episode 在哪里结束；
- train、val、test 按什么边界切分；
- seed 与数据量。

### 3. 简单基线

先实现一种不学习或很少学习的办法，例如复制上一状态、永远向目标移动、只使用当前观察。

基线在简单情况中应该能够成功。不要把它故意写坏。

### 4. Learned dynamics

实现至少一种从数据学习的转移模型。表格、线性模型或小神经网络都可以，但需要说明为什么当前数据需要它。

模型必须把动作作为输入或明确的条件。

### 5. 四类评价

同时报告：

- one-step 指标；
- 5、10、20 步 rollout；
- 同一起点只替换动作的反事实；
- 使用模型前后的任务成功率或 return。

### 6. 稳定失败

提交至少一组在固定 seed 下可重复的失败。说明失败更可能来自：数据、观察不足、模型能力，还是规划使用不当。

### 7. 下一步需求

最后只写一项最小改动。不要直接画出“CNN + Transformer + Diffusion + MCTS”的组合图。

## 评分

| 项目       | 分数 | 检查重点                         |
| ---------- | ---: | -------------------------------- |
| 问题与接口 |   15 | 不靠模型名也能说清缺口           |
| 数据与切分 |   20 | 时间对齐、episode 边界、无泄漏   |
| 基线与模型 |   20 | 基线合理，模型确实读取动作       |
| 评价证据   |   20 | 一步、多步、反事实、下游齐全     |
| 失败诊断   |   15 | 失败稳定，解释至少有两种可能     |
| 表达与复现 |   10 | Notebook 可运行，seed 与输出完整 |

## 资源边界

PA0 必须可以在 CPU 上完成，运行时间目标不超过 5 分钟。若选择小神经网络，也不能把 GPU 当作完成作业的必要条件。

PA0 不比较排行榜。它检查我们是否已经能把一个现实缺口变成数据、接口、模型、反例和下一步设计。

## 选路线

完成以后，回答四个问题：

```text
我最希望模型交出什么？
谁会使用这个结果？
哪些信息必须保留？
哪些信息可以暂时不预测？
```

根据答案进入第 3–7 章中的一条路线，而不是默认所有人继续学习 Dreamer。
